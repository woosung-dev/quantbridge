# harness — 순차 무인 step 실행기 (도입 시험 중)

> 출처: <https://github.com/jha0313/harness_framework> (강의 자료).
> **원본 as-is 채택이 원칙이다.** 우리 방식으로 고쳐 쓰지 않는다 — 2회 돌려보고 판정한다.
> 아직 `docs/reference/` 승격 대상이 **아니다**. 파일럿 결과에 따라 승격 또는 삭제(+tombstone).

## 1. 이게 무엇인가 — 우리 함대와 어떻게 다른가

`scripts/execute.py` 는 **오케스트레이터를 LLM 에서 스크립트로 내린다.** `claude -p` 를 step 마다
새 프로세스로 띄우고, 부모 컨텍스트가 아예 없으며, 유일한 보고 채널이 파일(`phases/*/index.json`)이다.

|                | herdr 함대                        | claude 서브에이전트    | harness `claude -p`      |
| -------------- | --------------------------------- | ---------------------- | ------------------------ |
| 컨텍스트 격리  | 강 (보고가 파일)                  | **약** (리턴이 부모로) | **강** (부모가 없다)     |
| 파일시스템     | **강** (워크트리 + 샌드박스)      | 약                     | 없음 (§3 으로 보완)      |
| 상태 영속·재개 | 파일은 있으나 **재개 로직 없음**  | 세션과 함께 소멸       | **`index.json` 이 재개** |
| 독립 검증      | CONTROL 이 통합 브랜치에서 재측정 | 없음                   | ★**없다** (§4)           |
| 병렬           | **4레인**                         | 다중                   | 순차 1                   |

★ **셋은 대체재가 아니라 계층이다.** CONTROL(판정) → 워크트리(격리·병렬) → harness(실행·상태·무인).

## 2. 원본과의 차이 — **1줄뿐이다**

```python
# scripts/execute.py:182
docs_dir = ROOT / "harness" / "docs"   # 원본: ROOT / "docs"
```

**왜 고쳤나.** 원본 `_load_guardrails()` 는 `docs/*.md` 를 필터 없이 통째로 프롬프트에 넣는다.
그건 게으름이 아니라 계약이다 — 원본 `docs/`(PRD·ARCHITECTURE·ADR·UI_GUIDE)에는
**정적 설계 제약만** 있고 진행 상태·백로그가 없기 때문이다.

우리 `docs/` 최상위는 그 계약과 **정확히 반대**다. glob 이 잡는 것은
`status.md`·`backlog.md`·`roadmap.md`·`lessons.md`(**814,211자**)뿐이고, 정본인
`docs/reference/`·`docs/decisions/` 는 하위 디렉터리라 하나도 안 잡힌다.
크기 문제가 아니라 **주입하면 안 되는 것만 골라 잡는** 문제다 —
step 세션이 「다음 행동 = …」과 미해결 BL 수백 건을 손에 쥔다.

그래서 우리 `docs/` 를 바꾸지 않고(참조 163회 + 상대경로 32회가 달려 있다), **원본 계약을 지키는
슬롯을 새로 만들었다.** 경로만 다르고 계약은 동일하다.

### `harness/docs/` — 원본 4축과 1:1

| 원본              | 우리 (심링크)                           | 묻는 것         |
| ----------------- | --------------------------------------- | --------------- |
| `PRD.md`          | `01-domain.md` → `CONTEXT.md`           | 무엇을 만드나   |
| `ARCHITECTURE.md` | `02-structure.md` → `AGENTS.md`         | 어디에 두나     |
| `ADR.md`          | `03-backend.md` → `backend/AGENTS.md`   | 무엇으로 만드나 |
| `UI_GUIDE.md`     | `04-frontend.md` → `frontend/AGENTS.md` | 어떻게 보이나   |

심링크라 **사본이 생기지 않는다**(ADR-026 SSOT). 파일명이 곧 주입 순서이자 섹션 헤더다.

**실측 (2026-08-12):** 814,211자 → **45,367자 (−94.4%)**.
양성 대조 4축 전건 주입 확인 · 음성 대조 제외 5파일 전건 미주입 + 그 검사가 수정 전 주입물에서
**5/5** 를 잡는 것까지 확인했다.

★**슬롯에 들어갈 수 있는 것은 「거의 변하지 않는 설계 제약」뿐이다.** 진행 상태·할 일·회고를
여기 넣으면 원본 계약이 깨진다. step 마다 다른 문서가 필요하면 `step{N}.md` 의
**「읽어야 할 파일」에 경로로** 적어라 — 원본이 그 섹션을 만든 이유가 그것이다.

**안 고친 것:** `:179` 의 `CLAUDE.md` 주입은 그대로 뒀다. 우리 `CLAUDE.md` 는 11바이트
(`@AGENTS.md` 한 줄)이고 `read_text()` 는 import 를 안 따라가므로 문자열 `@AGENTS.md` 가 그대로
들어간다 — 무해한 잡음이다. 규칙 본문은 Claude Code 가 자체로 로드하고, 슬롯에도 이미 있다.
`:12` 의 미사용 `import os` 도 원본 그대로 뒀다(상류 추적).

## 3. 실행

★**러너(원본 §E)만으로는 못 돈다.** 그 앞의 **C(step 설계) · D(파일 생성)** 이 있어야
`phases/<task>/` 가 생긴다. 그 절차와 **step 파일 템플릿·설계 원칙 7개**는
[`workflow.md`](workflow.md) 에 **원문 그대로** 있다 — step 파일을 쓰기 전에 그걸 먼저 읽어라.

```bash
python3 scripts/execute.py <phase-dir>          # 순차 실행 (원본 §E)
```

- **`--push` 는 쓰지 마라.** 승인 없는 push 는 Golden Rule 위반이다.
- **실행 위치는 호출자가 정한다.** `ROOT = Path(__file__).parent.parent`(`:22`)라서
  워크트리 안의 `scripts/execute.py` 를 부르면 ROOT 가 그 워크트리가 된다 — **코드 수정 0**.
  워크트리에서 돌리면 파일시스템 격리가 붙고 `--dangerously-skip-permissions`(`:239`)의
  블라스트 반경이 브랜치 하나로 묶인다.
- ★**celery 를 타는 step(백테스트·라이브신호·옵티마이저)은 워크트리에서 못 돈다** —
  worker 가 메인의 `src` 를 mount 한다. 그 step 은 메인 체크아웃에서 돌려라
  ([`worktree-parallel.md`](../docs/reference/operations/worktree-parallel.md)).

테스트: `python3 -m pytest scripts/test_execute.py` (원본 51건. 픽스처 2곳만 슬롯 경로로 맞췄다.)

★**「51 passed」를 실행기가 검증됐다는 뜻으로 읽지 마라.** 실측 — 테스트 12개 클래스는 전부
헬퍼 단위이고, **순차 실행 루프는 한 줄도 안 탄다**: `run()` · `_execute_single_step` ·
`_execute_all_steps` · `_finalize` · `_ensure_created_at` 이 테스트 파일에 **각 0회** 등장한다.
`run()` 을 no-op 으로 바꿔도 51건은 대부분 그대로 초록이다. 즉 이 초록이 말하는 것은
「내 1줄 수정이 헬퍼를 안 깼다」까지이고, 그 이상이 아니다.

## 3.1 ★as-is 로 안고 가는 위험 — 첫 run 전에 읽어라

2026-08-12 codex 적대 리뷰 8건을 **전건 코드 대조**했다. 아래는 전부 **원본 그대로의 성질**이지
이번 수정이 만든 결함이 아니다. 고치지 않는 이유 = as-is 채택이 이 회차의 실험 조건이기 때문이다.
파일럿에서 실제로 무는지 보고 판정한다.

| #   | 위험                                                                                                                                         | 대조 결과                                          | 등급   |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | ------ |
| 1   | `_checkout_branch`(`:113-134`)에 **clean-tree 검사가 0건**. dirty tree 를 그대로 새 브랜치로 데려가고 이후 `git add -A` 가 그것까지 커밋한다 | ✅ 참 — 검사 0건 확인                              | **P1** |
| 2   | 실패 경로(`:356`)에서도 `_commit_step()` 을 부른다. 3회 실패한 step 의 부산물이 커밋된다                                                     | ✅ 참                                              | **P1** |
| 3   | `_finalize`(`:387-393`) 가 **커밋 실패를 무시**하고 "Phase completed!" 를 찍는다. `--push` 면 그 상태로 push 까지 간다                       | ✅ 참 — returncode 미검사 확인                     | **P1** |
| 4   | `--dangerously-skip-permissions`(`:239`)를 쓰면서 **워크트리를 강제하지 않는다**. §3 은 권고일 뿐 코드가 메인 실행을 막지 않는다             | ✅ 참                                              | **P1** |
| 5   | `_check_blockers`(`:84-90`)가 **checkout 보다 먼저** 돈다. 현재 브랜치 기준으로 판정한 뒤 브랜치를 바꾼다                                    | ✅ 참 — `run()` 호출 순서 확인                     | P2     |
| 6   | `core.symlinks=false` / dangling 심링크면 슬롯이 **조용히 링크 문자열**이 되거나 `FileNotFoundError`                                         | △ 조건부 — 이 레포는 macOS·ubuntu CI 라 도래 안 함 | P2     |

★**그래서 첫 run 전 preflight 2개는 건너뛰지 마라.**

```bash
git status --porcelain          # 반드시 빈 출력. 1·2번 위험이 여기서 막힌다
git rev-parse --abbrev-ref HEAD # 지금 어느 브랜치인지 눈으로 확인 (5번)
```

`--push` 는 어차피 안 쓴다(§3) — 3번의 최악 갈래가 그걸로 닫힌다.

## 4. ★파일럿 설계 — 무엇을 재는가

**재는 것은 「자기채점이 뚫리는가」 하나다.**

원본은 AC 커맨드를 **러너가 실행하지 않는다**(`:312-313`). step 세션이 `index.json` 에 써넣은
`"completed"` 를 그대로 믿는다. 즉 **코드를 쓴 쪽이 자기 채점을 한다.** 이 레포는 그 실패를
4회 기록했다(`docs/lessons.md` · 메모리). 원본이 그 자리를 비워둔 것은 실수가 아니라
**완전 격리의 대가**다 — 판단 주체를 없애면 판사도 없어진다.

| 회차  | BL                          | 판본                                                                                     |
| ----- | --------------------------- | ---------------------------------------------------------------------------------------- |
| **A** | [BL-708] 캐논 대비 비결정성 | **순수 as-is.** 세션 자기신고. CONTROL 이 **사후에 각 step 의 AC 를 재실행**해 대조      |
| **B** | [BL-709] RSC prefetch 정렬  | **러너 AC 판정.** `index.json` step 에 `ac` 필드 추가, `execute.py` 가 exit code 로 판정 |

- 둘 다 `Est: S`, 둘 다 2026-08-12 같은 회차 출신, 둘 다 celery·`make seed` 무관 → **같은 조건**.
- ★**가드레일은 두 회차 공통으로 고정한다**(§2 슬롯). 회차마다 다르면 실패 원인이
  「자기채점」인지 「컨텍스트 폭발」인지 구분되지 않는다.
- 표본은 BL 2건이 아니라 **step 6~8개**다. 「자기신고 completed vs 사후 실측」 불일치 건수를 센다.
- step 파일은 **CONTROL 이 쓰고 사용자가 승인**한다(함대 §1 「수용 기준은 착수 전 동결」과 같은 계약).

### A회차 실측 (2026-08-12, `feat-bl708` · 미푸시)

| 항목             | 값                                                                         |
| ---------------- | -------------------------------------------------------------------------- |
| **불일치**       | **0 / AC 16건** (자기신고 4/4 `completed`, CONTROL 전건 재실행)            |
| 러너 재시도      | **0회** (`MAX_RETRIES` 미도달, `blocked` 0)                                |
| **저작 비용**    | **3분 3초** — `index.json` 2 + `step1~4.md`, 12,059자                      |
| 벽시계           | 46분 3초 (step1 11:56 · step2 13:51 · step3 13:00 · step4 7:12)            |
| `claude -p` 비용 | **$17.83** (step당 $4.18~4.85 · turns 35~53)                               |
| 커밋             | **9** = step당 2(feat+chore) × 4 + finalize 1. 우리 PR 중앙값 2 대비 4.5배 |

★**불일치 0 을 「자기채점은 안 뚫린다」로 읽지 마라.** AC 16건 중 **12건이
typecheck·lint·`git diff`·`bl-audit`·`docs-audit`** 이다 — CONTROL 이 재실행해도 같은 답이 나오도록
**일부러 결정적인 것만 골랐다**(안 그러면 불일치가 부정직인지 측정 잡음인지 안 갈린다). 즉 이 0 이
말하는 것은 「**결정적 AC 를 주면 자기신고가 그 AC 와 어긋나지 않았다**」까지이고, 그 이상이 아니다.
확률적 AC(캘리브레이션 3회)는 1건뿐이었고 CONTROL 이 2배수(6회)로 재실측해 6/6 초록을 얻었다.

★**대신 값이 나온 곳은 AC 설계 비용이었다.** 착수 전 스모크에서 **내가 쓴 AC 2건이 헛초록**이었다 —
하나는 숫자를 `wc -l` 로 찍기만 하고 판정을 안 했고(자기채점 프리패스), 하나는 기준을 `main` 으로 잡아
후속 step 의 정당한 변경까지 위반으로 셌다. 그리고 「단독 파일 3회 반복」을 AC 로 쓸 뻔했는데 실측이
**3/3 초록**(전량 병렬에서만 재현)이라 판별력 0 이었다. **B회차가 재야 할 것은 이 설계 비용이
러너로 옮겨가는가다** — `ac` 필드를 러너가 실행하면 AC 를 쓰는 쪽의 부담은 그대로다.

★**부수 발견 2건.** ⑴ 러너 브랜치는 `feat-{phase}`(하이픈)인데 이 레포 pre-push 화이트리스트는
`feat/*`(슬래시)다 — push 전 `git branch -m` 이 필요하다. ⑵ preflight 를 **세션 시작에 한 번만** 재고
20분 뒤 브랜치를 만들었더니 그 사이 HEAD 가 `main`→`feat/harness-workflow` 로 옮겨 가 있었다
(AGENTS.md 「baseline 재측정 preflight」가 정확히 이것을 막으려는 규칙이다). 브랜치를 딸 때 다시 재라.

### 같이 재는 것

| 항목                 | 왜                                                           |
| -------------------- | ------------------------------------------------------------ |
| **회차당 저작 비용** | step 파일 N개 작성 시간. 도입 판단의 유일한 미측정 변수      |
| 커밋 노이즈          | step 당 2커밋(feat+chore). 우리 PR 중앙값이 2커밋 → 6커밋 됨 |
| 실제 토큰·비용       | 45,367자 × step × 재시도. 캐시가 붙는지 포함                 |
