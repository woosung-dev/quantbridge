## ⓶ 반증 3건 — 이 회차의 최대 산출

### 반증 ⑴ — [BL-646] 의 전제가 틀렸다: 그리드가 받는 폭은 **뷰포트가 아니다**

착수 시점의 처방 후보는 「미등재 900px 경계를 1024 나 768 로 **흡수**한다」였다. 그 후보는
「뷰포트가 넓어지면 그리드가 받는 폭도 넓어진다」를 암묵 전제로 깔고 있었다. 실측이 그것을
깼다 — 그리드가 실제로 받는 것은 **`.page` 콘텐츠 박스**이고, 그 폭은 뷰포트에 **단조가
아니다.** `--sidebar-w` 가 1024 에서 **232 → 64 로 계단**을 밟기 때문이다.

| 뷰포트 | `--sidebar-w` | `.page` 콘텐츠 폭 |
| ------ | ------------- | ----------------- |
| 1023px | 232px         | **911px**         |
| 1025px | 64px          | **745px**         |

뷰포트를 **2px 넓혔는데 콘텐츠는 166px 줄어든다.** ⇒ 900 을 1024 로 흡수하면 「**가장 넓을 때
접는다**」는 모순이 되고, 768 로 흡수하면 뷰포트 769(콘텐츠 657)에서 `.trade-detail-metrics`
3열이 219px 씩이 되어 `.metric` 이 +6px 넘쳐 **라벨이 실제로 꺾인다**(「시각」 → 「시/각」).
900 유지가 모순 구간 42px 로 최소다. ⇒ **흡수 2안을 실측으로 기각하고 ①등재**(`DESIGN.md`
§4.3.1 신설, 콘텐츠 그리드 전용 6번째 경계)로 닫았다. 근본 해는 컨테이너 쿼리이고 [BL-647] 이다.

> **일반화:** 「경계를 통합하자」는 제안은 **그 경계가 무엇을 재는지**를 먼저 물어야 한다.
> 셸 경계(1024/768)와 콘텐츠 그리드 경계(900)는 **다른 양을 재는 서로 다른 축**이었다.

### 반증 ⑵ — [BL-598] 의 답이 (a)도 (b)도 아니었다, 그리고 codex 가 사거리를 **두 번** 좁혔다

백로그가 올려 둔 후보는 둘이었다 — (a) import 워밍업 · (b) 입력 크기 비선형. **둘 다 기각**됐다.

| 축                    | 실측                                                             | 판정                                   |
| --------------------- | ---------------------------------------------------------------- | -------------------------------------- |
| import 비용           | warm 0.26s = cold 합계의 **0.4%**, import 직후 DFA 상태 0        | **(a) 기각**                           |
| 크기 법칙 (cold 램프) | 크기 8.6배 → 8.39s→50.80s, log-log 기울기 **0.78**               | **(b) 기각**(sublinear)                |
| **인과 대조**         | 같은 프로세스·같은 입력에서 캐시**만** 비우니 3.68s → **51.37s** | 원인 = **ANTLR 파서 DFA 워밍업**(14배) |

진짜 답은 **`pynescript` 가 쓰는 ANTLR ALL(\*) 예측의 DFA 캐시가 「파싱에 의해」 지연
구축되는 것**이다. `PinescriptParser.decisionsToDFA` 가 generated 파서의 **클래스 속성**이라
프로세스 전역이고, 그래서 샤딩하면 샤드마다 중복된다.

**★그런데 codex 가 이 결론의 사거리를 두 번 좁혔다.**

1. **초판 cold 램프의 「평평하다」는 허상이었다.** 처음엔 같은 프로세스 안에서 조각을 키워
   가며 쟀는데, 앞 조각이 이미 DFA 를 데워 놔서 **공유 DFA 가 만든 평탄면**을 보고 있었다.
   조각마다 **새 프로세스**로 격리하자 8.39s → 50.80s 로 **단조 증가**했다. 램프의 결론
   자체는 살았지만(초선형이 아니다) 그 전의 그래프는 **아무것도 재고 있지 않았다.**
2. **성분 통제가 매 회차 뒤 되데우고 있었다.** [8] 의 성분 루프는 한 프로세스 안에서
   `비운다 → 잰다 → 다시 데운다` 를 돌린다. 그래서 `shared_ctx` 를 비울 차례가 왔을 때
   parser DFA 는 **이미 워밍돼 있었다.** 그 배치에서 나온 1.0배가 지지하는 문장은
   「shared_ctx 는 무관하다」가 아니라

   > **parser DFA 가 워밍된 상태에서는 나머지 둘이 추가 비용을 지지 않는다**

   까지다. ⇒ **결론 문구를 정정**하고, 성분마다 **새 프로세스**를 띄워 배경을 셋 다
   「cold 1회 + warm 1회」로 맞춘 independent control(`--components`)을 신설했다:
   `parser_dfa` **13.9배** · `shared_ctx` 1.0배 · `lexer_dfa` 1.0배(cold/warm 은 셋 다
   51.2s/3.8s 로 일치). **순서의 산물이 아니었다** — 그러나 이것도 조건부 문장을 확증할 뿐
   단독 기여를 재지 않는다. 완전 cold 성분 분해는 **캐시를 끈 채 파싱할 수단이 없어**
   실험 설계 자체가 없고, **미측정으로 적었다**.

★같은 정정에서 신규 **[BL-652]** 가 나왔다 — 프로파일러 `section_import` 이 **첫 서브프로세스
(17초, bytecode 컴파일 + OS 파일 캐시 워밍)를 버리고** 이후 0.26s 를 보고한다. **CI 러너는
매 잡이 cold** 이고 샤드를 나누면 샤드마다 cold 다. 버린 17초가 샤드 수만큼 반복되는지는
아무도 안 쟀다. ②의 파싱 디스크 캐시는 **파싱 비용만** 지우므로 이 축은 남는다.

### 반증 ⑶ — 라이트 캐논 spec 이 **fail-open** 이었다

「라이트를 감사한다」고 선언한 새 spec 이, 실은 **감사할 것이 있는지를 한 번도 확인하지
않았다.** `auditUrl` 이 `page.goto()` 의 **반환값을 버렸기 때문**이다. 그래서:

| 주입                      | 수리 전                              | 수리 후                                           |
| ------------------------- | ------------------------------------ | ------------------------------------------------- |
| 5라우트를 **없는 경로**로 | **5/5 초록**(404 를 감사하고 있었다) | **4 red**(404 프로브는 404 가 정답이라 초록 유지) |
| 감사 직전 **body 비움**   | **5/5 초록**(빈 DOM)                 | **5/5 red**(`minExamined` 가 0 을 받았다)         |

수리 = 결과 객체에 **도달 증거 두 축**을 싣는다 — `NavProbe.status`(그 URL 이 정말 그 응답을
냈는가) · `NavProbe.examined`(감사가 **몇 개**를 실제로 봤는가). 판정은 코어가 아니라 **spec**
이 한다. 정상 대상 중에 2xx 가 **아닌** 것이 이미 있기 때문이다 — `/qb-canon-404-probe`(404 가
정상) · `/maintenance`. 「2xx 여야 한다」를 코어에 박으면 그 둘이 **거짓 red** 가 된다.

★같은 리뷰가 **두 번째 구멍**도 잡았다 — canon 래칫이 **개수만** 셌다. dedupe 키가
`color|round(size)|txt[0:20]` 이라 하나가 사라지고 다른 하나가 생기면 **개수는 그대로인데
최악값만 나빠진다.** 음성 대조: `--text-muted` `#585f68`→`#585f6c` 는 개수(2/6/14/4/2)도
hardFail(0)도 **완전히 동일**한데 최악 대비가 5.60 → 5.57 로 내려가고 **새 단언만으로 5/5 red**
가 된다. 개수 래칫이면 전부 통과했을 회귀다. ⇒ `worstCanonRatio` 를 여유 **0** 으로 래칫했다.

> **일반화(→ lessons 승격):** **음성 대조가 「페이지가 제대로 온 경우」만 다루면 「안 온 경우」를
> 못 본다.** 이 회차의 라이트 spec 은 회귀 색을 주입하는 대조는 이미 갖고 있었고(5/5 red),
> 그래서 「판별력을 확인했다」고 적혀 있었다. 그 대조가 다루지 않은 축이 **도달**이었다.
