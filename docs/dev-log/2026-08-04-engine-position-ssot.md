## §1. 판정 — ④ = 0 ⇒ 슬라이스 2 미착수

근거 3층은 [ADR-022 §슬라이스 1 실측](../decisions/022-engine-position-ssot.md) 에 표로 있다.
요지만:

1. **연역 상계** — 주입은 엔진이 완전히 비었을 때만 일어나므로(`strategy_state.py:357`)
   **주입이 값을 넣는 tick ⊆ `exchange_only` tick**.
2. **모집단** — 17.06h 차분에서 `exchange_only` **+1**, 하드 `direction` 킬 **+2**.
   ★**결과 사건이 발화한 창**이다. 「무사고라 못 쟀다」가 아니다.
3. **부검 2/2** — 사망 세션 2건의 상류에 `exchange_only` **0건**. 유일한 1건은 세션 첫 tick 의
   먼지 잔여(`engine 0.0 / exchange -0.001`)라 원장이 비어 주입 대상이 아니다. 최악 상계 ≤ **1/21**.

**왜 0 인가** — 사망 경로는 **반전**이고 반전은 tick 경계에서 flat 을 거치지 않는다. C 의 전제가
사망 경로에서 구조적으로 밟히지 않는다. ADR-022 §결과의 예고(「같은 tick 에 공존할 수 없다」)가
**같은 에피소드 어디에도 없다**로 강해졌다.

★**예고가 맞았다는 것을 지우지 마라** — ADR-022 는 착수 전에 이미 「C 는 교정이 아니라 예방」이라고
적었다. 이번 실측은 그 예방의 **대상 자체가 비어 있음**을 보탠 것이다. 그래서 §결과 문단을
고치지 않고 실측 절을 **덧붙였다.**

## §2. ★더 큰 것 — net 은 맞고 legs 는 틀리다

⑤를 재려고 과거 **29세션 전량**에 `derive_open_position` 을 프로덕션과 같은 호출로 재생했다.

**⑤ = 판정 불가 8/29 = 27.6%**, 그중 **7건이 `duplicate_open`**(나머지 1건 `foreign_fill`).
소크 19 tick 에서는 **0/19** 였다 — ★**작은 창의 0 은 0 이 아니다.**

**뿌리 둘.**

1. **`trade_id` 는 trade 인스턴스가 아니라 Pine 진입 규칙 이름이다.** 실측 `PivRevSE`
   **56 체결 / 19 세션** · `PivRevLE` 39/16. 한 세션 안에서 같은 규칙이 여러 번 발화하면 같은 id 가
   반복된다.
2. **반전은 `:close:` 키를 만들지 않는다.** 배(倍) 수량 진입 주문 하나로 나간다 — 실측:
   숏 `0.03` 보유 중 롱 `0.06` 진입(= 청산 0.03 + 신규 0.03), 그 세션 원장에 `:close:` 키 **0건**.

⇒ 유도 함수 docstring 의 전제 「어느 진입을 어느 청산이 닫았는지 **키만으로 이어붙일 수 있다**」가
**반전 전략에서 성립하지 않는다.** 이 소크의 전략이 정확히 반전 전략(`PivRev*`)이다.

### 구현과 독립된 오라클 — 외부 진실로 재판정

「유도 함수가 맞나」를 유도 함수로 물으면 동어반복이다. **워커 로그가 그 시각 거래소에서 직접 읽은
`exchange_position`** 을 오라클로 썼다(유도 함수가 만들지 않은 값). 발산 이벤트 11건 전량:

| 판정      | 건수  |                                                      |
| --------- | ----- | ---------------------------------------------------- |
| 빗나감    | **0** | 유도 함수는 **틀린 답을 낸 적이 없다**               |
| 적중      | 4     | ★**4건 전부 `legs=2`** 인데 거래소는 **단일 포지션** |
| 판정 불가 | 7     | 전부 `duplicate_open`                                |

예: 숏 0.03 + 롱 0.06 → net **+0.03**(거래소와 일치 ✓) 인데 실제는 **롱 0.03 하나**다.

★★★**슬라이스 1 은 net 으로 `agree` 를 판정하고 슬라이스 2 는 legs 를 주입한다.** 즉
**계측이 초록이어도 주입될 값은 틀렸다.** 잘못된 legs 를 넣으면 진입가·청산 대상·`liq_price`·
pyramiding 캡이 허구가 되고, 없는 leg 를 닫으려는 reduce-only 주문이 거래소에서 거절된다
(이 레포가 이미 기록한 `110017` 형태). ⇒ **④가 0 이 아니었더라도 슬라이스 2 는 못 켠다.**

### ★회고가 아니다 — 같은 형태가 지금 소크에서 발화 중이다

`2026-08-04T03:34Z`(소크 `bbea6da4` T0+40분) 실측. 그 세션 원장은 두 줄뿐이다:

★**설계 미덕 하나는 실증됐다** — 「모른다」와 「비었다」를 접지 않은 fail-closed 가 실제로 작동해

다음 사람이 「유도 함수가 틀렸다」로 읽고 fail-closed 설계까지 되돌린다.

## §7. 이번 회차의 교훈

- ★★★**초록의 근거와 사용처가 다르면 그 초록은 허가가 아니다.** 계측은 net 을 보고 `agree` 를
  냈고, 쓸 값은 legs 였다. **무엇으로 판정했는지와 무엇을 쓸 것인지를 같은 줄에 적어라.**
- ★★★**작은 창의 0 은 0 이 아니다.** 19 tick 에서 ⑤ = 0/19 였고 29세션에서 27.6% 였다.
- ★★**모집단이 비었다는 것과 관측을 못 했다는 것은 다르다.** 이번엔 **결과 사건이 2회 발화한**
  창이라 상류를 읽을 수 있었다 — 그래서 「N시간 무사고」가 아니라 부검이 근거가 됐다.
- ★★**동어반복을 피하려면 값의 출처를 바꿔야 한다.** 같은 함수로 과거를 재생하면 판정 불가율은
  재도 정확성은 못 잰다. 정확성을 잰 것은 **로그에 남은 거래소 실측**뿐이다.
- ★**의심한 결함 하나는 코드로 반증됐다** — `len(fills) > LIMIT` 가 항상 False 일 거라 봤으나
  `list_fills_since` 가 `limit + 1` 을 가져온다. **보고하기 전에 조회 쪽을 읽어라.**
