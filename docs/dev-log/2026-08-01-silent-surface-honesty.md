## ★★★ 헤드라인 — 「기전 확정」이라던 것이 확정이 아니었고, 진짜 기전은 셋 다 아니었다

착수 프롬프트는 넷 다 기전이 확정됐다고 적었다. **BL-570 만은 아니었다** —
`backlog.md:5908`·`:5958` 이 스스로 「기전은 [가정]이고 미확정」이라고 두 번 적어 놨다.
그래서 10분짜리 판별식을 먼저 걸었고, **후보 셋이 전부 틀렸다.**

| 후보                                    | 예측한 `_formValues` | 실측    |
| --------------------------------------- | -------------------- | ------- |
| backlog 의 [가정] — `""` 로 남는다      | `""`                 | ✗       |
| CONTROL 경쟁 가설 — `Number(undefined)` | `NaN`                | ✗       |
| 정상 동작                               | `null`               | ✗       |
| **실측**                                | —                    | **`0`** |

**뿌리.** react-hook-form 은 registration 시점에 **DOM 문자열이 아니라 defaultValue 를 그대로**
`setValueAs` 에 넘긴다(`setFieldValue` → `getFieldValueAs`). `""` 만 거르던 구현에서는 `null` 이
새어 **`Number(null) === 0`** 이 되고, zod `.gt(0)` 이 그 0 을 거부해 `handleSubmit` 이 막혔다.

실브라우저 실측(수정 전, `/strategies/0d94167b.../edit`):

## ★★ 문서가 틀린 곳 — 「저장 경로 자체는 정상이다」가 반증됐다

`backlog.md` BL-570 은 대조군을 이렇게 적었다 — _"레버리지를 2→3 으로 실제 편집한 뒤 누르면
PUT 200 + 토스트 + 원장 반영 — **저장 경로 자체는 정상이다**"_.

**실측은 그것도 실패한다.** 레버리지만 고쳐도 `cap` 이 `0` 인 채로 남아 zod 가 계속 거부한다
(Z4 실행 로그: `dirtyFields:["leverage"]` · 클릭 후 `errorKeys:["max_trigger_breach_pct"]` · `PUTS []`).

⇒ **결함의 크기가 「무편집 클릭이라는 코너 케이스」가 아니라 「이 전략은 트레이딩 설정을
저장할 방법이 없다」로 커진다.** 유일하게 살아 있던 경로는 **cap 입력칸에 change 이벤트를 한 번
태우는 것**뿐이었다(Z4b: touch → `PUT 200` × 2). QA 가 관측한 「대조군 성공」은 그 경로였을 것이다.

- ★**BL-570 의 뿌리를 jsdom 으로는 잠글 수 없다.** 단위 테스트는 (a) errors 렌더 · (b) onInvalid
  두 층만 지킨다. 뿌리(`Number(null) === 0`)는 **실브라우저 e2e 에만** 잠겨 있고, `pnpm e2e` 는

  전부다.
