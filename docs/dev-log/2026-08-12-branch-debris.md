### ⑴ 프롬프트가 준 「실측」 6건 중 4건이 틀렸다

원격 291(→**290**) · A 217(→**270**) · C 68(→**14**) · 워크트리 보호 4개(→**11개**, 게다가 11개
**전부 local-only** 라 원격 삭제가 구조적으로 못 건드린다). 맞은 것은 B 6 뿐.

분모가 틀린 원인은 `git branch -r --format='%(refname:short)'` 가 `refs/remotes/origin/HEAD` 를
**`origin`** 으로 축약한다는 것이었다. `grep -vx HEAD` 로는 안 걸린다. 이전 회차 메모의
`337 = 47 + 290` 과 290 이 일치해 교차 확인됐다.

내 수치는 GraphQL(`gh pr list`)과 REST(`gh api .../pulls --paginate`) **두 경로가 완전히 일치**한다
(504행 / MERGED 473 / CLOSED 31 / OPEN 0).

### ⑵ 안전망은 이름이 아니라 sha 다 — 그리고 복원 버튼은 팁을 되살리지 않는다

프롬프트는 「A·B 는 PR 이 있으므로 GitHub 이 sha 를 보관하고 복원 버튼이 살아 있다」를 삭제의
안전 근거로 세웠다. **복원 버튼이 되살리는 것은 PR 의 `head.sha` 이지 브랜치의 현재 팁이 아니다.**
팁 sha ↔ PR head sha 를 맞추니 후보 276건 중 **9건**이 불일치했다(PR 머지 뒤 커밋이 더 쌓인 것).

로컬 축에서는 같은 실수를 **이름 일치**로 반복했다 — `feat/tpsl-phase3-fe-perf` 는 원격
`feat/tpsl-phase3-c-fe` 와 **같은 팁 sha**(`3b8e589c`)인데 이름이 달라 「안전망 없음」으로 셌다.

### ⑶ 고치면서 항진명제를 만들었다

⑵를 고치며 `git rev-list --all --remotes=origin` 을 썼다. `--all` 이 **로컬 ref 까지** 포함하므로
로컬 브랜치 팁이 **자기 자신 때문에** 집합에 들어간다 ⇒ **165건 전부 「안전」**.
집합 1,635 → `--all` 제거 후 **1,034** (601개가 가짜였다).

**「전건 안전」이 너무 좋아 보인 것이 유일한 단서였다.** 그래서 판별력 시험을 세웠다:
`git commit-tree` 로 원격에 없는 커밋을 만들어 「밖」 판정 확인(음성), `origin/main` 팁 「안」 확인(양성).
★이 시험을 **먼저** 세웠으면 ⑶을 만들지 않았다.

### ⑷ 병렬 fan-out 이 두 번 조용히 0행을 냈다

`export -f` → 0행(zsh 의 `export` 는 `-f` 를 안 받고 함수 정의를 stdout 으로 뱉는다).
고쳐 쓴 `xargs -P 6 -d '\n'` → 0행(`-d` 는 GNU 전용, BSD 는 `invalid option -- d` 로 죽는다).
★**둘 다 실제로는 에러를 냈다 — 조용하게 만든 것은 내가 붙인 `2>/dev/null` 이다.**
**0행을 성공으로 읽지 않게 막은 것은 `[ "$(wc -l)" -eq N ]` 가드뿐이다.**

첫 번째 실패는 오히려 회차를 살렸다 — 그 fan-out 이 돌았다면
`GET /commits/{sha}/pulls` 로 276건을 조회해 **전부 `NONE`** 을 받았을 것이다. 그 API 는
이 레포에서 **판별력이 0** 이다(실제 PR 의 head sha 에 빈 배열을 반환한다).
