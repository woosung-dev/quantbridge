## ★★★ 헤드라인 — 두 회차 동안 못 얻은 증거를 유도로 얻었다

직전 회차는 `_write_back_confirmed_terminal` 를 착지시키고도 **그 코드가 실주행에서 한 번도
실행되지 않은 채** 끝났다. 이번엔 기다리지 않고 **조건을 만들었다.**

```
17:40:34  793e79db  조건부 sell 등재 (state=submitted, 거래소에 살아 있음)
~17:41:20 CONTROL 이 거래소에서만 취소 (provider.cancel_order 1회 · 원장 미변경)
17:42:23  live_conditional_reconcile_divergence  order_id=793e79db   ← 리컨사일러가 최초 관측
17:42:23  원장 state=cancelled  (filled_at = updated_at, 같은 초)
          qb_live_conditional_reconcile_errors_total{stage=terminal_write_back_cancelled} = 1.0
```

- **독립 계측기 2개가 같은 초에 일치** — Prometheus counter ↔ `trading.orders` 원장 전이.
- 로그 이름이 `..._reconcile_divergence` 라 **스윕이 아니라 리컨사일러**가 최초 관측자였음이 확정된다
  (스윕이면 `live_conditional_entry_sweep_found_filled` 가 찍힌다).
- **거래소 terminal → 원장 기록 = 약 60초(리컨사일러 1틱).** BL-560 사고 때 같은 축의 값은 **818초**였다.

★**왜 기다리면 안 됐나 — 기저율을 먼저 쟀다.** `terminal_write_back_*` series 는 부재였고,
역사상 유일한 「스윕이 체결을 뒤늦게 발견」 사건은 `2026-07-31 07:44:13` **사고 그 자체**(pre-fix)였다.
즉 자연 발생 기저율 ≈ **4일에 1회**. 창을 늘리는 방법으로는 영원히 못 잰다.
경쟁자는 `trading.fetch_order_status`(15s/30s 백오프)와 `trading.scan_stuck_orders`(beat **300초**)이고,
**`scan_stuck_orders` 직후에 유도를 걸어** 리컨사일러(≈60초)에게 2~3틱의 런웨이를 줬다.
