## 1. 계측기가 먼저다

### 1.1 토큰 환산비는 추정이 아니다 — 트랜스크립트에서 역산했다

한국어는 바이트/문자/토큰 비가 전부 다르다. 그래서 실제 세션 기록에서 계수를 뽑았다 —
단일 `tool_result` 만 들어간 턴에서

```
tokens(tool_result) ≈ Δ(input + cache_creation + cache_read) − 직전 턴 output_tokens
```

직전 3회차 CONTROL 세션(`80dcce10` divergence-label-split · `48be44f4` entry-completeness-rejudgement ·
`8cc0bf0f` silent-surface-honesty)에서 md 표본 **16건 110,395자 → 81,218 tok = 0.736 tok/자**.
코드 0.445 · Bash 출력 0.587. 계수와 그 출처를 `scripts/context-budget.sh` 주석에 박았다 —
**어디서 온 숫자인지 모르는 상수를 남기지 않는다.**

## 2. ★착수 전제 4건 중 3건이 반증됐다

### 2.1 「자동 로드 = 56.6KB · 컨텍스트의 20%」 → **19,319 tok · peak 의 3.3~3.7%**

`CLAUDE.md` 가 import 하는 것은 `@AGENTS.md` **하나뿐**이다.
실제 고정비 = `MEMORY.md 13,487 + AGENTS.md 4,094 + 개인 CLAUDE.md 1,730 + repo CLAUDE.md 8`.

### 2.2 ★★★「`CONTEXT.md` 를 또 읽는 것이 중복 낭비」 → **반대다. 안 읽으면 안 들어온다**

착수 프롬프트 §0 은 「`CONTEXT.md` 는 읽지 마라 — 이미 자동 로드된다」고 했고 §4 는 그 지시를
다음 회차 템플릿에 반영하라고 했다. **그대로 했으면 도메인 헌법이 통째로 사라진다.**
이 회차가 §3 에 경계 대상으로 적어 둔 **「삭제에 의한 역선택」이 착수 지시 자체에 들어 있었다.**

### 2.3 「`.ai/rules/*.md` 는 `paths` frontmatter 로 자동 로드」 → **로더가 없다**

`CLAUDE.md` 의 `@` import 체인에도 `.claude/settings.json` 훅에도 없다.
「`global.md` 만 항상 로드」는 거짓이었고, 실제로는 세션마다 **손으로 3~6회**(10~23K자) 열고 있었다.

### 2.4 「`INDEX.md` 가 최악」 → **맞다** (유일하게 맞은 전제)

`## Quick Summary` 한 섹션이 **162,424자**, 표 34행 평균 4,700자, **구분선 한 줄이 4,607자**.
직전 회차의 `head -20 INDEX.md; grep …` **한 번이 16,104자**로 그 세션 **최대 단일 tool_result** 였다.

### 2.5 프롬프트가 약속한 절감 중 실현 불가였던 것

- **「프롬프트 템플릿 정정 = 10.9KB/회」 → 실현 가능액 0.** 3회차 전부 `AGENTS.md` 를 **Read 한 적이 없고**
  `CONTEXT.md` Read 는 중복이 아니라 필수였다. 뺄 중복이 없었다.
- **「`status.md` 드리프트 정정」 → 이미 PR #521 에서 고쳐져 있었다.**
- **`herdr-fleet.sh` 가 워크트리에서 거부된다** — §6 함대 배치를 실행할 수 없어 서브에이전트로 대체(§7).

## 4. ★내 계측기가 여섯 번 틀렸다

1. **`awk length()` 가 바이트를 셌다.** `backlog.md` 최대 줄을 3,008자로 읽었으나 실제 **1,913자**,
   `roadmap.md` 의 1,000자 초과 줄은 8이 아니라 **0**이었다. 한국어에서 바이트/문자 ≈ 1.45.
2. **공백 정규화 sha256 이 마크다운 의미 변화를 못 봤다.** 긴 줄을 접었더니 산문 속
   `+ **BL-416 Resolved**` 가 줄머리로 가면서 **리스트 항목이 됐다.** sha256 은 「동일」이라고 답했다.
   ⇒ 줄머리 블록 마커 생성 금지 가드로 2건 교정. 최종 증명은 **파일 전체 prettier 정규형 일치 +
   블록 개수 불변**(리스트 167 · 표행 180 · 헤딩 272)으로 바꿨다.
3. **`prettier --check` 가 경로 의존이었다.** 스크래치패드에서는 clean, 레포 안에서는 not clean —
   `.editorconfig` 때문이다. 「HEAD 는 prettier-clean 이다」라는 내 판단이 그 artifact 였다.
4. **C4 검사기 v1 이 압축 후 공허하게 통과할 참이었다.** 「300자 초과 줄」만 검사하므로
   압축이 끝나면 **검사 대상이 0**이 된다. 길이 문턱을 없앤 v2 로 바꾸고 **압축 전 트리에서 38건을
   잡는 것**으로 판별력을 먼저 증명했다. (압축 워커도 독립적으로 같은 결함을 발견해 보고했다.)
5. **C4 v2 가 PR 번호에 과잉 발화했다.** 「인용 토큰이 링크 대상에 있어야 한다」를 PR 번호에도

   `bl474-ingress-parity` ↔ `2026-07-26-bl474-webhook-ingress-parity.md` 를 놓쳤고(파일명이

- **`MEMORY.md` 압축은 C3 로 검증되지 않는다.** 판별력 시험은 레포 문서만 대상으로 하고
  개인 메모리는 서브에이전트 컨텍스트에 애초에 들어가지 않는다. 그 위험은 **미래의 내 세션**에 있다.
- **C4 는 「상세가 실재하는가」를 증명하지 「좋은 자리에 있는가」를 증명하지 않는다.**
  원문 아카이브로 링크하면 토큰은 언제나 실재한다.
- **변동비는 프로브 기반이다** — 새 세션을 실제로 돌려 잰 것이 아니라, 직전 회차가 실제로 친 명령을
  before/after 에 똑같이 먹여 stdout 을 센 것이다.
- **`AGENTS.md` 는 줄이려다 늘었다**(+389 tok). 정정이 새 내용이라서다. 사후에 목표를 옮기지 않고
