## §1. 관측 2건 — 둘 다 「수리할 것이 없다」

### ① `breach_with_resting` 11→12 은 정상이고, **확인식이 구조적으로 성립 불가**였다

status.md 가 「`breach_with_resting` 이 증가할 때 `market_converted` 동시 증가」를 확인식으로 정해
두었고, 동시 증가가 **없어서** 이상으로 인계됐다.

워커 로그에 그 한 줄이 그대로 있었다:

```
03:03:14 live_conditional_plan_drop session_id=bbea6da4… trade_id=PivRevSE
         reason=trigger_already_breached direction=short
         stop_price=63774.59 reference_price=63761.2
         had_resting=true resting_could_have_fired=true
```

코드(`conditional_entry_planner.py:442-447`)를 보면 이 갈래의 조건이
`breached and (resting_could_have_fired or not allow_market_conversion)` 이다. **그 갈래는 곧바로
`continue` 하므로 같은 leg 에서 `market_converted` 가 오를 수 없다.** ⇒ **확인식이 요구한 동시
증가는 코드상 일어날 수 없다.**

그리고 이 드롭은 **옳았다.** 그 대기 주문(`02:57:21 sell trigger 63774.5`)은 기준가 63761.2 보다
위에 있어 발화 가능했고, **57초 뒤인 `03:04:11` 에 실제로 체결됐다.** 시장가로 전환했으면 이중
진입이었다 — PR #493 이 막으려던 바로 그것이다.

★**대체 관측축**: counter 가 아니라 로그의 **`resting_could_have_fired`** 를 봐라. **`false`** 인
건이 [BL-589] 결함 형태다. (status.md 상비 참조에 반영)

### ② `terminal_write_back_filled` 은 **에러가 아니다 — 아무것도 던지지 않았다**

인계문은 「write-back 경로에서 무엇이 던지는지 로그에서 찾아라」였다. 던진 것이 없다.

```python
# live_signal.py:1300-1313
won = await _write_back_confirmed_terminal(...)
_count_safely(
    qb_live_conditional_reconcile_errors_total,
    stage=(f"terminal_write_back_{won}" if won is not None else "terminal_write_back_lost"),
)
```

`_write_back_confirmed_terminal`(`:958`)의 docstring이 답을 갖고 있다 — 「반환값은 **이 호출이
전이의 승자였을 때만** 그 terminal 상태명이고, 아니면 None」. ⇒ `terminal_write_back_filled` 는
**[BL-560] 수리가 체결을 앞당겨 기록하는 데 성공한 횟수**다. **성공이 "reconciliation failures"
라는 이름의 counter 에 계상되고 있다.**

심각도는 낮다 — 소비자가 전부 `stage` 라벨 단위라 자동 판정은 안 깨진다. **피해는 사람의
오독이고, 이번 인계문이 정확히 그 오독이었다.** [BL-566] 계열에 등재(새 BL 없음, 사용자 지시).

## §2. 신규 실측 — 판정 불가는 「비율」이 아니라 **흡수 상태**다

`_capture_ledger_shadow` 는 `since = sess.created_at`(`live_signal.py:471`)으로 **세션 전체**를
읽는다. ⇒ `trade_id` 가 한 번 반복되면 **그 뒤 모든 tick 이 영구히 `legs=None`** 이다.

**프로덕션이 실시간으로 증명했다** — `03:48:16` 이후 `derive_total{open}` 이 **44.0 에서 완전

### 판정 — veto 절반까지 꺼진다

[ADR-022] 의 C 는 두 절반이다. ④=0 이 **주입**을 막았지만 **veto/관망**은 `net` 만 필요하고 net 은
오답 0/11 이라 **살아 있다고 볼 수 있었다.** 그 여지가 이번에 닫혔다:

1. **사망 시점에 유도가 판정 불가였다** — veto 를 계산할 입력이 없다.
2. **설령 계산됐어도 발화하지 않는다** — veto 는 「원장 vs 거래소」 대조인데 사망 경로는
   **원장 == 거래소이고 엔진만 거짓말**한다. `agree` 로 통과하고 `direction` 킬이 그대로 난다.
3. **방향이 반대다** — `engine_only` **314** vs `exchange_only` **21**. C 가 메우는 것은 21 쪽이다.

⇒ **C 는 예방 전용이며 사망 경로에 구조적으로 닿지 않는다.**

## §3. ★본론 — 우리가 세 번 기각한 것이 결함 그 자체였다

`run_live(strategy.pine_source, df, ...)` 는 **전략 코드와 가격 데이터만** 받는다. 나가는 길
(엔진 → outbox → `orders` → 거래소)은 있는데 **돌아오는 길이 0곳**이다 — 체결을 원장에 쓰는 자리는
**6곳**인데(`live_signal.py:998` · `conditional_entry_janitor.py:130` · `trading.py:472`·`:820` ·
`websocket/reconciliation.py:234` · `websocket/state_handler.py:236`) 엔진으로 가는 것은 없다.

비대칭의 뿌리도 코드가 적고 있다(`conditional_entry_planner.py:418`) — **시뮬의 체결은 보장이고
거래소의 체결은 아니다.** `check_pending_fills` 는 `low <= stop` 이면 무조건 체결로 치고, 거래소는
`110092`/`110093` 으로 거절한다. 그래서 `engine_only` 가 `exchange_only` 의 **15배**다.

### 순환 기각 3건

| #   | 기각한 것                            | 기각 사유                                    | 왜 순환인가                                                                  |
| --- | ------------------------------------ | -------------------------------------------- | ---------------------------------------------------------------------------- |
| 1   | [ADR-022] **대안 D**(조정 연산 정의) | 「엔진에 쓸 자리가 없으므로… C 의 부분집합」 | **「쓸 자리 없음」이 결함 그 자체**다. 경계가 아니라 고칠 대상               |
| 2   | 「백테스트/라이브가 갈라진다」       | 엔진을 포크해야 한다는 전제                  | NautilusTrader: **reconciliation 은 라이브 전용**(백테스트는 양쪽을 다 쥔다) |
| 3   | 「합성 주문 행이 머니-패스를 오염」  | 「발주한 적 없는 주문 행이 섞인다」          | 그쪽은 **꼬리표를 붙인다**(`strategy_id=EXTERNAL`/`tag=RECONCILIATION`)      |

★**2번은 안심 재료가 아니다.** 실측해보니 **Trust Layer 3파일 23테스트가 `run_live` 를 0회
호출**한다. 즉 **라이브가 갈라져도 CI 는 구조적으로 green** 이다. 정확한 문장은 「엔진을 포크할
필요는 없다. 그러나 갈라짐을 잡을 CI 는 지금 0개다」이다.

### 선행연구 — 우리가 구조적으로 예외다

|                    | 포지션 소유자                                     | 전략의 정체                       |
| ------------------ | ------------------------------------------------- | --------------------------------- |
| **NautilusTrader** | `ExecutionEngine` + `Cache`(이벤트 소싱, 영속)    | 명령 송신 / 이벤트 수신 액터      |
| **Freqtrade**      | `Trade` DB 행                                     | **가격 데이터프레임의 순수 함수** |
| **QuantBridge**    | ★**`StrategyState.open_trades` — 매 tick 재계산** | 가격의 순수 함수                  |

Freqtrade 가 **우리와 구조가 거의 같은데** 라이브 루프 첫 두 줄이 「Fetch open trades **from
persistence**」·「Update trades open order state **from exchange**」다. 전략은 **읽기만** 하고
그 읽기 경로는 **라이브 전용**이다(백테스트에선 빈 결과).

그리고 **우리가 죽이는 상황이 그쪽엔 이름이 붙어 있다** — `Position side flip`(내부와 거래소가
정반대) → _"Generates LIMIT order to close internal and open external position."_ **우리는 세션을
죽이고 그쪽은 맞추는 주문을 낸다.**

★**[BL-591] 의 「유도 함수 재설계」 알고리즘도 공개돼 있다** — `trade_id` 짝짓기가 아니라 **부호
있는 순수량의 zero-crossing 으로 생애주기를 자른다.** 오늘 소크의 체결 사슬
(−0.029 → +0.029 → −0.029 → +0.029)은 반전마다 0을 지난다. `trade_id` 재사용·배수량 반전에
**구조적으로 면역**이다.

| 항목                                      | 실측                                                            |

⇒ 「Pine 은 전략이 포지션을 소유한다는 의미론이라 못 뺀다」는 **6곳짜리 seam** 이다.

### ★★★새 위험 R1 — replay 가 우연히 float 오차 청소부였다

`event_loop.py:595-604` 의 실측: `0.02953691 + 0.02946167 → 0.058998579999999995`.
**지금은 매 tick warmup replay 가 이 오차를 매번 리셋한다.** 영속화하면 리셋이 사라져 **단조
누적**된다. 아무도 이름 붙인 적이 없고, ADR-023 이 대안(주기적 재정규화 / Decimal 승격 / 재양자화)
없이는 판정 불가다. 나머지 R2~R8(→ `to_report()` round-trip 불가 · `events` 가 outbox 유일 소스 ·
Track A 병렬 경로 · within-bar 즉시성 · NaN · 재현성 · 멱등성)은 ADR-023 §대가.

## §5. 내가 틀린 것

- **「`.metrics` 증가 0」이 과장이었다.** 57분 창으로 「신규 0개」라고 먼저 적었는데, 같은 회차
  안에서 90분 창으로 다시 재니 **5개**였다. ★**n=1 창으로 「0」을 주장하지 마라** — 이 레포가
  이미 「작은 창의 0 은 0 이 아니다」로 적어둔 것을 **내가 그 문장을 인용하면서 밟았다.**
  정정본: 편집 세션 **~600/h** vs 조용한 소크 **~4–5/h** ⇒ 잔여 5,091 파일 = **약 42일**.
  결론([BL-581] 은 소크 창의 상한이 아니다)은 유지된다.
- **「`engine_only` 314 = 시뮬만 체결」로 단정했다.** 분류기는 「엔진 non-flat + 거래소 flat」이라는
  **상태만** 세고 **원인은 안 센다.** 후보가 최소 셋(주문 미발주·거래소발 청산·outbox 미발행)이고
  **어느 쪽이 지배적이냐에 따라 수리의 모양이 달라진다.** ⇒ ADR-023 §선행 측정으로 이관, 다음
  회차의 본 작업.
- **「ADR-020 Trust Layer 위험은 과대평가」라고 먼저 말했다.** 결론은 맞았는데 **이유가 틀렸다** —
  위험이 작은 게 아니라 **그걸 재는 장치가 0개**다. 안심이 아니라 경보다.
- **사전등록 예측에 창을 안 적었다** — 26.5분 만에 판정을 시도했는데 그 창에서는 두 가설 모두 0 을
  예측하므로 **판별력이 0**이었다. 이 레포가 이미 적어둔 규칙(「판정 지표가 그 창에서 발화
  가능한지 먼저 계산해라」)을 **남의 지표엔 적용하고 내 예측엔 적용하지 않았다.**
- ★**docs-only 푸시 3회로 CI 런 2개를 취소시켰다**(`04:45 cancelled` · `04:49 cancelled`).
  메모리에 **「docs-only push 반복이 CI 를 3회 취소」가 이미 적혀 있는데 같은 것을 반복했다.**
  ⇒ **회차 안 docs 커밋은 모아서 마지막에 한 번만 푸시해라.**

**ADR-023 의 긴급도**와 **다음 회차의 측정 방법**(라이브 관측 불가 → 과거 재생만 가능)이다.

## §5.6 그리고 같은 회차에 분해까지 했다 — **채널은 닫혔다 (157배)**

§5.5 가 던진 「314 가 언제 쌓였나」를 바로 갈랐다. 워커 로그 **39.5시간**(08-02 13:21 → 08-04 04:54)
에 `engine_only` 문자열이 **0회**다. ★단 「39.5시간」은 오해를 부른다 — 이 발산은 **세션이 돌 때만**
발화하므로 **라이브 노출 시간**으로 재야 한다.

| 창                                            | 라이브 시간        | `engine_only` 계열   | 발생률     |
| --------------------------------------------- | ------------------ | -------------------- | ---------- |
| **A** counter 출생(07-28 12:19) → 08-01 11:52 | **16.72h**(14세션) | **314**              | **18.8/h** |
| **B** 08-01 11:52 → 08-04 04:54               | **8.35h**(8세션)   | **1**(`unexplained`) | **0.12/h** |

기대 **157건** vs 관측 **1건**. `4bf679af`(163분) 단일 세션으로도 반증(기대 51 vs 0).
★창 A 의 18.8/h 는 [BL-566] 이 독립적으로 잰 **41.6/h → 12.9/h** 와 같은 자릿수라 **두 계측이
서로를 교차검증한다.**

★★**라벨 이동이 아니라 현상 정지다.** `_subclassify_engine_only_divergence`(`:772`)는 `None` 을
반환하지 않는다 — 조회 실패면 raw, 기대 방향 대기 진입이 있으면 `awaiting_trigger`, 없으면
`unexplained`. 계속됐다면 `awaiting_trigger` 가 자랐어야 하는데 **그 series 가 `/metrics` 에 아예
없다**(prometheus 는 `.inc()` 한 번이면 series 가 생긴다).

**닫은 것 — `#515` 유력.** `a6d891b1`(08-01 01:02, [BL-560] write-back 수리)은 **행위 변경**
(`live_signal.py` +277 · `trading.py` +233 · `strategy_state.py` +40)이고 그 커밋이 「원장이 낡은
채로 돌았다」고 적고 있다. `51f8e51d`(#516, 11:52)는 **계측만**(+104 = 분류기)이라 **인과 불가**.

★★**귀속은 「관측 판정 불가」로 닫았다** — 두 커밋 사이(01:02 ~ 11:52)에 **라이브 세션이 0건**이라
가를 데이터가 **존재하지 않는다.** 남는 근거는 연역(#516 인과 불가)뿐이다. **다음 사람은 이걸
데이터로 다시 캐지 마라** — 본 ADR 의 결론(표적 = `direction`)이 귀속과 무관하므로 #515 의 diff 를
읽어 기전을 논증하는 비용을 치를 이유도 없다.

★**본 ADR 에 대한 함의 — 죽지 않지만 표적이 바뀐다.** 단방향 파이프는 그대로고
(`direction_transient` 가 계속 나는 것이 증거 — 양쪽 non-flat 이라 C 의 주입 조건이 아니다),
**사망 2건도 모두 `direction` 경로**다. 바뀌는 것은 **표적**이다 — 「유령 포지션 제거」가 아니라
**「반전 시 거래소가 못 따라오는 구간」**. §3 의 「15 대 1」을 근거로 슬라이스를 짜면 **닫힌 채널을
겨냥하게 된다.**

⇒ **§6 이 「다음 회차 본 작업」으로 넘겼던 것이 같은 회차에 끝났다.** 다음 회차의 본 작업은
**표적을 `direction` 으로 옮긴 슬라이스 설계**다.
