## 실측이 킥오프 전제를 3건 정정했다

**① "authed 13 spec 이 실패한다" 는 파일 수를 테스트 수로 오독한 것.** 실제 = 13파일 / 64테스트, 하드 실패는 **6개**, 나머지 57 은 `page.route` 목킹이라 빈 DB 에서도 통과한다.

→ 그런데 **진짜 문제가 따로 있었다.** 캐논 감사 **9건이 조용히 통과**한다. 감사기는 *렌더된 것*의 하드 실패 수만 세는데 빈 DB 에서는 `StateBox` 하나뿐이라, 11열 표·최대 585 체결 원장이 사라진 걸 빨간 신호 없이 놓친다. baseline 측정 조건이 `authed-canon-p1.spec.ts:16-18` 에 **문서화돼 있는데 단정되지 않는다**(→ BL-470). C 의 가치는 "6건 빨강→초록" 이 아니라 **"9건 헛통과→실제 감사 복원"** 이었다.

**② 복원은 거의 공짜였다.** `TimescaleProvider` 가 cache-first + live CCXT fill 이라 **백테스트 1회가 곧 시딩**이다. 실측 9,337행(389일 × 24 + 1) · 갭 0. 별도 backfill 경로가 필요 없다.

**③ 프로즌 픽스처는 현재 경로에서 도달 불가.** `FixtureProvider` 가 `root / f"{symbol}_{tf}.csv"` 를 만드는데 canonical `BTC/USDT` 의 슬래시가 **경로 구분자**가 된다. 레포의 빈 `backend/data/fixtures/ohlcv/BTC/` 디렉터리가 과거에 누가 여기 부딪힌 흔적이다(→ BL-468).

## ★★워커가 구 코드였다 — 그래서 legacy 행이 공짜였다

착수 시 `quantbridge-worker` 가 `b97ac57`(#480) **8시간 전** 이미지로 돌고 있었다. bind mount 없는 baked image, §7.2 위반 상태.

## ★★dogfood 가 P1 을 잡았다 — 파산한 계좌에 양수 샤프

시드된 실행 하나가 **총수익률 −2179.68% 인데 샤프 +0.029** 였다.

원인 — 기간 수익률은 `(cur - prev) / prev` 다. `prev` 가 음수면 **부호가 뒤집혀 더 잃을수록 수익률이 양수**가 된다. `_periodic_returns` 는 `prev == 0` 만 막고 있었다(분모를 고민한 흔적은 있는데 음수 케이스만 빠졌다).

실측 — 10,000 시작 → **−207,968** 종료, 자본이 9,337 지점 중 **8,874(95%)에서 음수**, 월간 수익률 13개 중 **11개가 양수**.

**이건 BL-398(#480)이 없애려던 거짓말의 다른 얼굴이다.** 그쪽은 수식(bar 기준 t-통계량) 때문이었고 이쪽은 분모 부호 때문이라 원인이 다를 뿐, 화면에 나오는 결과는 똑같이 "파산했는데 위험조정수익이 양수" 다.

**★그리고 committed Trust Layer baseline 이 그걸 담고 있었다.**

```
s1_pbr   baseline sharpe +0.60013053  sortino +2.34906069   총수익률 -5.36696128 (-536%)
```

코퍼스 5종 중 **4종이 자본을 음수로 몬다**(s1_pbr 81.8% · s2_utbot 84.2% · i1_utbot 84.2% · s3_rsid 3.6%). 거래가 0인 `i2_luxalgo` 만 무관하고, **골든 parity 가 깨진 것도 정확히 그 4종**이다. 대응이 완벽해 가드가 의도한 대상에만 발화함을 증명한다.

**수정** — `_has_nonpositive_equity` 술어를 `sharpe_ratio`·`sortino_ratio` 앞에 두고 신규 마커 `unavailable_nonpositive_equity` 를 반환한다. `unavailable` 과 합치지 **않은** 이유 = 그쪽 문구("변동이 없거나 기간이 짧아")가 파산한 계좌에는 적극적으로 틀리다. 계좌가 무너진 것과 잔잔한 것은 다른 사실이다.

**baseline 재생성 차분 봉인** — 12 메트릭 키 중 **2개만**(`sharpe_ratio`·`sortino_ratio`), 해당 4 코퍼스 한정, `ohlcv_sha256` 불변, 거래수·수익률·드로다운 전부 동일.

**음수 자본 자체는 안 고쳤다** — L=1 에서 마진 게이트는 `is_leverage_active` 조기 반환으로 no-op 이고(#480 TV/MT5 컨벤션의 귀결) 청산도 없다. 설계 귀결이라 별도 BL-466 으로 분리했다. 여기서 닫은 것은 **그 위에서 지표가 거짓말하지 않는 것** 뿐이다.

## `make seed`

`backend/scripts/seed_dogfood.py` + Makefile 타깃. **실 서비스 계층 + 실 Celery** 경유 — HTTP/auth 만 우회한다. 이유: `authenticate_clerk_request` 가 `authorized_parties` 로 검증하고 clerk SDK(`verifytoken.py:44-46`)가 **`azp` 클레임을 필수**로 요구하는데 Clerk Backend API 로 발급한 토큰에는 `azp` 가 없다(브라우저 발급 토큰에만 있다) → 헤드리스 HTTP 시딩이 구조적으로 불가. 서비스 계층 경유라 `metrics` JSONB·`backtest_trades`·`equity_curve` 는 전부 **진짜 엔진 출력**이다.

함정 3종을 상수로 박았다 — canonical `BTC/USDT`(`ts.ohlcv` 는 읽기·쓰기 양쪽이 정규화를 지나므로 `BTCUSDT` 로 심으면 **모든 독자에게 안 보인다**) · 격자 정렬 UTC 경계(BL-309 유령 갭) · `exchange` NOT NULL.

**★시더에서 내 설계 결함이 드러났다** — `monthly` 가 `legacy` 와 입력이 완전 동일해 중복으로 스킵됐다. 그런데 "입력 동일 · 엔진 버전만 다름" 이 두 실행의 존재 이유다. 중복 판정을 실제 구분 성질(`sharpe_convention` 키 유무)로 바꿨다.

**전략은 3개** — S-A(PbR, 성과 실행 전부) · S-B(EMA, degenerate 전용) · S-C(HMA, optimizer 베이스). S-B 를 분리한 이유 = 전략목록·대시보드는 전략별 **최신 COMPLETED** 하나만 읽으므로 degenerate 를 S-A 에 섞으면 D1 을 화면에서 재현할 수 없다. S-C 를 분리한 이유 = Grid Search MVP 는 `input.int`/`input.float` 만 sweep 하는데 `s1_pbr` 은 bare `input(4, …)`(= `input.generic`)이라 거부된다.

산출 = 전략 3 / 백테스트 6 / 거래 3,194 / OHLCV 9,337 / optimizer 1. **재실행 전부 스킵(멱등).**

## 교훈

1. **stale worker 가 자산이 될 수 있다.** §7.2 위반 상태가 오히려 조작 없는 legacy 행을 공짜로 줬다. 다만 **순서가 비가역**이라 먼저 알아채지 못했으면 잃었을 기회였다 — 착수 시 sentinel 을 돌린 것이 값을 했다.
2. **"마커만 제거" 같은 지름길은 정직성 검사를 통과해야 한다.** 신 숫자에 구 각주를 붙이는 건 #481 픽스처 함정과 같은 부류다.
3. **가드를 만들면 판별력을 증명하라.** 첫 소스 스캔 규칙은 5곳 중 2곳만 잡았다. 통과했다고 넘어갔으면 커버리지 40% 짜리 가드를 커버리지 100% 로 착각했을 것이다.
4. **테스트 픽스처를 "정리" 하면 성질이 죽는다.** 실측 13표본을 6표본으로 줄이자 큰 음수 하나가 평균을 지배해 결함이 재현되지 않았다. 실측 계열을 그대로 썼다.
5. **dogfood 는 또 P1 을 잡았다** — 이번이 4번째다(#476 StrEnum 크래시 · #468 잠복 2건 · #480 마진 게이트 gross 자본 · 이번 음수 자본 샤프). 그리고 이번 것은 **트러스트 안전망 자체가 거짓말을 담고 있던** 경우다.
