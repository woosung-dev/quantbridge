## §1. 사전등록 (G1) — 코드 쓰기 **전**에 동결

`eca5323f` 선례). 아래가 그 흡수본이며, **§2 이후가 여기에 답한다.**

### 1.1 판정식 — 해로운 귀결 라벨

H1~H4 는 직전 회차 정의를 **글자 그대로** 재사용했다. 이번 대상은 대부분 거절·skip 경로라
H1(「성공한 외부 작용」)·H3(「rollback」)이 문자 그대로 맞지 않는다. **H1~H4 를 조용히 넓히는
대신 라벨을 신설했다.**

| 라벨 | 정의 |
| --- | --- |
| H1 | 성공한 외부 작용이 **실패로 보고**된다 |
| H2 | 내구 쓰기(`commit`) **뒤**의 후속 훅이 유실된다 |
| H3 | 내구 쓰기 **앞**이라 계측 예외가 DB 전이를 **rollback** 시킨다 |
| H4 | 안전 장치가 **통째로 건너뛰어진다** |
| **H5** *(신설)* | **확정된 4xx 도메인 거절이 HTTP 500 으로 오보고된다** |
| **H6** *(신설)* | **정상 종결(terminal skip · 정산 귀결)이 task 실패·재시도로 오분류되고 최종 기록 사유가 실제와 달라진다** |
| **H7** *(신설)* | **내구 쓰기 이전 단계에서 던져 아직 일어나지 않은 적재가 통째로 중단된다** (rollback 이 아니다) |

사이트별 4라벨(수리함 / 가드 없이 유지 / 판정 보류 / 영구 제외) + 메타 대조 2종
(**빠짐없음** — 25곳 전건이 정확히 하나로 / **발화 가능** — 각 H 를 일으킨 사이트가 최소 1개,
0개면 「공허」라고 적는다).

### 1.2 주입 방식

`monkeypatch` 로 **`.labels` 를 폭파**시킨다(`OSError("mmap allocation failed")`) +
**「stub 이 정확히 1회 호출됐다」를 함께 단언** + 사이트별 **비-계측 postcondition**.

★`.inc` 가 아니라 `.labels` 인 이유 — multiprocess 모드에서 **새 라벨 조합이 mmap 을 늘리는
시점이 `.labels()`** 다(BL-536 R2). `.inc` 만 폭파시키면 `.labels()` 를 안 감싼 반쪽 수리가
통과한다.

## §3. 판정 결과 — **수리함 23 · 판정 보류 2**, 「가드 없이 유지」 **0곳**

수리 전 주입 25곳이 **전건 red** 였고, 실패 원인은 예외 없이

### 3.1 반증 1 — 「`order_service.py` 10곳은 blast radius 0」

10곳 전부 `.inc()` **직후 도메인 예외를 raise** 한다. 계측이 던지면 그 도메인 예외가 **아예
발생하지 않는다**(10/10 실측). 9종 전부 `AppException`(4xx) 이므로 전역 핸들러가 4xx 로
직렬화하던 것이 **HTTP 500** 이 된다(**H5**).

그중 **6종은 호출자가 예외 타입으로 분기**한다 — `tasks/live_signal.py:3232`/`:3239`/`:3249`
가 `mark_failed` + `commit` 을, `:2793` 이 무재시도 종결을 한다. 타입이 바뀌면 그 분기가 통째로
빠진다(**H4**): 이벤트가 outbox 에 `pending` 으로 남고, 결정론적 거절이 **3회 재시도**되며,
소진 시 `max_retries_exhausted` 로 **사유까지 틀리게** 기록된다.

★**H4 는 두 단계 실측의 합성이다** — ① 주입 25건이 「도메인 예외 대신 OSError 가 탈출한다」를
재고, ② 신규 오라클 2건이 「호출자는 타입으로 갈린다」를 잰다. ②는 호출자의 성질이라 수리
뒤에도 참이라 **회귀 가드로 남겼다**(red→green 게이트가 아니라는 것을 파일에 적어 뒀다).

★부수 정정 — BL 표는 A10(`:341`)을 「발주 **전** 검증 거절 직후」라 적었지만 실제로는
`begin_nested()` + advisory lock **안**이다.

### 3.2 반증 2 — 「closed_pnl 은 `already_synced` 로 수렴」

수렴을 만드는 것은 `backfill_exchange_realized_pnl` 의 `realized_pnl_synced_at IS NULL`
조건이다(`order_repository.py:729`). 그런데

- **:1470 · :1474 · :1477 · :1498 · :1505 (5곳)** — 그 함수를 **한 번도 호출하지 않는** 종결
  skip 경로다. 적용될 대상 자체가 없다. 던지면 종결이 예외로 승격돼 `max_retries=4` 재시도(**H6**).
- **:1530(`already_synced`)** — 수렴이 아니라 **고정점 실패**다. 재시도해도 같은 줄에서 다시 던진다.
- **:1528** 하나만 논거대로다. 단 commit **뒤**라 확정된 손익 교체가 실패로 보고된다(**H1**).

★**「귀결은 거짓 알림 1건」도 반대였다.** `:1744`/`:1756` 은 `_alert_closed_pnl_unbackfilled`
**바로 앞**이다. 계측이 지속 실패하면 알림이 1건 더 나가는 게 아니라 **0건**이고 task 는 죽는다(**H2**).

### 3.3 백로그가 이름을 대지 않았던 8곳 — **6곳 유해 · 2곳 도달 불가**

`_sweep_closed_pnl_with_session` 6곳 + `refresh_closed_pnl_task` 2곳.

### 3.3a ★내 하네스가 프로덕션 계약을 깨서 「유해」를 만들어냈다 (codex G6 BLOCKING)

## §6. 회고

1. ★★★**산문 근거의 타율이 0 이다.** 이번에 반증된 두 문장은 각각 **10곳**과 **7곳**을
   가드에서 빼는 근거였다. 직전 회차의 4곳까지 합치면 「~라서 안전하다」로 뺀 **21곳 중 21곳**이
   주입에서 유해했다. 다음 회차는 **잔여 104곳도 산문으로 분류하지 말고 주입으로 시작**해라.
2. ★★★**백로그가 이름을 댄 범위가 문제의 범위가 아니었다.** 「closed_pnl 7곳」은 같은 파일·같은
   metric **15곳 중 7곳**이었고, 이름 없던 8곳이 오히려 더 나빴다(계정 루프 전체 중단 · 원장 유실).
   **census 정본을 먼저 읽고 백로그 문장을 대조 대상으로 삼은 것이 이 8곳을 살렸다.**
3. ★★**테스트가 결함을 못 잡는 이유가 「주입하지 않아서」였다.** `test_sweep_isolates_one_account_failure`
   는 계정 격리를 지키라고 있는 테스트인데, 그 격리를 깨는 실제 경로(`except` 첫 줄의 raw 계측)를
   못 잡았다 — provider 예외만 주입하기 때문이다. **불변식을 지키는 테스트가 있다는 사실이
   그 불변식이 지켜진다는 뜻이 아니다.**
4. ★★**주입 지점을 바꾸면 게이트의 폭이 바뀐다.** `.inc` 대신 `.labels` 를 폭파시킨 것은 옳았지만
   **그것만으로는 반쪽 수리를 못 잡는다**(M5). 「무엇을 주입하는가」와 「무엇을 보장하는가」는
   다른 질문이고, 후자는 가드 자체의 단위 테스트가 답해야 했다. 그 테스트가 없었다.
5. ★**라벨을 넓히는 대신 늘렸다.** H1 의 괄호 열거만 보면 이번 사이트들이 들어가는 것처럼
   보였지만, 그렇게 쓰면 H1 의 뜻이 회차마다 달라진다. H5·H6·H7 을 신설하고 **왜 신설했는지**를
   적었다. 대신 H3 은 두 회차 연속 공허다 — 그것도 적었다.
