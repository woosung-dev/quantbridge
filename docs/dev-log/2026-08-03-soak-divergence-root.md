## §2. 뿌리 — 계획기가 시뮬이 이미 잡은 진입을 버린다

코드가 스스로 적고 있었다 (`conditional_entry_planner.py:417-421`):

> "가격이 피벗을 이미 지나가면 **시뮬은 `low <= stop` 으로 즉시 체결로 보는데** 거래소는
> long RISE 는 retCode 110092, short FALL 은 110093 으로 **거부한다**."

시장가 전환 탈출구가 있는데 **대기 주문이 존재하기만 하면** 꺼졌다:

```python
if breached and (matching_actual or not allow_market_conversion):   # 수리 전
    to_cancel.extend(matching_actual); continue
```

배제는 **의도적**이었다. PR #493(`274dc645`) 커밋: _"전환은 resting 조건부가 없을 때만. 있으면
거래소가 이미 그 주문을 트리거했을 확률이 높아 취소+시장가는 이중 진입이 된다."_

★**그러나 이번 사고는 그 위험에 해당하지 않았다.**

| 축                   | 값                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------- |
| 사고 로그(10:56:39)  | `trigger_already_breached · direction=long · stop_price=62661.71 · reference_price=62700.0 · had_resting=true` |
| 대기 주문 `1adf0cab` | `trigger_price=62811.5` · `trigger_direction=1`(상승)                                                          |
| 발화 가능?           | 62811.5 **>** 62700 ⇒ **한 번도 닿은 적 없다**                                                                 |

피벗이 62811.5 → 62661.71 로 내려가 새 트리거가 현재가 **아래**라 stop 으로 못 걸었고, 계획기는
드롭 + 대기 주문 취소만 했다. 시뮬은 그 진입을 이미 잡았다 ⇒ 엔진 롱 `+0.030392388292696512` /
거래소 숏 `−0.03` ⇒ `direction` 발산 **2회 연속**(`live_signal.py:2566-2572`) ⇒ fail-closed.

**⇒ 술어가 「대기 주문이 있는가」를 묻는데, 물어야 할 것은 「그 대기 주문이 발화할 수
있었는가」였다.** 이것이 이번 수리의 전부다.

★**크기 `+0.0304` vs `0.03` 은 별건이다.** 시뮬의 미절삭 의도 수량 대 `qty_step` 절삭
(`190422.997 × 1% / 62654 ≈ 0.030392`). 상대차 1.3% 가 `_POSITION_SIZE_REL_TOL = 0.05` 아래라
`size` 로는 영영 안 뜨고 **부호가 뒤집힐 때만** 치명적이 된다. 이번 사망 원인이 아니라 손대지 않았다.

## §3. 사전등록 — 2단계로 나눠 각 변경의 근거를 따로 얻었다

수리 **전에** 변이를 먼저 찍었다. 사전등록 변이 판별력 0 이 **네 회차 연속**이었기 때문이다.

| 변이    | 케이스                                   | 수리 전 | 술어만 좁힌 뒤 | 최종  |
| ------- | ---------------------------------------- | ------- | -------------- | ----- |
| **M1**  | breached + resting **발화 불가**         | **RED** | green          | green |
| M2※     | breached + resting **발화 가능**         | green   | green          | green |
| M3      | 전환 off + resting 발화 불가             | green   | green          | green |
| M4      | 드롭 사유 진단 필드                      | RED     | green          | green |
| **M1b** | 굵은 눈금에서 시장가↔대기 stop 등가 붕괴 | RED     | **RED**        | green |

※ M2 = **기존 테스트 `test_breached_trigger_with_resting_cancels_and_does_not_convert` 를 한 글자도
안 고쳤다.** PR #493 의 보호가 안 깨졌다는 회귀 증거로 쓰려면 손대면 안 된다. 처음엔 여기에 단언을
하나 더 붙였다가 **「수리 전후 불변」이라는 대조 성질이 깨져서** 원복하고 진단 필드는 별도 변이(M4)로 뺐다.

★**M1b 의 red 를 두 번 읽었다.** 수리 전에도 red 였지만 그건 M1 과 **같은 원인**(전환과 대기 주문이
공존 불가)이라 아무 증거도 아니다. 술어만 먼저 넣고 다시 보니 **M1b 만 red 로 남았다** — `as_market`
이 등가 비교 축에 없어서, `price_tick=10` 이면 desired stop 100 과 resting stop 108 이 둘 다 100 으로
정규화돼 **아무것도 취소하지 않고 아무것도 등재하지 않는다.** 술어를 좁히기 전에는 **도달 불가**였던
구멍이고, 사전등록에 없던 것을 구현 중 발견했다. 한 번에 넣었으면 두 변경이 서로의 증거를 가렸다.

**★드롭 쪽은 손해보지 않는다.** 두 갈래 모두 `matching_actual` 을 취소하므로, 전환이 하류 가드
(미지 interval · 최근 전환 중복 `has_recent_market_converted_entry` · 돌파 해소 `breach_reverted` ·
`max_breach_pct`)에 걸려 무산되면 결과가 **기존 드롭과 같다.** 엄밀히 회귀 불가다.
