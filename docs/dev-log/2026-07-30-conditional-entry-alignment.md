## 1. 착수 preflight 가 전제 2건을 반증했다

플랜을 짜기 전 `AGENTS.md` §7.1/§7.4 대로 baseline 재측정을 돌렸고, `docs/status.md` 가 지정한 두 전제가 **둘 다 틀렸다**.

### 1.1 BL-544 — 원장은 사망 4분 36초 전에 이미 알고 있었다

앱 DB 를 직접 뒤져 실패한 세션 `1178787c` 의 원장을 재구성했다.

| 증거         | 값                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------- |
| 조건부 진입  | `cond:1785337500` buy stop @ **64166.7**, created **15:06:25**                               |
| 체결         | `state=filled` · `filled_quantity=0.029` · `filled_price=64166.9` · **`filled_at=15:10:00`** |
| 세션 사망    | **15:14:36** `gap_resync_position_mismatch`                                                  |
| 사망 시 엔진 | `position_size 0.0` · `open_trades []` · `_qb_position_epoch 14:56:00`                       |

두 가지가 따라 나왔다.

1. **worker/beat 는 멈춰 있었지만 `ws-stream` 은 살아서 체결을 원장에 찍었다.** 판정부(`live_signal.py:1679`)는 그 원장을 **조회하지 않았을 뿐**이다.
2. **BL-543 의 discard 가 먹은 게 아니다** — epoch 이 `14:56` 이라 15:06 진입은 범위 밖. 즉 **재생이 그 체결을 애초에 만들지 않았다.** 기전은 조건부 진입 trigger 가 tick 마다 재도출되는 것이고(실측 `64235.3 → 64166.7`), 공백 동안 reconciler 가 안 돌아 **거래소에는 엔진이 더는 원하지 않는 stop 이 남아 체결됐다.** 이 기전은 이번 soak 에서도 그대로 관측됐다(`64252.10 → 64195.20`).

### 1.2 ★"판정만 넓히기" 는 능동적으로 해롭다

BL 원문의 (b) 안을 코드로 따라가 보니 `exchange_only` 발산은 `live_signal.py:1765-1772` 에서 **counter 만 올리고 세션을 죽이지 않는다.** seed 없이 판정만 넓히면 **시끄러운 사망이 조용한 고아로 바뀐다.** → 사용자 결정 = (a)+(b) 동시.

### 1.3 BL-423 — 이미 어제 착지해 있었다

`include_inactive` 는 **BL-526(PR #496 @`9a80e3c2`, 2026-07-29)** 이 이미 넣었다. 상세 경로에 `is_active` 게이트는 **한 곳도 없었다**(`grep` 0 hit). BL 원문은 그 커밋 **이전** 상태를 서술한 것이었다. → 잔여 갭만 남기고 **BL-484 사유 컬럼**을 함께 묶는 것으로 사용자 결정.

> **교훈:** BL 본문은 **작성 시점의 스냅샷**이다. 하루 전 PR 이 전제를 바꿔 놓을 수 있다. 착수 preflight 가 이번에 그걸 두 번 잡았다.

## 2. 무엇을 만들었나

### BL-544 (워커 `bl544`, 커밋 2개)

- `OrderRepository.list_fills_since` — `_session_scope_where` **재사용**(스코프 SQL 번역은 계속 한 자리). `list_filled_realized_for_session` 은 `realized_pnl IS NOT NULL` 을 걸어 **진입을 구조적으로 못 본다** — 그게 이 버그의 조회측 원인이었다.
- `StrategyState.seed_positions_from_ledger` — `discard_state_before_epoch` 의 **대칭**, **멱등**(재생이 이미 열었으면 no-op).
- 판정을 `exchange_positions == [] and carried_flat` → **엔진↔거래소 순포지션 일치**로 일반화. `None`(REST 실패)·hedge 2-leg·미지 side 는 **계속 mismatch**.
- ★**seed 출처는 원장, 판정 대조는 거래소.** 거래소로 seed 하면 대조가 동어반복이 되어 가드가 통째로 사라진다. 음성 대조 테스트로 잠갔다.
- 신규 metric `qb_live_gap_ledger_seed_total{outcome}` + 구조화 로그 = **soak sentinel**.

★**codex G1 2회가 설계를 두 번 갈아치웠다.** 결정적인 것: **`filled_at` 은 거래소 체결시각이 아니라 우리 관측시각**(`websocket/reconciliation.py:223` 이 `datetime.now()`). 그래서 "체결 bar 에 seed" 를 철회하고 **마지막 bar 직전**으로 옮겼다 — 뒤에 재생할 bar 가 없어 "전략이 seed 를 닫았는데 gap 경로엔 `emit_from_bar_time` 이 없어 그 close 가 조용히 사라지는" 실패가 **구조적으로 불가능**해진다.

### BL-484 + BL-423 잔여 (워커 `bl423`, 커밋 2개)

- `deactivated_reason` 컬럼(nullable `String(64)`) + `SessionDeactivationReason` 9종 SSOT + `deactivate(..., reason)` **기본값 없는 필수 키워드**.
- **7개 종료 경로 전건 배선.** ★`live_signal.py` 는 다른 워커 소유라 import 를 못 넣어 리터럴을 썼고, 대신 **AST 테스트가 그 파일의 모든 `deactivate(...)` 호출을 훑어 미등재 사유를 차단**한다 — 변수 인자(`preflight_cat`)까지 대입 리터럴을 추적하고 **리터럴 아닌 대입이면 실패**시킨다. 내가 부과한 소유 경계 제약을 워커가 이렇게 풀었다.
- 코크핏 목록 쿼리 이중화 해소 → 부수로 **도달 불가였던 `PAUSED` 칩이 살아났다**(실브라우저 확인).
- ★**워커가 스스로 막은 결함:** `sessionItems.length` 를 quota 로 쓰면 **최근 종료 세션 5건만으로 신규 세션 생성이 잠긴다**(활성 ≤5). 소스 래칫으로 못 박았다.

## 3. 통합 후 적대 리뷰가 P1 을 냈다 — 게이트 통과는 리뷰를 면제하지 않는다

워커 게이트 전건 green · 통합 게이트 green · 실브라우저 PASS 이후에 codex 가 찾았다.

★**부분체결 뒤 `cancelled`/`rejected` 된 조건부 진입이 원장 조회에서 빠진다.** 코드 대조로 확정 — `transition_to_cancelled`/`_rejected` 는 `filled_quantity != 0` 이면 체결분을 **보존**하고 `conditional_entry_janitor.py:132-146` 이 거래소 probe 수량을 두 전이 모두에 넘긴다. 그런데 조회는 `state == filled` 만 봤다. **거래소에는 부분 포지션이 남는데 엔진은 flat 으로 seed → BL-544 가 고치려던 사망이 형제 케이스로 부활.**

이건 스코프 밖이 아니라 **동결 기준 ①("공백 창 안의 체결")의 미달**이라 판단해 `bl544` 에 재지시(R1)했다. `_session_scope_where(scope, *, states=(filled,))` 파라미터화로 기존 3 소비처를 깨지 않고 수리 + **실 DB repository 테스트 3건**(태스크 경계 테스트는 `list_fills_since` 를 mock 하므로 SQL 술어 자체를 못 잰다는 것을 워커가 스스로 지적했다).

**5% 허용치 P1 은 강등했다** — 그 값에는 실측 근거가 있다(엔진 float 누적 vs 거래소 step 양자화 = **측정된 3.45%**). 좁히면 seed 가 애초에 정렬되지 않아 BL-544 자체가 무효가 된다. → BL-545.

### ★★soak 이 증명하지 못한 것

**세 leg 모두 재생이 포지션을 스스로 재현해서 살았다.** `outcome="applied"`(seed **주입**)는 **한 번도 밟히지 않았다** — 그러려면 대기 stop 이 **공백 중에** 트리거돼야 하는데 28분 동안 일어나지 않았다(시장 의존이라 강제 불가).

즉 증거 수준이 **비대칭**이다:

| 기전                        | 증거                       |
| --------------------------- | -------------------------- |
| 판정 완화(엔진↔거래소 일치) | **실주행 실증** (3 leg)    |
| 원장 seed **주입**          | 단위테스트 + 표적 변이까지 |

원래 BL-544 실패가 정확히 seed 주입이 필요한 케이스였으므로 이 공백은 실질적이다 → **BL-553**. "생존했으니 전부 충족" 으로 쓰지 않는 것이 G9 의 존재 이유다.

부수 소득 — leg 3 는 **거래소 flat / 엔진 롱** 구도가 되어 **BL-543 의 realign 경로**까지 의도치 않게 실주행 검증됐다.

## 5. 이번 회차의 함정 (실측)

1. ★**`| tail` 로 파이프하면 exit code 도 가려지고 출력도 버퍼링된다.** 게이트 체인 첫 실행이 0바이트 로그로 죽었다 — 문서가 경고한 그 함정을 오케스트레이터가 밟았다. 파일로 직접 흘려야 한다.
2. ★**`final-gates.sh` 를 커밋 전에 돌리면 게이트를 skip 하고도 통과처럼 읽힌다** — 영역 판정이 `git diff BASE..HEAD`(커밋된 diff)라 미커밋 변경을 못 본다. 워커 `bl423` 이 자기 실행 중 발견했다 → **BL-549**.
3. ★**테스트 DB 가 stale 하면 `test_migrations.py` 5건이 깨진다 — 코드 결함이 아니다.** 워커가 예측했고 그대로 났다. 스키마를 비우고 `alembic upgrade head` 로 스탬프하면 6 passed. ★그리고 **DB 를 통째로 드롭만 하면 안 된다**(`alembic_version` 이 사라져 다른 방향으로 깨진다).
4. ★**커버리지 잡이 도는 중에 내가 그 DB 를 비워 측정을 오염시켰다.** 그 실행은 폐기하고 재실행했다 — 오염된 측정을 근거로 쓰지 않는 것이 판단 자체보다 중요하다.
5. ★**계측기가 오탐을 냈다.** 375px 프로브가 8건을 "넘침" 으로 보고했으나 **전부 오탐**이었다(세 표 모두 `div.table-wrap{overflow-x:auto}` 안). 스크롤 조상을 제외하고 다시 재니 실제 원인 0건, 결정적 판정은 `window.scrollTo` 후 `scrollX` 실측이었다. 그리고 인과 분리(상세 닫힘 0 / 열림 24 / parity 숨김 0)로 **우리가 안 만진 컴포넌트**임을 확정했다 → BL-548.
6. ★**`fleet-dispatch.sh` 가 프롬프트 미제출을 성공으로 보고한다.** 재지시 때 텍스트가 입력창에 붙기만 하고 제출되지 않았는데 스크립트는 `✓` 를 찍었고 상태표는 `idle/pending` 으로 정상 대기처럼 보였다. `herdr pane send-keys <pane> Enter` 로 풀었다 → **BL-552**.
7. ★**내가 재지시를 쓰면서 원 동결 기준 파일을 덮어썼다.** G9 대조 대상이 사라져 승인 플랜에서 복원했다. 다음부터 재지시는 `tasks/<worker>.r<N>.md` 로 분리한다. 그리고 복원본을 `tasks/` 에 두면 **분배 스크립트가 워커로 오인해 die** 하므로 `frozen/` 으로 옮겼다.
