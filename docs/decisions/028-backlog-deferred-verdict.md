# ADR-028: 원장 판정어 `DEFERRED` — 「조건이 아직 안 왔다」를 셈에서 가른다

> **상태:** 확정 (Accepted — 2026-08-10, 사용자 판정)
> **일자:** 2026-08-10
> **결정자:** woosung (기안: Claude)
> **관련:** [ADR-026](026-documentation-ssot.md) §1 SSOT 7축 · `scripts/bl-audit.sh` · `scripts/bl-trigger-sweep.sh`
> **출처:** 2026-08-10 bl-trigger-triage 실측 — ACTIVE 159건 전량 트리거 판정

---

## Context — ACTIVE 159 는 작업량이 아니라 셈하는 규칙이 만든 수였다

`bl-audit` 의 판정 어휘는 넷이었다 — `ACTIVE / PARTIAL / RESOLVED / UNKNOWN`.
이 넷 어디에도 **「트리거 조건이 아직 안 왔다」**를 적을 자리가 없다. 그래서 열린 항목은
조건이 왔든 안 왔든 **전부 ACTIVE** 로 떨어졌다.

실측이 그 구조를 드러냈다 (2026-08-10):

| 재는 것                                         | 값                 |
| ----------------------------------------------- | ------------------ |
| ACTIVE                                          | **159** / 전체 244 |
| 그중 `**Trigger:**` 줄을 가진 것                | **159/159**        |
| 트리거 문법 — 동승(「X 를 다음에 손댈 때」)     | **73**             |
| 트리거 문법 — 외생(승인·cutover·Beta·소크·관측) | **39**             |
| 트리거 문법 — 지금 도래                         | **4**              |

**정보는 이미 원장에 있었다.** 「지금 할 수 있는가」를 가릴 근거가 159/159 기재돼 있었고,
그걸 읽는 어휘가 없었을 뿐이다. 그 결과 ⓪ 다음 후보 표는 원장이 아니라 **회차마다 손으로**
후보를 얹고 취소선으로 지우는 방식으로 유지됐고, 12행 중 9행이 사문이었다.

★**이 축은 2026-08-09 status-triage-mass 와 다르다.** 그 회차는 「ACTIVE 를 다시 읽으면
이미 닫힌 것이 나올 것이다」를 쟀고 **기각**됐다(116건 전량 대조, r=5.17%). **원장은 부풀지
않았다 — 그냥 크다.** 본 ADR 이 재는 것은 「닫혔는가」가 아니라 **「조건이 왔는가」**다.

---

## Decision

### 1. 다섯 번째 판정어 `DEFERRED` 를 신설한다

상태줄 어휘 = `⏳ **대기 (트리거 미도래)**`. `verdict_of`(`scripts/bl-audit.sh`)가
`미도래|Deferred` 를 **ACTIVE 검사보다 먼저** 읽는다.

`bl-audit` 출력에서 ACTIVE 와 **따로** 세어지고, `active` 집계에 들어가지 않는다
(PARTIAL 과 같은 취급). ⇒ **ACTIVE 는 이제 「지금 단독으로 착수 가능한 것」만 가리킨다.**

### 2. 경계 — 외생과 **동승을 둘 다** 포함한다

미도래 = 다음 둘 중 하나.

- **외생 조건** — 우리 의지로 만들 수 없다. 사용자 승인·요청 / 실자금 cutover / Beta·프로덕션
  배포 / 소크 창(`soak-gate.sh` PASS) / 외부 관측 / 미해결 선행 BL
- **동승 조건** — 인접 작업을 열 때만 값이 난다. 「그 파일을 다음에 열 때」([BL-693]),
  「탑바 높이를 바꿀 때」([BL-686]), 「pine_v2 coverage 후속」([BL-385])

★**동승을 포함하는 것이 이 결정의 핵심이고, 사용자가 명시적으로 고른 것이다.**
근거 = 그것들은 **「단독 착수 시 값이 0」이라고 트리거 자신이 선언한 것**이다. 제외하면
ACTIVE 가 100 대에 머물러 「지금 할 수 있는 것만 남긴다」는 목적을 달성하지 못한다.

### 3. 3면 계약 — DEFERRED 는 **ACTIVE 와 같은 「미완」 쪽**이다

| 면               | DEFERRED 의 규칙                                 |
| ---------------- | ------------------------------------------------ |
| 섹션 `**상태:**` | `⏳ **대기 (트리거 미도래)**` (SSOT)             |
| 인덱스 표 행     | ✅ 또는 🟡 가 있으면 **불일치** (ACTIVE 와 동일) |
| roadmap 체크박스 | `[x]` 면 **불일치** (ACTIVE 와 동일)             |
| 우선순위 배치    | 변화 없음                                        |

★**인덱스 표에 새 마커(⏳)를 요구하지 않는다.** 요구하면 최대 77행을 함께 고쳐야 하고
**동기화 표면이 하나 더 는다.** 3면 계약의 강도는 그대로이고 편집량은 0행이다.

### 4. 판정에는 근거를 붙인다 — `**트리거 판정:**` 줄

각 섹션에 상태줄 **다음 줄**로 넣는다:

```
**트리거 판정:** 미도래 — 외생 조건(실자금 cutover). 우리 의지로 만들 수 없다 (2026-08-10 bl-trigger-triage)
```

★상태줄에 이어붙이지 않는다 — 상태줄 최대 실측 **966자**이고 `docs-audit` 상한이 1,000자다.
★그 줄에 ✅/🟡 를 쓰지 마라 — `bl-audit` 의 `is_marker` 가 물 수 있다.

### 5. 판정기는 `scripts/bl-trigger-sweep.sh` 다 — 손으로 세지 않는다

기계가 판정하는 것은 **세 축뿐**이다: 선행 BL(`bl-audit` 되읽기) · 소크(`--soak`) ·
트리거 자기선언(`즉시`·`이미 발화`). 나머지는 **버킷만** 주고 「판단 필요」로 내린다.

★**`--selftest` 를 전량 스윕보다 먼저 돌려라.** 양성 2 + 음성 4 를 가르지 못하면
전량 판정은 값이 0이다.

## Consequences

**좋아지는 것**

- ACTIVE **159 → 9**(신규 [BL-695] 포함). ⓪ 다음 후보 표가 **원장에서 파생**된다(`--list ACTIVE` 전량) —
  손으로 후보를 얹고 취소선으로 지우는 유지 방식이 끝난다
- 「무엇이 막는가」가 항목마다 한 줄로 적혀 있다. 종전에는 트리거 원문을 매번 다시 해석해야 했다

**나빠지는 것 / 감수한 것**

- 판정어가 5종이 됐다. `--list` · P별 내역 · crosscheck 세 곳이 함께 늘어난다
- **동승 판정은 우리가 고르는 계약이지 관측이 아니다.** 「지금 값이 0」이라는 판단이 바뀌면
  DEFERRED → ACTIVE 로 되돌려야 하고, 그걸 강제하는 것은 6-8주 재평가 규율뿐이다
- `bl-trigger-sweep.sh` 의 버킷 정규식은 **원장 문구에 결합**돼 있다. 문구가 바뀌면 드리프트하고
  이를 지키는 것은 `--selftest` 6건뿐이다 ⇒ [BL-695]

**하지 않은 것**

- backlog `## Deferred` H2 표(BL-070~075 등 8건, 섹션 없음)는 **그대로 뒀다.** 이제 같은 것을
  두 방식으로 말하게 됐다 ⇒ [BL-694] 로 등재만 하고 이 회차에서 통합하지 않는다
