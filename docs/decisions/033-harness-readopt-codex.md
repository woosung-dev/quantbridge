## Context — 이미 2회 돌리고 걷어낸 것을 다시 붙인다

[ADR-030](030-harness-pilot-verdict.md) 이 2026-08-13 에 이 프레임워크를 걷어냈다
(PR #623 `5a0e3304`, 27파일 / 3,711줄 / 230.7 KB). 파일럿은 2회였다:

| 회차 | BL / PR            | 실행기                                                  |
| ---- | ------------------ | ------------------------------------------------------- |
| A    | [BL-708] / PR #615 | `claude -p --dangerously-skip-permissions` (원본 as-is) |
| B    | [BL-709] / PR #616 | **codex** + 러너가 exit code 로 AC 판정                 |

★**이번 재도입 구성은 B회차와 같은 실행기 축이다.** ADR-030 이 남긴 재개 조건 3항 중 ⑴ 이
그것과 정면 충돌한다:

> ⑴ 실행기를 `claude` 로 되돌려 **축을 분리**하고 ⑵ **비결정적 AC 를 혼입**해야 원래 질문을 물을 수 있다.
> ⑶ 위험 7번(`TimeoutExpired`)과 9번(exit code 미판독)은 as-is 로 두지 마라.

## Decision

**⑴ 을 뒤집는다. ⑵⑶ 은 이행하지 않는다.** 실행기는 `codex exec`, 권한은 bypass, 나머지는 as-is.

**무엇을 사는가** — 무인 순차 실행 능력. ADR-030 이 「잃는 것」에 **실재하는 손실**로 적어 둔 그것이다.
2회차 모두 사람 개입 0으로 BL 하나를 끝까지 닫았고(코드 + 원장 3면 + ⓪ 표), 리뷰에서 수정할 것이 없었다.

**무엇을 안 사는가** — ADR-030 이 재려던 질문(**「자기채점이 뚫리는가」**)에 대한 답. 그것은
⑵ 없이는 안 재진다. 이 ADR 은 그 질문을 **묻지 않기로** 한 것이지 답한 것이 아니다.

### 운용 안전장치 2개 (코드가 아니라 규약이다)

1. **워크트리에서만 돌린다** — bypass 의 블라스트 반경을 브랜치 하나로 묶는다.
2. **`--push` 영구 금지** — Golden Rule. **A/B 파일럿이 원격 유출을 면한 것이 이것 하나 덕이었다**
   (위험 3·7의 최악 갈래를 닫는 유일한 장치).

### 회수 조건

위험 7(`TimeoutExpired`)이 **회차를 다시 죽이면** 그 자리에서 러너를 뗀다. 같은 사고의 2회 재현은
「as-is 로 둘 수 있다」의 반증이고, 그때는 ⑶ 을 이행하거나 ADR-030 으로 되돌아간다.

## 우리 수정 6곳 — 「as-is」의 실제 경계

★**「as-is 니까 한 줄도 안 건드린다」는 성립하지 않았다.** 파일럿은 「수정은 경로 1줄뿐」이라고
적었는데, [ADR-029] 재배치 후 레이아웃에서 **그 1줄이 6곳**이다. 그중 셋(②-3·②-4·②-5)은 안 고치면
**예외 없이 조용히** 틀린 답을 낸다.

★★**②-1 의 파생을 나는 두 번 놓쳤다.** ②-4 는 스스로 찾았고 거기서 「경로 전수 확인 끝」이라고
믿었는데, ②-5 가 남아 있었고 **codex 적대 리뷰가 잡았다.** 경로 상수 하나를 옮기면 그것을 쓰는
자리가 코드·문자열·프롬프트 세 층에 흩어진다 — grep 한 번으로 끝났다고 믿지 마라.

| #   | 위치               | 무엇                                                                                           | 안 고치면                                                                                                                                                                |
| --- | ------------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ①   | `_invoke_claude`   | argv 를 `codex exec --dangerously-bypass-approvals-and-sandbox -C <root>` + `stdin=DEVNULL` 로 | ★`-p` 를 그대로 옮기면 codex 에서 **`--profile`** 이다. ★`stdin` 미지정이면 codex 가 **무한 대기**한다(`generator-evaluator-pipeline.md` §7.1 — 워커 2기 52분·38분 소실) |

## ★스모크 1회 실측 (2026-08-15, `.harness/phases/smoke/`) — 발견 2건

1-step phase(`guardrail-proof`)를 돌렸다. 코드를 안 고치고 **주입된 규칙만으로** 5문항에 답하게 해
가드레일이 실제로 세션에 도달했는지를 재는 것이 목적이다. 42초 완주(11:05:16 → 11:05:58), rc=0.

`PROOF.md` 5문항 **전건 정답** — `uv` / `pnpm` / 「`make up` 아니오, 컨테이너·앱 DB 1벌 공유」 /
Golden Rules **5개** / 4축 문서 제목 4개. 파일을 열지 말라고 금지했으므로 이 답의 출처는
**프리앰블 주입분뿐**이다. ⇒ ②-2·②-3 이 end-to-end 로 작동한다.

### ★발견 A — 1-step 인데 커밋이 **4개** 났다

| 커밋                                               | 주체                | 내용                                          |
| -------------------------------------------------- | ------------------- | --------------------------------------------- |
| `8d983677` `feat(smoke): step 0 — guardrail-proof` | ★**codex 자신**     | `PROOF.md` + **`index.json`**                 |
| `1b257b11` `feat(smoke): step 0 — guardrail-proof` | 러너 `_commit_step` | `step0.md` (남아 있던 것이 입력 파일뿐이었다) |
| `7347d0bf` `chore(smoke): step 0 output`           | 러너                | `index.json` (`completed_at`)                 |
| `d0e197c7` `chore(smoke): mark phase completed`    | 러너 `_finalize`    | `index.json`                                  |

원인 = `_build_preamble` 규칙 6 이 세션에게 **「모든 변경사항을 커밋하라」**고 지시한다.
ADR-030 이 잰 「step 당 2커밋」은 **과소평가**였다 — **같은 메시지의 `feat` 이 두 번** 난다.

### ★발견 B — 그래서 ②-4 로 고친 2단 커밋 분리가 **실물에서 발화하지 않는다**

세션이 `index.json` 을 자기 `feat` 커밋에 이미 넣어 버리므로, 러너가 `git reset HEAD -- <index>` 를
할 때 **되돌릴 것이 남아 있지 않다.** 즉 상류 설계에 모순이 있다 — **프리앰블 규칙 6**(세션이 커밋)과
**`_commit_step` 의 2단 분리**(러너가 메타데이터를 떼어낸다)가 같은 것을 두고 싸운다.

⇒ ②-4 수리 자체는 옳다(경로가 틀리면 `git reset` 이 조용히 실패한다). 다만 **그것이 지키려던 성질은
프리앰블이 이미 깨고 있었다.** 단위 테스트는 초록이고 실물은 무의미하다 — 「테스트가 덮었다」와
「실행 경로에서 작동한다」는 다른 명제라는 또 하나의 사례다.

### 범위 이탈 — 이번엔 0건

`git diff --stat 3edeea7e..HEAD` = smoke 3파일 72줄뿐. `final-gates` 미실행, 코드 파일 0줄.
★**1회 관측을 「codex 는 이제 범위를 지킨다」로 읽지 마라** — ADR-030 §④ 의 2/2 위반은 그대로 유효하고,
이번 step 파일에는 **금지사항 5줄이 명시**돼 있었다. 잰 것은 「명시하면 지켰다」까지다.

### 산출물 부피

`step0-output.json` **79,030 B**. ADR-030 의 556KB~1.29MB/step 보다 훨씬 작지만 그건 작업이
사소했기 때문이다. `.gitignore` 가 먹어 **커밋 0건** — 의도대로다.

  산출물(gitignore 로 추적은 막았다) · 자기채점 · 위험 7종.
