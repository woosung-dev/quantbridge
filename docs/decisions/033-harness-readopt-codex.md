## Context — 이미 2회 돌리고 걷어낸 것을 다시 붙인다

[ADR-030](030-harness-pilot-verdict.md) 이 2026-08-13 에 이 프레임워크를 걷어냈다
(PR #623 `5a0e3304`, 27파일 / 3,711줄 / 230.7 KB). 파일럿은 2회였다:

| 회차 | BL / PR            | 실행기                                                  |
| ---- | ------------------ | ------------------------------------------------------- |
| A    | [BL-708] / PR #615 | `claude -p --dangerously-skip-permissions` (원본 as-is) |
| B    | [BL-709] / PR #616 | **codex** + 러너가 exit code 로 AC 판정                 |

★**이번 재도입 구성은 B회차와 같은 실행기 축이다.** ADR-030 이 남긴 재개 조건 3항 중 ⑴ 이
그것과 정면 충돌한다:

> ⑴ 실행기를 `claude` 로 되돌려 **축을 분리**하고 ⑵ **비결정적 AC 를 혼입**해야 원래 질문을 물을 수 있다.
> ⑶ 위험 7번(`TimeoutExpired`)과 9번(exit code 미판독)은 as-is 로 두지 마라.

## Decision

**⑴ 을 뒤집는다. ⑵⑶ 은 이행하지 않는다.** 실행기는 `codex exec`, 권한은 bypass, 나머지는 as-is.

**무엇을 사는가** — 무인 순차 실행 능력. ADR-030 이 「잃는 것」에 **실재하는 손실**로 적어 둔 그것이다.
2회차 모두 사람 개입 0으로 BL 하나를 끝까지 닫았고(코드 + 원장 3면 + ⓪ 표), 리뷰에서 수정할 것이 없었다.

**무엇을 안 사는가** — ADR-030 이 재려던 질문(**「자기채점이 뚫리는가」**)에 대한 답. 그것은
⑵ 없이는 안 재진다. 이 ADR 은 그 질문을 **묻지 않기로** 한 것이지 답한 것이 아니다.

### ★받아들이는 위험 7종 — 「몰랐다」가 성립하지 않게 여기 박아 둔다

전부 ADR-030 실측치다. 전문 = `.harness/README.md` §4 (원본 11건 표).

| #     | 위험                                                                         | 실측                                                                                                                                                        |
| ----- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7     | `subprocess.run(timeout=1800)` 이 **`TimeoutExpired` 를 안 잡는다**          | ★**B회차를 죽였다.** 남은 트리 = **AC 0건 실행 + `completed` 커밋**. 최악 갈래는 재실행 — 죽어도 `completed` 가 파일에 남아 다음 run 이 그 step 을 건너뛴다 |
| 9     | non-zero exit code 가 완료를 못 막는다 (`exitCode` 를 아무도 안 읽는다)      | fail-open                                                                                                                                                   |
| 1·2·3 | clean-tree 검사 0건 · 실패 경로에서도 커밋 · `_finalize` 가 커밋 실패를 무시 | 전건 P1                                                                                                                                                     |
| 4     | 권한 bypass 를 쓰면서 **워크트리를 강제하지 않는다**                         | 코드가 메인 실행을 막지 않는다                                                                                                                              |
| 11    | AC 가 **세션이 변조했을 수도 있는 대상**을 실행한다                          | 이번 판에는 `ac` 필드 자체가 없다(순수 as-is)                                                                                                               |
| —     | 권한 bypass 가 `.claude/settings.json` **deny 10종** 우회                    | `rm -rf*`·`git reset --hard*`·`git push --force*`·`docker volume rm*`·`sudo*` …                                                                             |
| —     | codex 범위 이탈                                                              | `claude` **6/6** 준수 vs `codex` **2/2** 게이트에 손댐 · 1회는 66분 33초                                                                                    |
| —     | 커밋 노이즈 · 산출물 부피                                                    | step 당 2커밋(**PR 중앙값의 5배**) · **556KB~1.29MB/step**                                                                                                  |

### 운용 안전장치 2개 (코드가 아니라 규약이다)

1. **워크트리에서만 돌린다** — bypass 의 블라스트 반경을 브랜치 하나로 묶는다.
2. **`--push` 영구 금지** — Golden Rule. **A/B 파일럿이 원격 유출을 면한 것이 이것 하나 덕이었다**
   (위험 3·7의 최악 갈래를 닫는 유일한 장치).

### 회수 조건

위험 7(`TimeoutExpired`)이 **회차를 다시 죽이면** 그 자리에서 러너를 뗀다. 같은 사고의 2회 재현은
「as-is 로 둘 수 있다」의 반증이고, 그때는 ⑶ 을 이행하거나 ADR-030 으로 되돌아간다.

## 소유 방식 — 인라인 포크 → **어댑터** (2026-08-15 전환)

★**상류는 라이브러리가 아니라 「clone 해서 시작하는 스타터 템플릿」이다.** `CLAUDE.md` 가
`{프로젝트명}`·`{프레임워크}` 빈칸이고 `docs/` 는 PRD·ARCHITECTURE·ADR·UI_GUIDE 골격이다.
그래서 기존 레포에 **파일 2개만 벤더링하는 우리 사용법은 저자가 의도한 것이 아니고**, 그 결과
전제가 9곳에서 어긋난다(아래 §꼬임).

**초판(인라인 포크)** — 상류 소스에 6곳을 직접 박았다. 그 6곳조차 파일럿이 적어 둔 「경로 1줄」이
아니었고, ★**②-1 의 파생을 두 번 놓쳤다** — ②-4 는 스스로 찾고 「경로 전수 확인 끝」이라 믿었는데
②-5 가 남아 **codex 적대 리뷰가 잡았다**(F1, P1). 경로 상수 하나를 옮기면 그것을 쓰는 자리가
**코드 · 문자열 · 프롬프트** 세 층에 흩어진다 — grep 한 번으로 끝났다고 믿지 마라.

**현행(어댑터)** — `tools/vendor/harness/execute.py` 를 **상류 `da676bc6` 바이트 그대로** 두고,
`tools/scripts/qb_harness.py` 가 `StepExecutor` 를 상속해 **차이 전량을 한 파일에** 모은다.
sha256 은 `tools/scripts/harness-test.sh`(11번째 게이트 하네스)가 고정한다.

★**전환의 실질은 정리정돈이 아니다.** 인라인 포크가 **구조적으로 못 막던 3건**을 어댑터는 막는다:

| 브랜치           | `feat-{task}` 생성·전환                                                 | 그대로 — **스모크가 실제로 `feat-smoke` 로 이탈** | `_checkout_branch` no-op                                        |

## ★스모크 실측 — 인라인 포크 판 → 어댑터 판 (2026-08-15, `.harness/phases/smoke/`)

같은 1-step phase(`guardrail-proof`)를 두 판으로 돌렸다. 코드를 안 고치고 **주입된 규칙만으로**
5문항에 답하게 해 가드레일이 실제로 세션에 도달했는지를 재는 것이 목적이다.

|           | 인라인 포크 판            | **어댑터 판**                                                                          |
| --------- | ------------------------- | -------------------------------------------------------------------------------------- |
| 벽시계    | 42초                      | 69초 (고정 검사 포함)                                                                  |
| 커밋      | **4개**                   | **3개**                                                                                |
| 브랜치    | ★`feat-smoke` 로 **이탈** | `worktree-feat+harnes01` **유지**                                                      |
| 고정 검사 | 없음                      | `FE typecheck rc=0` · `BE ruff rc=0`                                                   |

두 판 모두 `PROOF.md` **5문항 전건 정답** — `uv` / `pnpm` / 「`make up` 아니오, 컨테이너·앱 DB 1벌
공유」 / Golden Rules **5개** / 4축 문서 제목 4개. 파일 열기를 금지했으므로 출처는 **프리앰블 주입분뿐**이다.

### ★자기정정 2건 — 인라인 판 스모크의 진단이 틀렸다

**정정 ① — 「커밋 4개는 프리앰블 규칙 6 탓」이 부정확했다.**

```
8d983677 feat (codex 세션)   PROOF.md + index.json      ← 상류 설계대로
1b257b11 feat (러너)          step0.md                   ← ★내가 step 파일을 커밋 안 하고 돌렸다
7347d0bf chore (러너)         index.json completed_at    ← 상류 설계대로
d0e197c7 chore (finalize)     index.json                 ← 상류 설계대로
```

**상류 설계는 step 당 2커밋**(세션 feat + 러너 chore) + finalize 1 = **3개**다. 4번째는 **내 운용
실수**(dirty tree)였고, 그것을 아무도 안 막은 이유가 as-is 위험 #1(clean-tree 검사 0건)이다.
어댑터 판을 **클린 트리에서** 돌리자 정확히 **3개**가 나왔다.

**정정 ② — 「2단 커밋 분리가 실물에서 발화하지 않는다 = 상류 설계의 모순」은 과했다.**

`_commit_step` 의 feat 커밋은 **세션이 커밋하지 않았을 때의 폴백**이다. 세션이 코드를 커밋하면
러너의 chore 는 그 뒤에 자기가 추가한 `completed_at` 만 담는다 — **모순이 아니라 정상 동작**이다.
⇒ ②-4(reset 경로) 수리 자체는 여전히 옳다(경로가 틀리면 `git reset` 이 조용히 실패한다). 틀린 것은
그것을 「상류 모순」으로 부른 내 서술이다.

★두 정정 다 **같은 병**이다 — 한 번의 관측을 설계 결함으로 승격시켰고, 그 관측에 **내 운용 변수가
섞여 있었다.** 「클린 트리에서 다시 재라」가 그것을 갈랐다.

### ★어댑터가 되찾은 것 — 저자 설계는 4층인데 우리는 1층만 가져왔었다

상류 레포 12파일 중 우리가 가져온 것은 **2개**였다.

| 층          | 상류                                                      | 하는 일                     | 인라인 판 | 어댑터 판                     |
| ----------- | --------------------------------------------------------- | --------------------------- | --------- | ----------------------------- |
| ① 엔진      | `scripts/execute.py`                                      | 순차 실행·재시도·상태       | ✅        | ✅ (pristine 벤더)            |
| ② 저작 규약 | `.claude/commands/harness.md`                             | A탐색→…→E실행 슬래시 커맨드 | ❌        | ✅ **G1/G2 분리에 맞춰 개작** |
| ③ 검증 강제 | `.claude/settings.json` Stop 훅 = `lint && build && test` | 세션 자기채점의 뒷받침      | ❌        | ✅ `STEP_CHECKS`              |
| ④ 리뷰      | `.claude/commands/review.md`                              | 5축 체크리스트              | ❌        | — (우리 G6 codex 리뷰가 대체) |

★★**③이 가장 조용한 손실이었다.** 상류에서 자기채점이 버틴 이유는 **Stop 훅이 매 세션 끝에
lint+build+test 를 강제**했기 때문이다. 실행기를 codex 로 바꾸는 순간 그 층이 사라지는데
(codex 는 `.claude/settings.json` 을 읽지 않는다) 우리는 **그것을 어디에도 안 적었다** —
즉 **상류보다 약한 상태**로 돌고 있었다. 어댑터의 `STEP_CHECKS` 가 그 자리를 메운다.
그리고 그것이 **러너가 세션 자기신고를 뒤집을 수 있는 유일한 지점**이다.

### 범위 이탈 — 두 판 모두 0건

`git diff --stat` = smoke 파일뿐. `final-gates` 미실행, 코드 0줄.
★**1회 관측을 「codex 는 이제 범위를 지킨다」로 읽지 마라** — ADR-030 §④ 의 2/2 위반은 유효하고,
이 step 파일에는 금지사항 5줄이 명시돼 있었다. 잰 것은 **「명시하면 지켰다」**까지다.
