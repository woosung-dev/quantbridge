## 3. 표본 게이트 — 상수를 버리고 **필요 N 을 읽기 시점에 유도**한다

임계 20 은 폐기한다. 데이터를 본 뒤 고른 숫자였고, 실제로 계산해보니 **그 숫자는 비결론을 통과시킨다.**

★**첫 유도는 평가자(나)가 틀렸다.** `mean(gross)` 와 `mean(fee)` 를 두 독립 표본처럼 놓고 간격을 쟀는데, **둘은 같은 leg 에서 나오는 짝지어진 값**이다. 올바른 통계량은 차이 자체 — 즉 leg 당 **net** 한 표본이다(`net = gross − fee`). "엣지가 비용을 넘는가" 는 정확히 "**mean(net) > 0 인가**" 이다.

```
leg 당 net (실측 27 leg): 평균 -1.0238, SD 4.0943
SE = 4.0943 / sqrt(27) = 0.7880
t  = |-1.0238| / 0.7880 = 1.299   ->  |t| < 2, 0 을 기각 못 한다
2 SE 분리에 필요한 N = (2 x 4.0943 / 1.0238)^2 = 64.0  ->  64
```

**결론은 같은 64 지만 근거가 다르다** — SD(net) ≈ SD(gross) 라 수치가 우연히 일치했을 뿐이다. 잘못된 유도로 맞는 답을 얻는 것은 다음 데이터에서 틀린다.

**규칙:**

- 상수는 **신뢰 배수 하나뿐** — `PARITY_SE_MULTIPLIER = 2` (관례. 데이터에서 유도하지 않는다).
- **필요 N 은 표본 자신에서 매번 유도**한다: `required_n = ceil((k * sd(net) / |mean(net)|)^2)`.
- `matched_legs >= required_n` 일 때만 전략 성능 비율(엣지율·비용/엣지 배수·승률·leg 당 평균)을 낸다.
- 미달이면 값 대신 **현재 N 과 필요 N 을 함께** 낸다. "판정 불가" 가 아니라 **"얼마나 더 모아야 하는지"** 를 말한다.
- `mean(net) == 0` 이거나 `sd(net) == 0` 이거나 `N < 2` 면 `required_n` 은 `None` 이고 **그 경우도 차단**이다(조용한 통과 금지).

★**현재 실데이터는 이 게이트에 걸린다** (27 < 64). 그게 정직한 결과다 — 화면은 "비용이 엣지의 2.66배" 라고 **말하지 않는다.** 합계는 보여주되 결론은 표본이 살 때까지 유보한다.

**항상 노출** — 합계(기대 gross / 체결 gross / 확정 net / 수수료), 건수, 왕복 notional, 실효 수수료율. 분자·분모가 둘 다 실측 합계라 표본에 흔들리지 않는 기계적 성질이다.

### 여기서 나온 신규 발견 2건

1. ★**세션 창 밖 확정 청산 4건(net -0.5463)이 어느 표면에도 안 잡힌다.** `SessionScope` 의 반열림 창이 세션 종료 후 늦은 체결을 어디에도 넣지 않는다(`order_repository.py:37-39` 이 수용한 트레이드오프). 이 스프린트에서 스코프를 바꾸지 않되 **크기를 알았으니 BL 로 등재**한다.

## 3.8 W1 에서 평가자 스펙 결함 1건 (E1) — 워터폴이 안 닫혔다

구현 후 실행으로 재현했다. codex 구현은 스펙대로였고 **스펙이 틀렸다.**

```
관측 2건: (기대 10, net -3, gross 12, notional 1000) + (기대 4, net -1, gross None)
expected_gross = 14   actual_net = -4
execution_gap  =  2   cost = -15
14 + 2 + (-15) = 1  !=  -4      <- 막대가 5 만큼 안 닫힌다
```

원인 — 합계는 **전 관측**인데 격차·비용은 **분해 가능분만**이라 두 집합이 다르다. 분해 불가 관측이 하나라도 있으면 화면 워터폴이 어긋난다. 0 으로 메우면 비용 없는 주문처럼 보이고, 관측을 빼면 총 실적이 줄어든다.

**처분** — `decomposable_expected_gross` / `decomposable_actual_net` 를 노출해 **워터폴은 분해 가능 부분집합 위에서만** 그린다. 전 관측 합은 세션 총계용으로 유지한다. 변이 **M19** 로 고정.

> ★이 결함은 게이트가 전부 green 인 상태(10 tests · ruff · mypy 210)에서 나왔다. **테스트 통과는 스펙이 옳다는 증거가 아니다.**

| **E** (기대)         | 스코프 내 `action='close'` 이벤트 전체                                                               | 72   |
| **A** (실적)         | 스코프 내 **확정**(`realized_pnl_synced_at IS NOT NULL`) 주문 전체 = `/state.confirmed_realized_pnl` | 27   |
| **M** (매칭) = E ∩ A | close 이벤트가 확정 주문에 이어진 것                                                                 | 21   |

- **4층 워터폴(기대 gross → 체결 격차 → 비용 → 실적 net)은 오직 M 위에서만 계산한다.**
- `E \ M` = **51** (`expected_only`: dispatch failed 16 + rejected 35) — 엔진이 청산했다고 봤으나 확정되지 않았다.
- `A \ M` = **6** (`actual_only`) — 확정 청산인데 대응 close 이벤트가 없다.
- **세션 총 실적은 A 전체**(`/state` 와 같은 숫자)이고 **워터폴 합은 M 뿐**이다. 두 숫자가 다른 것이 정상이며, **화면은 그 차이를 설명해야 한다.**
- `coverage = |M| / |E ∪ A|` = 21 / 78 = **26.9%**. 이 값을 응답과 화면 양쪽에 싣는다.

## 4. 구조 제약 (구현이 반드시 지킬 것)

1. **분해는 매칭 leg 에만 적용한다.** `expected_only` / `actual_only` / `unrecorded` 금액을 `execution_gap` 에 흘려보내지 않는다. 그 순간 **우리 조인의 결함이 전략의 실행 격차로 렌더된다.**
2. **`coverage` 는 선택 필드가 아니다.** `matched_legs / total_close_events` 를 응답과 화면에 모두 싣는다. 현재 실측 21/72 = **29%** 다.
3. **귀속 술어로 `classification` 을 쓰지 마라.** `ExitClassification`(`models.py:679-688`)은 7 값이고 `bracket_tp`·`bracket_sl`·`trailing`·`liquidation` **도 우리 청산**이다. 귀속은 `matched_order_id` / `attributed_strategy_id` + `attribution_confidence` 가 답한다. `inferred` 는 `exit_attribution.py:110-113` 이 "검정력 없음" 으로 봉인했으므로 **별도 라벨로 격리**한다.
4. **심볼 공간 변환은 한 자리에서만.** `ExchangeExit.symbol` 은 거래소 원문(`BTCUSDT`), `SessionScope.symbol` 은 canonical(`BTC/USDT`). 순진한 동등 비교는 **항상 0행**을 반환해 버킷이 영원히 비어 보인다(BL-464 가 같은 이유로 죽었다).
5. **`SessionScope` 는 주문 축의 정의다 — event 축의 정의가 아니다.** (C7 정정)
   - **주문 축** — `order_repository.py:20-99` 의 `SessionScope` + `_session_scope_where` 를 **재구현 없이 그대로** 쓴다. 전략 누적은 `Sequence[SessionScope]` union.
   - **event 축** — `LiveSignalEvent` 에는 전략·계정·심볼 열이 없다. `session_id` **FK 직접 필터**가 스코프이고, 전략 누적은 세션 id 목록이다. 여기에 `SessionScope` 를 억지로 끼우면 **분모 72 와 failed/rejected 버킷이 통째로 탈락**한다.
   - 두 축이 다르다는 사실 자체를 코드 주석과 테스트로 고정한다.
     > **분기 사유** — 검토자는 쿼리를 `OrderRepository` 에 두라고 했다. 그 파일은 이미 700줄 이상이라 신규 리포지토리를 두되, **스코프 술어를 재구현하지 않고 `_session_scope_where` 를 그대로 import 해 쓰는 것**으로 지적의 실질(번역 이중화 금지)을 만족시킨다.
6. **`assumption` 블록 라벨은 `house_default`** 다. `run_live` 는 비용 인자를 **아예 넘기지 않고**(`event_loop.py:383-395`) 비용모델은 `v2_adapter` 에만 있다 — 즉 "run_live 가 이 기본값을 쓴다" 는 명제는 거짓이다. 화면 문구는 **"귀하의 백테스트 설정과 다를 수 있음"** 을 동반하고, TP(maker) leg 는 `maker_fee` + 슬리피지 면제라 왕복 0.3% 가 과대계상임을 명시한다.
7. **레이어 규칙** — `.ai/stacks/fastapi/backend.md` §3. Router 는 HTTP 전용, service 가 파생을 소유, repository 만 `AsyncSession`. 기존 `/state`(`router.py:487-570`)가 이 규칙을 어기고 있으나 **그 지역 선례를 복제하지 않는다.** `/state` 자체는 이번 스코프에서 손대지 않는다.
8. **신규 엔드포인트** — `/state` 는 활성 세션 5초 폴링 + 세션당 팬아웃(최대 5)이다. 3테이블 조인을 거기 얹지 않는다. 신규 경로는 폴링하지 않는다.

### 최종 구조 (§4.9 ~ §4.13)

9. ★★**분석 단위는 leg 가 아니라 `Order` 다.** (D3)
   백필이 `(account, exchange_order_id)` 합계 **하나**를 `Order.realized_pnl` 에 쓰므로 net 은 구조적으로 주문 단위다. gross 만 leg 단위로 두면 배분 근거 없는 숫자가 나온다. 따라서 **주문 하나 = 관측 하나**로 고정하고, 그 주문의 원장 행들을 접어 gross 를 만든다.

10. ★★**`actual_net` = `Order.realized_pnl` **단, `realized_pnl_synced_at IS NOT NULL` 인 것만.\*\* (D4)
    - **이 필터는 선택이 아니다.** 미동기 값은 엔진 추정치이고 그것은 `expected_gross` 와 **같은 숫자**다. 필터를 빼면 격차가 항상 0 인 동어반복 화면이 된다.
    - 일치시킬 대상은 `/state` 의 `total_realized_pnl` 이 **아니라** `confirmed_realized_pnl` 이다(`router.py:531` 이 confirmed/estimated 를 나눠 이미 노출한다). **이 항등식을 테스트로 고정한다.**
    - 시간축도 `filled_at` 하나로 통일되어 거래소 `exchange_created_at` 축은 집계에 들어오지 않는다.

11. **귀속 복구는 텍스트 동등으로 한다 — 캐스트 금지.** (D2)
    `orders.id::text = exchange_exits.order_link_id` 로 잇는다. `order_link_id::uuid` 는 malformed 값 **한 행이 응답 전체를 실패**시킨다(컬럼은 임의 `String(120)`).
    - 적재 경로(`on_conflict_do_nothing`)가 귀속을 영원히 안 고치는 것은 이 스프린트에서 고치지 않는다(스코프 밖). **읽을 때** 복구한다.
    - ★그래도 안 살아나는 행이 실재한다 — `ours/none` 3행은 `order_link_id` 가 어느 주문으로도 해석되지 않는다(실측 `link_resolves = 0`). **`unattributed` 버킷**으로 명시하고 어떤 합계에도 넣지 않는다.

12. ★★**식별이 모호하면 분해하지 않는다 (fail-closed).** (D1)
    `exchange_created_at` 은 안정 식별자가 아니다 — `trading.py:1723` 이 `createdTime` 결측 시 `updatedTime` 을 대입하므로 같은 청산의 갱신본이 **다른 파티션**에 떨어질 수 있다. 그래서 접는 규칙을 정교하게 만드는 대신 **의심스러우면 포기**한다:
    - 한 주문의 원장 행이 계정 스코프 적용 후에도 **1행이 아니면** 그 주문은 `decomposable = false`.
    - 평가 필드(`closed_size`·`avg_entry_price`·`avg_exit_price`) 중 하나라도 NULL 이면 `decomposable = false`.
    - 원장 행이 아예 없어도 `decomposable = false`.
    - `decomposable=false` 인 주문은 **net 은 세고 gross·수수료·notional 은 안 센다.** `undecomposed` 건수와 금액을 응답·화면에 낸다.
    - ★**0 으로 채우거나 행을 빼는 것이 곧 화면 왜곡이다.** 수수료율 분모에서 조용히 빠지면 비용이 낙관 편향된다.
    - 실측: 현재 (계정 스코프 후) 주문당 원장 1행 · NULL 평가 필드 0건 → 오늘 데이터의 `undecomposed` 는 **0** 이다. 정확도를 잃지 않으면서 이중계상 위험만 없앤다.

13. **`actual_only` 는 건수가 아니라 금액도 갖는다.** (D5)
    거래소 네이티브 브래킷 청산은 대응 local reduce-only `Order` 가 없을 수 있고(백필 대상이 `reduce_only=True` 로컬 주문뿐), 그러면 §4.10 의 net 에 **구조적으로 안 잡힌다**. 그 금액을 `actual_only.net` 으로 **따로 표시**하고 `coverage` 가 그 크기를 말하게 한다. 합계에 섞지 않는다.
    > 현재 데이터에는 0건이지만 **BL-523(브래킷 부착)이 바로 다음 후보**다. 픽스처로 미리 고정한다.
