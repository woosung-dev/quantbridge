# Sol 생성 전략의 다중 언어 실행 계약

결정은 [ADR-046](../adr/046-generated-strategy-language-evaluation.md), 현재 작업 진입점은
`docs/status.md`다. 이 문서는 실험과 제품 연결의 계약이며 완료 회차 기록을 쌓지 않는다.

## 연구 생성과 제품 LLM의 구분

연구의 1,350개 생성물은 로컬 Codex CLI 구독으로 요청한 `gpt-6.1-sol` high 산출물이다.
제품 서버의 Gemini 연결은 이 연구 모델·프롬프트·기존 생성물을 바꾸지 않으며 재생성하지 않는다.
로컬 CLI에서 만든 Python·TypeScript·Pine 원문은 `/strategies/code`에 붙여 넣고 검토·버전
저장한 뒤 서버의 검증·백테스트·Demo 경로를 이용할 수 있다. CLI 구독과 Gemini API의
인증·quota·과금은 별개이며, 구독의 정확한 plan·응답 실제 모델·USD 청구액을 추정하지 않는다.

제품의 OpenAI 유료 API 생성기 연결은 보류하고, 기존 Gemini Developer API 경로의 무료
프로젝트만 연결한다. 연결 전에 AI Studio UI에서 `Free`와 `Set up billing`을 확인해
청구 계정 미연결 상태를 확인한다. 이는 UI 관찰 근거이며 모델 목록 metadata 조회나 API 키의
존재 자체가 무료 등급을 증명하지 않는다. 기존 Pine 생성·해설·지표 변환은 공유 provider 층을
이용한다. Gemini 클라이언트는 Developer API 경로와 SDK 시도 1회를 명시한다.
`LLM_PROVIDER_ORDER=gemini`로 허용 provider를 한 개로 제한하면 다른 provider로의 fallback과
다른 provider의 명시 override를 차단한다. 무료 quota 초과는 요청 실패로 종결하며 유료 provider·프로젝트로
전환하지 않는다. 기본값인 빈 provider 목록의 외부 LLM 차단 정책은 유지한다.

무료 조건은 프로젝트의 청구 상태와 모델별 제공 범위에 의존한다. 향후 청구 계정을 연결하거나
등급·모델·설정을 바꾸면 현재 무료 사용 전제는 사라지므로 호출 전에 다시 확인한다.
[공식 billing 안내](https://ai.google.dev/gemini-api/docs/billing)는 Free와 청구 계정 연결 후의
유료 등급을 구분하며, [rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)는 프로젝트
단위 한도와 초과 오류를 설명한다. [Gemini 3.5 Flash-Lite 가격표](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite)는
Free Tier 입력·출력이 무료임을 명시한다. 무료 사용은 무제한·상시 가용성 보장이 아니며
무료 tier의 입력·출력은 Google 제품 개선에 사용될 수 있다.

## 공통 실행

언어는 `pine | python | typescript`다. TypeScript는 strict 검사 후 JavaScript로 컴파일해
Node에서 실행한다. Python은 CPython, Pine은 기존 `pine_v2`의 해석기를 사용한다.
언어 실행기는 실제 소스로 신호를 계산하며 수익률이나 체결 결과를 대신 반환할 수 없다.

부모봉의 완료 신호와 실행 봉은 구분한다. `execution_ohlcv`가 제공되면 검증된 1분봉으로
보호·평가·펀딩을 순서대로 재생한다. 평가 곡선과 위험 통계의 표본 주기는 1분이고
`config_used.freq`는 원래 신호 주기다. 분봉이 없는 상위봉 내부 펀딩은 임의 배분하지 않는다.

프로토콜은 JSONL이다. `init`은 `protocol/source/params`, `bar`는 현재 완료 봉과 확정
포지션을 전달한다. 시각은 UTC 봉 시작이며 판단은 봉 완료 뒤다. 03:00 시작 1h봉이
완료되면 00:00~04:00의 4h봉도 즉시 완료 데이터로 사용할 수 있다. 가격·수량은 decimal 문자열이다. 실행기는 현재 봉을 포함한
과거 이력만 볼 수 있다. Python `on_bar(ctx, state)`, TypeScript `onBar(ctx, state)`의
출력은 `hold | long | short | close` 중 하나인 `action`이다. SL/TP·수량 지정은 거부한다.
Pine은 같은 확정 포지션을 읽고 미체결 entry/close 의도를 내므로 체결을 두 번 계산하지 않는다.

## 고정 청산 정책

- 완료 신호 봉과 그 이전 완료 봉의 극값을 참조하고 다음 봉 시가에 진입한다.
- 실제 진입가에서 손실 방향 극값까지 거리의 1.1배를 초기 R로 고정한다.
- 1.5R에서 최초 수량 50%를 한 번 청산하고, 2R에서 비용 전 진입가부터 2R 거리로 추적한다.
- 같은 방향은 보유 계획을 유지한다. `close`는 잔량 무효화 청산이며 반대 방향은 청산 확인 뒤 반전한다.
- 비양수 R·손실 방향이 아닌 극값·유효하게 분할할 수 없는 거래소 수량은 진입 불가다.

SL/TP를 원본 코드와 이 정책이 동시에 소유하게 하지 않는다. 거래소 확정 체결이 신호 재생보다
우선한다. Demo는 사전 임시 SL과 최종 진입 VWAP 재조정을 구분하며 보호 ACK 전 상태를 숨기지 않는다.
정확한 실제 진입가 SL을 0ms에 원자적으로 부착한다고 주장하지 않는다.

## 평가와 재현

모델은 `gpt-6.1-sol` high로 고정한다. 직접 생성 A는 한 번, B와 C는 공개 오류에 의한 수정이나
생성 미완료 후 재시도를 합해 최대 두 번 추가 호출한다. 관측 누적 출력 토큰이 한도를
넘거나 누적 생성 시간이 180초에 이르면 추가 호출을 중단한다. 토큰은 응답 후 관측값이며
usage 미보고 시 실제 총소비량의 상한을 인증하지 않는다. 따라서 A와 B/C 차이는 순수한 코드
수정 효과만이 아니며 최초 생성 실패의 재시도 효과도 포함한다. timeout·미지원·표현 불가도
전체 분모에 남기며 다른 모델로 fallback하지 않는다.
개발 파일럿은 6전략×2반복×3방식×3언어, 본 평가는 30×5×3×3 산출물이다.
각 방식·언어·반복은 별도 Sol 요청이며 C는 그 요청에서 받은 명세를 요청 언어로 컴파일한다.
같은 명세를 다른 언어로 추가 컴파일한 결과를 독립 생성 표본으로 세지 않는다.

본 평가는 수치 계약 v2로 동결한다. 유한한 신호 비교는 `1e-12×max(1,|a|,|b|)` 이내를
동률로 보며 교차의 이전·현재 비교, RSI pivot·divergence와 Supertrend에도 적용한다.
원본 OHLC 극값·Aroon 동률·정수·시각과 지표 내부 분모 0은 exact다. 상수 입력의
평균·EMA/RMA는 상수를, 표준편차·MAD·회귀 기울기는 0을 보존하는 안정식을 쓴다.
CCI의 MAD 0·TSI의 평활 절대변화 0은 0, DMI의 ATR 0은 DI 0·DI합 0은 DX 0이다.
StochRSI의 RSI 범위 0은 NA이며 작은 양의 분모를 임의로 0으로 바꾸지 않는다.
이 규칙은 세 방식 모두의 공개 계약에 포함한다.

파일럿 v1은 평탄 SMA의 1 ULP 차이를 교차로 판단한 독립 기준 계산 결함이 있어 선정에
사용하지 않는다. 생성·공개 검사는 108건(107통과·1실패), 의미 결과는 70건을 보존하고
남은 38건은 중단했다. 실패 raw 결과의 오라클 결함을 모델 오류로 귀속하지 않는다.
원시 증거·동결 소스와 `INVALIDITY.json`을 보존하며 새 계약·소스·입력 manifest로 본 평가를 새로 생성한다.
본 평가 입력은 고정된 UTC anchor가 내부에 포함되도록 시작 시각을 정하고, 모든 전략의
네 의도 class 관찰수를 보고한다. 일부 전략의 long·short 기회가 1개씩인 경우도 있으므로
비영 관찰만으로 충분한 검증이나 시장 전반의 정확성을 주장하지 않는다.

원 생성 manifest의 기본 자원 epoch는 2 CPU·4 GB 연구 VM이며 공개 실행은 프로세스당 1개,
본 의미 검증의 기본 동시성은 최대 2개다.
파일럿과 본 평가는 서로 다른 불변 워크트리·run-dir를 사용한다. 파일럿 실행 중에는 본
생성·공개 실행만 진행해 합계 최대 2개 guest를 유지하며, 파일럿 종료 후에만 본 의미 검증
2개를 시작한다. 본 평가의 기본 실행은 생성·공개 실행 후 같은 manifest의 의미 검증이다.
완료된 trial의 의미 검증을 선행할 때는 생성 중 보조 작업자 1개와 공개 실행 1개로
VM 전체 guest를 최대 2개로 유지한다. 생성 종료·전체 trial 종결·공개 guest 부재와
현재 보조 작업의 정리를 확인한 뒤에만 의미 작업자를 최대 2개로 늘린다.

선행 검증은 모델·추론 강도·프롬프트·생성 예산·시도 횟수·동결 소스·이미지를 바꾸지 않는다.
생성 중인 trial은 읽기 대상에서 제외하고, 완결된 입력·캐시 hash 검증 후에만 평가한다.
공식 후속 helper는 대기 상태·자식 없음·PID 정체성·phase 락 소유를 확인해 정지시켜
캐시 writer를 하나로 유지한다. 보조 writer는 임시 파일의 배타적 원자 승격을 사용하며
기존 캐시를 덮어쓰지 않는다. 캐시별 source SHA·입력 identity·manifest·실행 환경·산출물 SHA를
별도 증거로 결합한다. 정상 인계에서는 전체 분모·캐시 증거·호스트 작업·guest 정리를 확인한 뒤 공식
helper를 재개해 원래 캐시 검사·요약·점수 선정 절차로 돌아간다. 관측 오류나 불완전 입력은
의미 실패 점수로 게시하지 않고 새 보조 작업 제출을 보류한다.

선행 검증이 중도 종료되면 기존 생성 종료 대기 경로로 복귀할 수 있다. 보조 프로세스·자식의
종료와 writer 락 해제, 보조 guest 잔존 없음, 원 helper의 정체성·대기 상태·phase 락과
동결 입력·소스를 확인한다. 완료된 canonical·proof의 일대일 대응과 원문·입력·산출물 SHA,
부분 게시 부재를 검증하고 기존 실패 결과까지 보존한 뒤 원 helper만 재개한다. 이 복귀는
선행 검증 1,350건 완료를 뜻하지 않는다. 원 helper는 생성 종료까지 기다렸다가 전체 입력을
검사하고 기존 캐시와 미완료 평가를 처리한다. 보조 러너의 중단 상태는 그대로 보존하고
복귀 증거를 별도로 기록하며, 공식 재직렬화 후 기존 캐시의 byte SHA를 다시 대조한다.

생성 종결 뒤 평가 기동 전에 설정 import가 실패하면 기존 실패 로그·상태를 보존하고 별도
재개 런처·증거 경로를 사용한다. 빈 작업 디렉터리와 정제 환경에서 설정 import에 필요한
`TRADING_ENCRYPTION_KEYS`는 메모리의 임시 Fernet 키로만 충족하며 실제 계정 키·환경 파일을
읽지 않는다. 새 모델 호출과 공개 재실행을 차단한 상태에서 동결 manifest·소스·이미지와
전체 생성 캐시를 검사하고 원래 평가 함수로 기존 의미 캐시와 미완료 평가를 처리한다. manifest 원문과
생성 산출물은 바꾸지 않으며, 평가 기동 실패를 모델의 의미 불일치로 귀속하지 않는다.
후속 분석도 원래 거절 증거를 보존하고 새 의미 검증의 실제 성공 종료·전체 분모·기존 캐시
SHA 보존을 검증하는 별도 인계 경로를 사용한다.

guest당 CPU 1개·메모리 1 GiB 한도는 전용 자원 예약이 아니다. 동시성 변경 시각·자원·
처리량·실행 오류를 기록하며, 같은 물리 호스트의 경합이 900초 wall deadline에 영향을
주지 않는다고 보증하지 않는다. 전후 작업 구성도 달라지므로 처리량·지연 변화만으로
품질 무손실이나 인과적 가속률을 주장하지 않는다. 중간 점수로 생성·선정 규칙을 바꾸지 않는다.
생성 종결 후 자원을 확대할 때는 기존 분석 대기·writer·소유 guest의 실제 종료와 락 해제를
확인하고, 완료한 실패를 포함한 전체 캐시의 원문 SHA·입력 정체성·생성 inventory를 고정한다.
원 생성 manifest는 바꾸지 않고 실제 자원·동시성을 별도 실행 epoch에 기록한다. 현재 확대
epoch는 6 CPU·8 GiB VM에서 최대 6개이며 guest당 1 CPU·1 GiB와 900초 제한을 유지한다.
기존 완료 캐시는 재직렬화·재시도하지 않고 미완료 작업만 같은 평가 함수로 계산한다.
새 계산은 시작·완료 증거를 남기고 단일 writer가 배타적으로 게시한다. 중단된 미게시 작업은
별도 인프라 중단으로 보존하며 모델의 실패 행을 새로 만들지 않는다. 자원 변경이 wall timeout에
주는 영향은 미확정이고, 실제 가속률은 별도로 관찰한다.
원격 분산을 추가할 때는 공개 저장소의 무료 표준 `ubuntu-24.04-arm` runner만 사용한다.
최대 16개 host에 각각 4개 worker를 배치하며 유료 runner·Actions artifact/cache·Packages·LFS를
사용하지 않는다. 외부 Release에는 인증 암호문만 게시하고 단기 CI secret은 평가 환경에
전달하지 않는다. 원본 source·hidden 입력·결과 원문과 실제 계정 키는 공개하지 않는다.
원격의 수치 재생성이 기존 Mac 입력 digest와 달라지면 기존 Mac의 1,200봉 값을 JSON으로
봉인해 전달한다. 별도 v8 입력 provider가 dtype·UTC index·freq와 두 원 digest를 검증한 뒤
복사본을 공급하며 원 평가·oracle·채점 함수와 기대 hash는 유지한다. 기존 v7 실패 증거와
입력 재생성 차이를 보존하고 제품 소스는 교체하지 않는다.
호스트별 정확한 Python·package·원 이미지 ID·runsc SHA와 hidden 입력 digest, 수동 3언어
fixture를 먼저 검증한다. 기존 완료 캐시는 원문 SHA로 보존하고, 인계 중 추가로 중단된
미게시 native 작업도 별도 인프라 증거로 남기며 원 1,350 분모·실패·기간·5회 fresh 검증을
줄이지 않는다. 원격 결과는 고정 shard와 입력 SHA를 검증한 단일 부모만 게시한다.
혼합 host의 자원·처리량·timeout은 별도 epoch 기술 통계다. 동일 코드·입력·이미지라도
호스트 성능과 wall deadline 영향은 달라질 수 있어 결과 동등성이나 품질 무손실을 보증하지 않는다.

산출물마다 원 실행·동일 재실행·prefix·원본 및 반전 가격의 외부 포지션 probe에 각각
새 transport를 사용한다. 캐시는 실제 평가 소스 SHA·입력 identity가 모두 맞아야 재사용한다.
구형 결과에 SHA를 사후 부착해 인증하지 않는다.

계약 충실 40·독립 원장 일치 25·재현성 15·제품 통합 10·비용/지연 10점이다. 미래 참조·
무손절·역방향 SL·중복/초과 청산·초기 R 재설정·재실행 불일치는 해당 산출물 실패다.
100점 식과 표는 그대로 보고하되, 최종 방식·언어 후보는 효율 10점을 제외한 `quality90`의
전략 평균으로 선정한다. 전략마다 5회 점수를 먼저 평균하고 30전략을 같은 비중으로 평균한다.
정확히 같은 평균의 후보에만 모든 생성·수정 attempt 출력 토큰 합계가 작은 순서를 적용한다.
동률 집합 중 하나라도 usage 미보고 또는 호출 관측 누락이면 토큰 기준 전체를 건너뛴다.
남은 동률에는 산출물별 모든 attempt 생성시간 합계의 p95가 작은 순서를 적용한다.
동률 집합 중 하나라도 실제 시간 관측이 불완전하면 이 기준 전체도 건너뛴다. `interrupted`의
선언 timeout은 실제 경과시간이 아니며 `unknown_duration_calls`로 표시하고 분위수에서 제외한다.
최종 동률은 `arm/language` 문자열 오름차순으로 정하되 우월성을 주장하지 않는다. 추가 운영
표면은 정량화하지 않았으므로 N/A이며 선정 기준에 넣지 않는다. 새 가중치·역치·수익률로
후보를 바꾸지 않는다. 정책 ID는 `quality90_then_known_tokens_then_known_p95_then_lexicographic_v1`이다.

보고서는 `policy`·`selected_candidate`·`tie_reason`을 기록한다. `--quality-selection`은 이 후보의
확인이며 다른 조합은 거절한다. 경제 분석도 같은 정책을 다시 계산하고 후보와 증거가 일치해야
실행한다. 전략별 첫 semantic pass 반복만 고정하고 없으면 N/A로 30전략 분모에 남긴다.
통과 산출물에 조건부인 회고 경제 분석이며 생성 전체의 무조건 성과나 미사용 검증이 아니다.

경제 평가의 ordered 병렬 경로는 sealed 30개와 닫힌 주기 지원 계약상 잠재 실행 일감이
있을 때 최대 6개 `run_job`을 실행하고, 없으면 원 직렬 경로를 사용한다. 원 `execute`와
`run_job`의 계산·cache binding·720+720=1,440 분모·N/A·FAIL 처리는 유지한다. 작업 완료
순서는 달라도 결과는 원 순서로 소비하고 단일 journal/report writer가 기록한다. worker 안에서
입력을 복제하며 Decimal context를 보존한다. 원 output 락은 worker drain이 끝날 때까지
유지한다. 계획 preview와 빈 실행 output을 분리하며 기존 output 자동 resume이나 완료 실패·
N/A의 재시도는 하지 않는다. 중단은 UNKNOWN으로 남기고 host worker join과 실제 guest 정리를
구분한다. 이 스케줄 변경의 실제 처리량·메모리 효과·품질 무손실은 아직 검증하지 않았다.

전략 단위 paired bootstrap은 5회 생성물을 독립 전략처럼 재표집하지 않는다. 30개 고정
카탈로그에 대한 기술 통계이며 전략군 간 상관·임의 모집단 대표성·승자 선택 편향을 제거하지
않는다. bootstrap의 `rank_leader_reference`는 해당 평균 순위와 사전순으로 정하므로, 정확
동률에서 토큰·시간을 쓰는 `selected_candidate`와 다를 수 있다. 실제 비교 기준을 함께
표시하며 그 기준과 8개 후보의 Bonferroni 구간도 확정 우월성·동등성 판정이나 선정 gate로
쓰지 않는다. 유한 평가 기준의 최적화가 선택 편향을 만들 수 있다는
[Cawley·Talbot](https://jmlr.org/papers/v11/cawley10a.html) 및 여러 데이터셋 비교의 분석 단위를 다룬
[Demšar](https://www.jmlr.org/papers/v7/demsar06a.html)의 한계를 함께 공개한다.

계약 40점은 hold·long·short·close의 class별 정확도 평균이다. 실제 거래 이력과 원본/반전
가격의 외부 포지션 probe를 함께 사용하고 기회가 없는 class는 0점 및 미검증으로 표시한다.
원장 25점은 독립 신호를 동일 broker에 넣은 거래·비용·곡선의 완전 일치, 재현성 15점은
동일 재실행과 미래 prefix 불변을 모두 통과해야 받는다. 초기 R은 별도 Decimal 식으로 검산한다.
통합 10점은 실제 언어 실행기와 공통 broker 경로의 공개 smoke 성공에 10점, 실패에 0점을
주는 일괄 proxy다. 다섯 항목을 개별 측정해 합산하는 점수가 아니다. 공개 smoke는 trace를
수집하지 않으며 비공개 semantic에서 별도로 수집·평가한다. 이 10점을 UI·SQL·실거래소
연결이나 제품 운영 적합성 검증으로 해석하지 않는다.
의미 평가의 이진 `status=failed`와 합산 부분 점수는 다르다. 재현·prefix가 안정적이고
위험 감사가 통과한 잘못된 신호도 class 정확도 일부를 받으며, 의미 불일치만으로 재현성
15점과 공개 smoke 10점이 사라지지는 않는다. 위험 감사가 실패하면 계약·원장 점수는
0이지만 재현·통합 점수는 별도 조건으로 남을 수 있다. `quality90`을 의미 정확도나 의미
통과율로 읽지 않고 항목별 점수·이진 통과율을 함께 보고한다. 의미 실행 중 예외는 의미
80점을 0점으로 보존하되, 실행기·시간 초과 등 인프라성 오류와 신호 불일치를 구분해 공개한다.
동결 점수를 원인 분류 후 다시 채점하지 않으며 모든 실패를 모델의 의미 오류로 귀속하지 않는다.
효율 10점은 `5×max(0,1−출력토큰/16384)+5×max(0,1−생성초/180)`다. CLI 구독의
실제 USD 청구액을 알 수 없으므로 이는 예산 효율 지표이며 API 가격 추정이 아니다.
출력 usage 미보고 또는 시간 미관측·interrupted 호출이 하나라도 있으면 해당 효율 성분을
0점으로 두며 관측된 다른 성분은 유지한다. 미관측을 0토큰·0초의 절약으로 취급하지 않는다.
생성/공개 실행 실패는 전 항목 0점이다. 현재 독립 기준 식은 30개 전체를 지원한다.
예상 밖 `not_evaluable`이 나오면 보고서 검증이 중단되므로 완료 평가의 0점으로 임의
편입하지 않는다. C 컴파일러의 22개 지원·8개 미지원은 별도 축이며, 생성·공개 실패도
전체 30전략 분모에 두고 해당 부분집합의 결과를 함께 보고한다.

소스·프롬프트·명세/컴파일러·parser/interpreter/stdlib·공통 리스크·기준 계산·입력 데이터·
이미지 ID·요청 모델과 관측 usage를 기록한다. CLI 응답에 실제 모델 ID가 없으면 요청
플래그만 확인한 것으로 표시하며 실제 모델을 검증했다고 주장하지 않는다. raw 생성·실행 산출물은 `runs/`에만 둔다.
기존 24개월 자료는 회고 분석이며 미사용 최종 검증이 아니다. 비용과 펀딩의 가정도 함께 공개한다.
6개월 분봉 기간은 24개월 부모봉 기간 안에 포함되므로 두 계열을 독립된 시장 증거로 세지
않는다. 경제 시나리오는 한 번에 한 요인만 바꾸며 결합 스트레스가 아니다. `funding_x2`는
펀딩의 부호를 유지해 수취 포지션의 수익을 늘릴 수 있으므로 항상 불리한 비용 스트레스로
해석하지 않고 baseline보다 유리한 셀도 표시한다.

## 격리와 제품 편입

연구는 기존 `qb-python-research` Linux VM을 명시적인 Docker endpoint로 사용한다. 공유
Docker context는 바꾸지 않는다. gVisor·network none·read-only·nonroot·CPU/메모리/PID·
시간/출력 한도를 확인하며 컴파일도 같은 경계 안에 둔다. 호스트 fallback은 없다.

기존 Pine 저장/백테스트는 계속 기존 경로다. 비교와 수동 검토를 위한 코드 저장·dispatch는
세 언어를 지원하고, 기본 생성 방식·추천 언어는 평가 후 결정한다. 과거 Python 연구
3테이블은 자동 복구·삭제하지 않는다. API의 장기
작업은 202+작업 ID를 사용하며 실행기는 주문 키·DB 접근·임의 egress를 갖지 않는다.
연구 백테스트의 전체 900초 제한 통과는 제품의 30초 cold replay 적합성을 뜻하지 않는다.
고정 후보·첫 통과 source hash에 대해 제품과 같은 격리 자원·시작 비용·지원 이력 길이의
30초 replay와 intent 일치를 별도로 확인한다. 실패하면 연구 후보/운영 부적합으로 표시하고
점수나 반복 선택을 바꾸지 않는다. `final_selection_allowed`는 본 평가 완료·증거 요건이며
운영 승인이나 Demo 적합성을 뜻하지 않는다.
실제 Demo 주문 관측과 배포는 별도 승인 전까지 미검증 상태로 남긴다.

개발용 원격 사전 검사는 201개 1시간봉과 `freq="1h"`를 함께 고정한다.
초기 사전 검사에서 누락된 freq는 transport 생성 전 데이터 검증으로 거절되었으며,
해당 개발 fixture 실패를 연구 전략의 실패 점수나 완료 건수에 넣지 않는다.
