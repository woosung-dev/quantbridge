# FE 성능 평가

## 기준과 범위

`vercel-react-best-practices`의 적용 조건과 프로젝트 FSD Lite·Hooks H-1~H-3를 함께 확인한다.
React Query는 요청 중복 제거 규칙의 구현이다. SWR 추가, 모든 함수의 메모이제이션, 모든 배럴의
제거를 요구하지 않는다. 의도적인 Recharts 청크 진입점과 Next의 기본 패키지 최적화도 확인한다.

시작 시 메인 체크아웃의 변경 여부를 확인하고 `git pull --ff-only origin main`으로 동기화한다.
작업 워크트리는 최신 `origin/main`에서 브랜치를 만들며 main에 직접 push하지 않는다.
기준 SHA의 `git ls-files -z apps/web` 목록과 각 파일·스킬 규칙 원문의 SHA-256을 보존한다.
실행 코드, 테스트·지원 도구, 설정, 스타일, 정적 자산을 구분해 담당자와 검토 수준을 기록한다.
파일 이동·분할은 기존 항목과 새 경로를 연결하고 신규 코드는 별도 검토한다.

## 점수

기록 단위는 파일 안의 이름 있는 컴포넌트·훅·함수와 적용 규칙이다. 판정에는 코드 위치와
적용 이유를 남긴다. 테스트·정적 자산을 애플리케이션 성능의 PASS로 세지 않는다.

| 판정 | 의미 |
| --- | --- |
| PASS | 적용 조건이 있고 코드·검증 근거로 충족을 확인함 |
| FAIL | 적용 조건과 구체적인 위반이 확인됨 |
| UNKNOWN | 판정에 필요한 코드 또는 실행 증거가 부족함 |
| N/A | 적용 조건이 없음. 규칙 또는 규칙 묶음별 사유 필수 |

자체 준수 점수는 `100 × PASS / (PASS + FAIL + UNKNOWN)`이다. N/A는 분모에서 제외한다.
적용 항목이 없으면 점수는 N/A다. 파일·요소·도메인·8개 규칙군 점수는 원시 판정 수를 합산해
계산한다. 파일 점수의 평균으로 전체 점수를 계산하지 않는다.

Before의 적용 항목 집합을 고정한다. After에서 N/A로 바꾸려면 Before도 같은 기준으로 다시
평가하고 사유를 공개한다. 구조적으로 위반 경로를 없앤 경우 기존 항목에 수정 근거를 연결한다.
검토 완료율과 `(PASS + FAIL) / 적용 항목 수`인 확정 판정률도 표시한다. 구조 경계 평가는
별도 항목이며 Vercel 규칙 점수와 합치지 않는다. 이 점수는 Vercel이 제공한 공식 점수가 아니다.

## 실제 성능 비교

기존 `screen-evidence`의 프로덕션 빌드·Playwright 자산 바이트 측정을 재사용한다. 빌드와 분석의
번들러를 일치시킨다. 같은 SHA의 독립 Before 소스를 보존하고, 같은 브라우저·뷰포트·데이터·
세션·캐시·네트워크 조건에서 각 시나리오를 5회 측정해 중앙값과 최솟값·최댓값을 남긴다.

- 초기 JS/CSS는 `/_next/static/` 응답의 `request().sizes().responseBodySize` 합계다.
  폰트는 제외하고, 선택 기능을 연 뒤 받은 청크는 초기 로드와 구분한다.
- 화면별 데이터 완료 앵커와 최종 URL을 확인한다. 실패 응답·pageerror·앵커 누락은 측정 실패다.
  로그인 화면이나 빈 오류 화면의 가벼운 번들을 성능 개선으로 기록하지 않는다.
- 요청은 엔드포인트·시작 시각·횟수를 보존한다. 정상 폴링, SSR hydration, 재시도를 구분한다.
  기존 인증 화면의 불안정한 전체 요청 수 baseline을 임의의 정수로 바꾸지 않는다.
- 입력·정렬·차트 갱신은 같은 동작에서 호출 횟수와 처리 시간을 비교한다. 모의 라이브러리의
  호출 수 검증과 실제 브라우저 시간을 구분하며, 개발 모드 Strict Mode도 별도로 확인한다.
- 합성 응답·고정 거래 원장·최적화 셀로 측정하면 그 조건을 명시한다. 실제 시장 데이터와
  운영 성능으로 일반화하지 않는다. 미측정·환경 실패는 UNKNOWN으로 남긴다.

## 결과와 검증

원시 판정, 파일 목록, 규칙 해시, 측정값, 화면과 실행 로그는 `runs/fe-react-audit/<기준SHA>/`에
둔다. `runs/`는 gitignore이므로 PR에는 요약 표와 재현 명령을 직접 남기고, 산출물 보관은 별도로
수행한다. 완료 회차 기록을 설계 문서나 status에 누적하지 않는다.

수정자 외 에이전트가 원래 규칙·코드·검증을 대조한다. 변경에 맞는 표적 테스트와 실제 dev
브라우저 확인을 수행하며, 최종 품질 판정은 기존 CI의 Biome·TypeScript·Vitest·build와
배선된 여정 검증이다. 점수를 올리기 위한 신규 영구 CI 게이트나 훅을 추가하지 않는다.
