# ADR-047 — 에이전트 지침은 「규칙 ↔ 집행」 표로 줄이고, 하네스 러너를 걷어낸다

- **상태:** Accepted (2026-11-19 사용자 결정)
- **관련:** [ADR-026](./026-documentation-ssot.md) · [ADR-027](./027-nested-agents-md.md) · [ADR-030](./030-harness-pilot-verdict.md) · [ADR-037](./037-harness-zero-base.md)
- **복원 원본:** `git show befaa005:<경로>` — 철거 직전 커밋

## 결정

「지금 무엇을 하는가」의 정본은 코드다. 지침 파일(`AGENTS.md` 3종)은 코드가 말하지 못하는 것만 갖는다.

1. **규칙은 가장 높은 단에서 고친다.** 구조 → 타입·lint → 테스트 → 문장 순이다.
   문장으로 남기는 것은 판단이 필요한 규칙과, 아직 집행기가 없는 안전 규칙뿐이다.
2. **`AGENTS.md` 마다 「규칙 ↔ 집행」 표를 둔다.** 집행기가 있는 규칙은 표 한 줄로 줄이고 설명은
   그 테스트·lint 의 오류 문구가 갖는다. 집행기가 생기면 문장을 지운다.
3. **집행 없는 규칙이 다시 어겨지면 같은 변경에서 집행기를 만든다.** 문장을 더 굵게 쓰지 않는다.
4. **이력·개수·줄 좌표·정정 서사는 지침 파일에 두지 않는다.** git 과 코드가 갖는다.
5. **하네스 러너를 걷어낸다** — `tools/harness/execute.py` · `apps/api/tests/harness/` ·
   `.claude/commands/harness.md` · `phases/`.
6. **절 번호와 `H-N` id 는 옮기지 않는다.** 코드 주석·테스트 오류 문구가 수백 곳에서 인용한다.

남기는 것: `evals/harness`(지침이 실제로 적용되는지 재는 유일한 행동 검사) · `/review-code` · `/qb-review` ·
`ledger-vitals.sh` · 권한 경계 소품(pre-push · `assert-main-checkout.sh` · codex 훅).

## 이유와 대가

- 지침 3종은 623줄이었고 그 대부분이 코드가 이미 말하는 것(스택 표·폴더 트리·CI 단계 목록)이거나
  옛 문장과의 차이를 설명하는 서사였다. CI 단계 목록은 세 곳에 복사돼 있었고 한 곳은 틀려 있었다.
- 「집행 = `auth-ctx-boundary.test.ts`」라고 적힌 규칙의 가드는 한 파일만 보고 있었다.
  집행기를 문장으로 적어 두면 가드의 실제 스코프와 어긋나도 아무것도 실패하지 않는다.
- 러너는 2026-08-30 이후 주행이 없고 `phases/index.json` 은 빈 배열이었다. 그동안에도 러너 본체
  780줄·자기 테스트 5파일·커맨드 227줄이 유지 비용으로 남았다.

대가:

- codex lane 에 지침을 주입하던 `GUARDRAIL_FILES` 가 사라진다. codex 는 가까운 `AGENTS.md` 를 직접 읽는다([ADR-027]).
- 워크트리 병렬 lane 의 무인 주행(lane PR·머지)이 없어진다. 슬롯·테스트 DB 준비는
  `tools/scripts/worktree-bootstrap.sh` 가 그대로 한다.
- 지침에서 빠진 사고 서사는 `docs/lessons.md` 와 git 에만 남는다.

## 버린 대안

- **문구만 다듬는다** — 지워질 문장을 고치는 일이다.
- **`evals/harness` 도 지운다** — 지침을 줄인 뒤 「그 줄이 없어도 같은 답을 하는가」를 잴 수단이 없어진다.
- **pstack 스킬을 통째로 설치한다** — 전역(`~/.claude`) 결정이고 이 레포의 지침 형태와는 별개다.
  여기서 가져온 것은 `/correct` 의 사다리와 규칙 표뿐이다.

## 재평가 트리거

- 같은 교정을 두 번 하게 되면 그 규칙의 집행기를 만든다.
- 병렬 lane 무인 주행이 다시 필요해지면 `befaa005` 에서 러너를 복원하기 전에 도구 자체 기능으로 되는지 먼저 본다.
