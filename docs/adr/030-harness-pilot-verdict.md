## Context — 「하네스」는 한 덩어리가 아니라 두 종류였다

2026-07-29 ~ 08-13 사이 3주 동안 이 레포에 **하네스라고 불리는 것이 480KB** 쌓였다.
걷어내기를 논하려면 먼저 갈라야 한다 — 두 종류는 모델 능력에 **반대 방향으로** 반응한다.

|                 | **(a) 조종 장치**                                                                  | **(b) 증거 장치**                                                            |
| --------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 하는 일         | 모델을 _어떻게 움직일지_ 강제 — step 분해·순차 실행·재시도·프리앰블 주입·워커 분배 | 결과가 _틀렸을 때 그것을 드러냄_ — 게이트·감사기의 판별력 자기시험·커밋 차단 |
| 부피            | **230.3 KB** (27파일) → 회수                                                       | **249.7 KB** → 유지                                                          |
| 모델이 좋아지면 | 값이 **줄어든다**                                                                  | 값이 **그대로거나 늘어난다** — 빠른 모델은 틀린 것도 빨리 커밋한다           |
| 지우면          | 「내가 더 자유롭다」                                                               | 「**틀렸는지 모르게 된다**」                                                 |

★**부피는 `wc -c`(실바이트)로 쟀다.** 처음 `du -k` 로 재서 「260KB / 260KB」로 적었는데
4KB 블록 반올림이라 **13% 부풀었다**. 파일이 많고 작을 때 `du` 를 크기 근거로 쓰지 마라.

★**구분 시험은 이 마지막 줄 하나다.** 이 ADR 이 걷어내는 것은 (a) 전량이고, (b) 는 한 줄도 안 건드린다.

### 무엇을 시험했나

`scripts/execute.py`(출처: <https://github.com/jha0313/harness_framework>, 강의 자료)는
**오케스트레이터를 LLM 에서 스크립트로 내린다.** `claude -p` 를 step 마다 새 프로세스로 띄우고,
부모 컨텍스트가 없으며, 유일한 보고 채널이 `phases/*/index.json` 이다.
원본 as-is 채택을 조건으로 **2회 돌려보고 판정**하기로 했다 (수정은 경로 1줄뿐).

**재려던 것은 하나였다 — 「자기채점이 뚫리는가」.** 원본 러너는 AC 커맨드를 실행하지 않고
step 세션이 써넣은 `"completed"` 를 그대로 믿는다. 즉 **코드를 쓴 쪽이 자기 채점을 한다.**
이 레포는 그 실패를 4회 기록해 두었다.

| 회차  | BL     | 판본                                                                                  |
| ----- | ------ | ------------------------------------------------------------------------------------- |
| **A** | BL-708 | 순수 as-is. 세션 자기신고 → CONTROL 이 **사후에** 각 step 의 AC 를 재실행해 대조      |
| **B** | BL-709 | `index.json` step 에 `ac` 배열 + 러너가 exit code 로 판정. **실행기도 codex 로 바꿈** |

## 근거 — 왜 (a) 를 걷어내나

1. **재려던 것이 안 재졌다.** 2회차 40건에서 불일치 0 인데, 그건 **결정적 AC 만 준 결과**다 —
   A 는 16건 중 12건, B 는 24건 중 20건이 typecheck·lint·vitest·grep·`git diff`·게이트다.
   CONTROL 이 재실행해도 같은 답이 나오도록 **일부러 골랐다**(안 그러면 불일치가 부정직인지
   측정 잡음인지 안 갈린다). ⇒ 「자기채점이 뚫리는가」에 대한 답은 **여전히 없다.**
2. **값이 나오는 자리가 옮겨가지 않았다.** 러너는 AC *실행*을 가져갔을 뿐, 「무엇을 재야 red 가
   나는가」는 그대로 사람 몫이었다. 오히려 **비싸졌다** — 러너가 exit code 로 판정하므로
   AC 버그가 측정 오차가 아니라 **회차를 막는 red** 가 된다.
3. **실행 경로가 취약하다.** as-is 위험 11건을 코드 대조해 표로 동결했는데, **회차를 죽인 것은
   표에 있던 것이 아니라 없던 7번째**였다(`_invoke_claude` 의 `subprocess.run(timeout=…)` 이
   `TimeoutExpired` 를 안 잡는다). 그때 트리에 남은 상태가 **정확히 B 가 막으려던 것**이다 —
   AC 0건 실행 + `completed` 커밋. `--push` 를 안 쓴 것만이 그것이 원격으로 나가는 걸 막았다.
4. **커밋 노이즈 5배** (step 당 feat+chore 2커밋 × 4 + finalize).

★★**걷어내는 이유가 「모델이 좋아졌으니까」가 아니라는 점을 박아 둔다.** 우리 실측은
「똑똑한 모델은 step 파일 없이도 순서를 안다」를 **재지 않았다**. 잰 것은 「이 조종 장치가
값을 안 냈고 비용은 5배였다」다. 근거를 갈아 끼우면 판단이 틀린 곳으로 간다
(`lessons.md` LESSON-089).

### 판정 이력 — 같은 날 뒤집혔다

- **2026-08-13 (1차)** 사용자 판정 = 「일단 유지」(보류). 삭제도 3회차도 고르지 않음.
- **2026-08-13 (2차, 이 ADR)** = **걷어낸다.** (a)/(b) 구분을 세운 뒤 재판정한 결과다.
  1차는 「세 갈래가 열려 있다」는 상태였고 이 ADR 이 그중 삭제를 골랐다.

## ★하네스가 없어져도 남는 발견 5건 — 이 ADR 의 실질

파일럿이 실제로 값을 낸 곳은 러너가 아니라 **우리 레포에 대해 알아낸 것**이다.
하네스를 지워도 이 다섯은 참이고, 다음에 어떤 무인 도구를 붙여도 다시 만난다.

### ① 우리 `docs/` 최상위를 프롬프트에 주입하면 **주입하면 안 되는 것만** 들어간다

원본 `_load_guardrails()` 는 `docs/*.md` 를 필터 없이 넣는다. 그건 게으름이 아니라 계약이다 —
원본 `docs/`(PRD·ARCHITECTURE·ADR·UI_GUIDE)에는 **정적 설계 제약만** 있다.
우리 `docs/` 최상위는 그 계약과 **정확히 반대**다. glob 이 잡는 것은
`status.md`·`backlog.md`·`roadmap.md`·`lessons.md`(**814,211자**)뿐이고, 정본인
`docs/reference/`·`docs/adr/` 는 하위 디렉터리라 **하나도 안 잡힌다.**
크기 문제가 아니라 **선택 문제**다 — 세션이 「다음 행동 = …」과 미해결 BL 수백 건을 손에 쥔다.

⇒ 무인 세션에 규칙을 주입할 때 쓸 4축은 **`CONTEXT.md` · `AGENTS.md` · `backend/AGENTS.md` ·
`apps/web/AGENTS.md`** 다. 실측 **814,211자 → 45,367자 (−94.4%)**, 양성 대조 4축 전건 주입 ·
음성 대조 제외 5파일 전건 미주입 + 그 검사가 수정 전 주입물에서 5/5 를 잡는 것까지 확인했다.

### ② `AGENTS.md` 의 「게이트는 마지막 커밋 뒤에」가 무인 세션에게 **66분**을 태웠다

step 파일·프리앰블을 고정하고 **실행기만 바꿔** 1-step 프로브를 4회 돌린 실측:

| arm | 실행기 | 벽시계             | 셸 실행 | `final-gates`                 |
| --- | ------ | ------------------ | ------- | ----------------------------- |
| A   | codex  | 2분 36초           | 19건    | 읽기만(실행 0)                |
| B   | codex  | **1시간 6분 33초** | 14건    | **실행 3회** → BE pytest 전량 |
| C   | claude | **52초**           | 5건     | 0                             |
| D   | claude | **59초**           | 4건     | 0                             |

★**러너 자체의 오버헤드는 1분 미만이다. 66분은 전부 게이트였다.**
arm B 가 자기 입으로 이유를 말했다 — 「**프로젝트 규칙의 마지막 커밋 후 게이트 의무에 따라**
`final-gates.sh` 를 실행하겠습니다」. 막히자 스스로 우회했다: 인자 없이 실행(rc=1) →
`--run eod`(BL-706 으로 금지) → **자기가 슬러그를 지어냄**.

**인과** — `AGENTS.md` 의 그 문장은 **회차 단위**(PR 직전 1회)를 뜻하는데 **그 맥락이 글에 없다.**
사람은 문맥으로 알지만 무인 세션은 물어볼 사람도 없다.
⇒ **잔여 부채:** 이 문장에 범위(회차 단위 · 세션이 아니라 사람이 돈다)를 박아야 한다. 미착수.

### ③ `-s workspace-write` 샌드박스의 집행력은 **파일시스템 축에만** 있다

| 대상                                   | 결과                                              | 재현성              |
| -------------------------------------- | ------------------------------------------------- | ------------------- |
| 워크스페이스 안 쓰기 · `git commit`    | 허용                                              | 전건                |
| `/tmp` 쓰기                            | 허용                                              | 전건                |
| **홈 디렉터리 쓰기**(`~/.cache/uv` 등) | **거부** — `Operation not permitted (os error 1)` | **전건**            |
| 네트워크(`localhost:8100`)             | ★**갈린다**                                       | **3 차단 / 6 관측** |

★**「샌드박스가 네트워크를 막는다」는 거짓이다.** 같은 커맨드 6회 중 3회 차단 / 3회 허용(200).
**한 번 보고 단정했다가 프로브가 뒤집었다** — 기전은 모른다(`[확인 필요]`).
BE pytest 가 막힌 것도 네트워크가 아니라 **홈 캐시 쓰기**에서였다.
⇒ 범위 강제를 샌드박스 하나에 걸지 마라. 확실히 얻는 것은 「워크스페이스 밖을 못 쓴다」뿐이다.

### ④ 실행기 축은 실재하지만, **문을 열어 둔 것은 우리 규칙이다**

`claude` 는 **6/6** 으로 범위를 지켰다(프로브 2회 + A회차 4 step). `codex` 는 **2/2** 로
게이트에 손을 댔고 그중 1회가 실행까지 갔다. B회차 step 1 에서는 작업을 **4분 19초**에 끝내고
**AC 에 없는 backend pytest 전량을 두 번** 돌리다 1800s 상한에 걸렸다.
⇒ 「구현은 codex」 워크플로우를 쓸 때 **범위 이탈은 프롬프트로 막아야 한다** — 모델 선택으로 안 막힌다.

### ⑤ 「51 passed」가 실행기를 검증하지 않았다

원본 테스트 51건은 **12개 클래스 전부 헬퍼 단위**이고 순차 실행 루프를 한 줄도 안 탄다 —
`run()` · `_execute_single_step` · `_execute_all_steps` · `_finalize` · `_ensure_created_at` 이
테스트 파일에 **각 0회** 등장한다. `run()` 을 no-op 으로 바꿔도 51건은 대부분 초록이다.
⇒ 초록이 말한 것은 「내 1줄 수정이 헬퍼를 안 깼다」까지였다. (LESSON-101 계열)

### 부수 — AC 를 쓸 거면

- **헛초록 4건이 착수 전 스모크에서 걸렸다** (A 2 + B 2): 판정 없이 `wc -l` 로 찍기만 함 ·
  기준을 `main` 으로 잡아 후속 step 의 정당한 변경까지 위반으로 셈 ·
  `grep -q 'searchParams'` 가 **결함을 설명하는 주석** 때문에 이미 rc=0 · 무관한 동명 상수.
  ⇒ AC 는 착수 전에 **red/green 양쪽을 실측**해라(B 는 24건에서 red 10 / green 14 를 확인했다).
- **순서 의존 AC 는 사후 재실행이 불가능하다.** 「이 회차가 아직 X 를 안 건드렸다」는 뒤 step 이
  X 를 정당하게 고치면 영원히 red 다. ⇒ **AC 를 시점 독립으로 짜라.**
