# Generator / Evaluator 파이프라인 — 구현은 codex, 판정은 Claude

> **목적:** 생성 주체와 검증 주체를 분리해 circular oracle(`global.md` §7.3)을 절차가 아니라 **구조**로 차단한다.
> **도입:** 2026-07-27 live-ops-hygiene 스프린트 (1/3 검증 시작).
> **승격 경로:** 3회 검증 통과 시 `.ai/common/global.md` §7.6 영구 규칙 승격.
> **근거:** `.ai/common/global.md` §7.1(kickoff preflight) · §7.3(circular oracle 금지) · `docs/reference/gates-and-traps.md`.

---

## 1. 왜 나누는가

이 프로젝트가 반복해서 밟은 함정은 **생성한 주체가 그 결과를 검증하는 것**이다. 지금까지는 같은 세션이 코드를 쓰고 같은 세션이 게이트를 돌린 뒤 **codex 리뷰 1회**로 그것을 겨우 보정해 왔다. 그 보정은 실제로 작동했다 — 최근 **5세션 연속 P1 을 적발**했고, 그중 2건은 "내가 이미 고쳤다고 문서에 쓴 것이 절반이었다" 였다. 바꿔 말하면 **자기 검증은 5번 연속 실패했다.**

구현자를 codex 로 분리하면 비순환성이 구조로 보장된다. 대신 새 위험 두 개가 생기고, 이 파이프라인은 정확히 그 둘을 막는 형태다.

| 새 위험                                                                                                | 차단 장치                                                                                    |
| ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| 생성자가 테스트도 쓰면 그 테스트는 구현의 거울이 된다                                                  | **수용 기준과 표적 변이는 구현 전에 평가자가 동결**한다(G1). 판별력 검증은 평가자만 한다(G3) |
| codex 는 이 레포의 함정을 모른다(3-env 소싱·5433/6380·KITPORT 센티넬·`pnpm test --run` 의 조용한 죽음) | **게이트를 codex 에게 맡기지 않는다.** 태스크 스펙에 `gates-and-traps.md` 를 명시 첨부한다   |

## 2. 적용 대상

- **적용** — Est S 이상, 또는 머니-패스·게이트·라이브 매매 시맨틱에 닿는 변경.
- **비적용** — XS 단건, 문서 전용, 오타·설정. 이 파이프라인이 과하다.

## 3. 역할 카드

|      | **Generator = codex**                 | **Evaluator = Claude**                                                                                                |
| ---- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 산출 | 코드 + 단위테스트 diff                | 수용 기준 · 표적 변이 · 게이트 판정 · 화면 검증 · 문서 · PR                                                           |
| 금지 | 게이트 판정 · 문서 갱신 · 커밋 · 머지 | 구현 diff 작성                                                                                                        |
| 예외 | —                                     | 평가 중 발견한 1~3줄 수선은 허용. 단 **그 수선은 G6 codex 리뷰에 반드시 포함**시켜 자기 검증으로 되돌아가지 않게 한다 |

## 4. 단계

```
G0 preflight ─→ G1 수용기준 동결 ─→ G2 구현(codex) ─→ G3 평가(변이+오라클)
                      ↑                                      │
                      └────────── 되돌림 ←───────────────────┘
G4 화면(playwright MCP) ─→ G5 vercel-react-best-practices ─→ G6 codex 최종 리뷰
                                                                    │
G7 로컬 CI 3잡 재현 ─→ G8 문서 원자 갱신 + PR ←─────────────────────┘
```

### G0 — preflight (평가자)

`global.md` §7.1 의무. baseline 재측정 + **전제 실측 반박**.

- 게이트 baseline(BE·FE·e2e 숫자)을 지금 HEAD 에서 다시 잰다.
- BL 본문의 주장을 **DB SQL / 로그 grep / 코드 대조**로 1줄씩 확인한다.
- ★**핸드오프·백로그·플랜의 문장은 신뢰 대상이 아니라 대조 대상이다.** 실측이 스코프를 바꾼 사례가 연속으로 나왔다 — BL-498 은 백엔드 신규 경로가 아예 불필요했고(`close_position` 이 `is_active` 를 요구하지 않았다), 2026-07-27 종결 세션은 **핸드오프 문장 2개가 틀렸다**(작업 문서 커밋 여부·게이트 숫자).
- **STOP** — 전제가 반박되면 플랜을 고치고 G1 으로 간다. 반박된 전제 위에 구현을 시작하지 않는다.

### G1 — 수용 기준 동결 (평가자) ★분리의 핵심

BL 별로 **실행 가능한** 통과 조건을 쓴다.

1. 어떤 테스트가 red → green 이 되는가(파일·테스트명까지).
2. 어떤 화면이 무엇을 보여야 하는가(렌더된 페이지 기준).
3. 어떤 **외부 오라클**과 일치해야 하는가(raw HMAC · 손계산 · 결정론 픽스처).
4. **표적 변이 M1..Mn** — 구현 전에 적는다. 구현을 보고 만든 변이는 구현에 맞춰진다. **음성 대조(N)** 도 함께 적어 과민 반응을 배제한다.

여기서 codex 플랜 검증 1회를 건다.

```bash
codex exec -s read-only -C "$QB" "$(cat plan.md)" < /dev/null
```

findings 는 **전건 재현 판정** 의무다. 액면 수용 0건, 기각도 사유를 남긴다.

★**이 단계가 가장 싼 수정 지점이다.** live-ops-hygiene 1회차에서 codex 가 8건을 냈고 **전건 재현·기각 0건**이었으며, 그중 3건이 **설계 자체를 교체**시켰다(§6 참조). 코드를 쓴 뒤였다면 전부 재작업이었다.

### G2 — 구현 (생성자 codex)

```bash
codex exec -s workspace-write -C "$QB" "$(cat task-spec.md)" < /dev/null
codex exec resume --last "<후속 지시>" < /dev/null    # 이어가기
```

- ★**`< /dev/null` 필수.** 백그라운드에서 stdin 이 열려 있으면 무한 대기한다(워커 2기가 52분·38분을 그렇게 날렸다).
- **BL 1건 = codex 1세션.** 여러 BL 을 한 세션에 넣으면 diff 가 섞여 변이 판별이 무뎌진다.
- 태스크 스펙에 반드시 넣을 것 — G1 수용 기준 · `.ai/rules/` 레이어 규칙(Repository-only · `Decimal` · prefork-safe) · `docs/reference/gates-and-traps.md` · **"스펙 밖 리팩토링 금지"**.

### G3 — 평가 (평가자) ★진짜 게이트

1. **코드 대조** — 스펙 이탈과 레이어 위반을 읽어서 찾는다. codex 요약을 근거로 쓰지 않는다.
2. **표적 변이 주입** — G1 에서 미리 쓴 M1..Mn. 의도한 테스트만 red 이고 **음성 케이스는 green 을 유지**하는 것까지 본다.
   - ★변이·복원은 **문자열 치환 쌍**으로 한다. `git checkout <file>` 을 쓰면 그 파일의 **이번 스프린트 신규 코드까지 함께 사라진다**(실제로 신규 repository 메서드가 통째로 날아갔다).
   - ★마지막에 **복원 확인 실행**을 반드시 넣는다. 그 단계가 위 사고를 잡았다.
3. **외부 오라클 대조** — 엔진 산출을 같은 엔진으로 검증하지 않는다. 머니-패스는 raw HMAC 독립 조회로 3중 대조한다.
4. **적대 검증 — 읽기 전용 서브에이전트 3기 병렬.** 렌즈를 **서로 다르게** 준다(동시성 / 거래소 실상 / 표시 계약). 같은 렌즈 3기는 중복이고, 다른 렌즈는 서로 못 보는 실패 모드를 잡는다. findings 는 전건 코드 재현 판정 후 처분한다.
   - ★**반드시 읽기 전용이다.** 테스트 DB 는 `quantbridge_test` 하나이고 세션 픽스처가 `drop_all + create_all` 을 돌린다(pytest-xdist 미설치). 쓰기 에이전트를 병렬로 두면 **서로의 테이블을 실행 중에 날린다.** e2e authed 도 flake 때문에 `--workers=1` + 공유 storageState 로 묶여 있고, dev 서버·격리 스택·dogfood 거래소 계정도 각각 하나뿐이다. **이 레포에서 병렬화가 가능한 것은 읽기뿐이다.**

**STOP** — 변이가 아무 테스트도 뒤집지 못하면 그건 게이트가 아니다. 승인하지 말고 G1 으로 되돌린다.

### G4 — 화면 검증 (MCP playwright, 평가자)

- ★**정체성 프로브 먼저.** `http://localhost:3100` 이 `<title>QuantBridge</title>` 인지 확인한다. 3000 은 남의 앱(Nexus)이고, 과거 캐논 27건이 그 앱을 감사하며 전부 거짓 그린이었다.
- Clerk `storageState` 쿠키 주입으로 authed 화면에 진입한다.
- 확인 항목 — 실제 클릭 → 네트워크 요청 → **원장·거래소 변화**, 콘솔 error 0, 375px 반응형.
- ★**"화면에서 확인" 은 렌더된 페이지에서 한다.** API 응답이나 DB 행으로 대체하면 그것은 화면 검증이 아니다(그 혼동으로 회고를 정정한 이력이 있다).
- 화면이 이상하면 **3층 대조** — 소스 / 프로덕션 빌드 / dev 서버가 실제로 서빙하는 원문. ③만 다르면 Turbopack 캐시이고 **복구는 재기동뿐**이다. 실행 중인 서버 밑에서 `.next` 를 지우면 `routes-manifest.json` ENOENT 로 그 서버가 500 을 낸다.

### G5 — FE 품질 패스

FE diff 가 있을 때만 `/vercel-react-best-practices` 를 건다. 우선순위는 waterfall → bundle → server → rerender 순. 수정 필요분은 **다시 codex 로 되돌려** 생성자 역할을 유지한다.

### G6 — codex 최종 적대 리뷰

```bash
codex exec review < /dev/null        # 또는 누적 diff 를 붙여 challenge 모드
```

**생략 금지.** 5세션 연속 P1 을 적발했다. findings 는 **수정 / 기각(사유 기록) / BL 등재** 로 전건 처분한다. ★codex 의 지적도 코드로 재현 판정한다 — 결론은 맞고 근거가 틀린 사례가 반복해서 나왔다. ★평가자가 직접 손댄 줄(문서·1~3줄 수선)을 리뷰 범위에 반드시 포함시킨다.

### G7 — 로컬 CI 3잡 동일 재현

이 레포는 GitHub Actions 크레딧 초과로 게이트 잡이 **2초 만에 죽는다**(러너 미할당이지 코드 실패가 아니다). 판단 근거는 로컬뿐이다.

```bash
git diff --name-only $(git merge-base origin/main HEAD)..HEAD   # path-filter 판정
```

| 잡       | 로컬 상시 게이트에 없는 CI 전용 스텝                                                                                                    |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| backend  | `pytest --cov=src.trading.registry --cov=src.trading.webhook --cov=src.trading.websocket --cov-report=term-missing --cov-fail-under=90` |
| backend  | fresh throwaway DB 에 `alembic upgrade head` (개발 DB 를 향하지 않게)                                                                   |
| frontend | `pnpm build` · `pnpm install --frozen-lockfile` · rules-of-hooks eslint-disable 차단 grep                                               |
| e2e      | `pnpm e2e`(project=chromium, 4건) — `e2e:design-canon`·`e2e:authed` 와 **별개**                                                         |

실측 소요 — BE pytest 4분 + 커버리지 7.6분 + FE vitest 20초 + e2e authed 3.6분 + canon·build 각 1분 ≈ **20분**. 그래서 **풀 게이트는 G7 에서 1회만** 돌리고 G3 중간에는 표적 서브셋만 돌린다.

### G8 — 문서 원자 갱신 + PR

- dev-log 신규 + INDEX + status + roadmap + backlog 를 **같은 커밋에서** 갱신한다.
- ★**요약 레이어는 본문보다 늦는다.** 2026-07-27 종결 시 `dev-log/INDEX.md` 가 **폐기된 설계를 출시된 것처럼** 적고 있었고 `roadmap.md` 도 같은 상태였다. 종결 체크리스트에 **"요약(INDEX·roadmap·status)을 본문과 대조"** 를 고정 항목으로 넣는다.
- 작업 문서(`docs/<theme>/`)는 **흡수 대조 후 삭제**한다. 대조 없이 지우지 마라 — 2세션 연속으로 미흡수 2건이 나왔다. `docs/` 최상위 10 유지.
- PR 생성까지. **squash 는 사용자.** 명시 위임이 있을 때만 머지한다.

## 6. 검증 누적

`global.md` §7 승격 규칙에 따라 **3회 검증 후** §7.6 승격 후보가 된다. 적용할 때마다 1줄씩 남긴다.

| 회차 | 스프린트         | 결과                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1/3  | live-ops-hygiene | **진행 중.** G1 이 즉시 값을 냈다 — codex 플랜 검증 1회(읽기 전용)가 **8 findings, 전건 재현, 기각 0**. 그중 **3건이 설계를 교체**시켰다: ① 제출 중단 행을 `rejected` 로 찍는 초안이 **거래소에 실주문 고아를 남길 수 있었다**(`orderLinkId` 조회로 교체) ② `OrderNotFound` 흡수 설계가 겨눈 예외가 틀렸다(Bybit `110010`/`110008` 은 `InvalidOrder`) ③ uid 대표 계정만 조회하면 세션 귀속이 계정 id 에 묶여 있어 **청산 버튼이 오히려 사라진다**. 평가자가 독립 발견한 2건과 수렴, 3건은 평가자 미발견 |
