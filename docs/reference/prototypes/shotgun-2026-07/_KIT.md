## 0. 시작 절차 (반드시 이 순서)

```bash
cd docs/reference/prototypes/shotgun-2026-07
cp _kit.html screen-NN-이름.html      # 절대 처음부터 쓰지 않는다
```

1. `<title>` 치환
2. 사이드바 6개 `.nav-item` 중 현재 화면 하나에 `class="nav-item active"` + `aria-current="page"` 부여
3. 상단 `.crumbs` 치환

5. 화면 고유 CSS 는 **`PAGE-SPECIFIC` 마커 아래에만** 추가

**절대 금지.** 마커 위쪽 CSS(토큰·컴포넌트·반응형) 한 글자라도 수정. `preflight.py` 가 `_kit.html` 과 바이트 비교해서 잡아낸다.

### 4.0 이 절을 읽는 법 (증보분 4.1 ~ 4.10)

위쪽 §4 본문은 확정 캐논이다. **한 글자도 바꾸지 않는다.** 아래 4.1 ~ 4.10 은 교차 감사에서 "캐논에 없어서 화면마다 지어냈다" 로 잡힌 영역을 실측으로 메운 증보분이다.

세 가지 규칙만 지키면 새 화면은 기존 17벌과 충돌하지 않는다.

1. **여기 있는 값은 그대로 옮긴다.** 반올림·정규화·보기 좋게 고치기 전부 금지.
2. **여기 없는 값은 만들지 않는다.** 특히 4.9 인쇄 금지 목록에 걸린 것은 대체 문구를 쓴다.
3. **원장 화면이 다른 화면과 어긋나면 원장이 이긴다.** 원장 지정은 4.1 표에 있다.

각 절 끝의 `미해소` 표시는 17벌 사이에서 아직 값이 갈린 지점이다. 새 화면은 미해소 항목을 **다시 인쇄하지 않는 쪽**을 기본으로 한다. 꼭 필요하면 원장 쪽 값만 쓴다.

`해소됨` 표시는 그 반대다. 한때 값이 갈렸다가 화면 교정으로 정리된 지점이며, **지금 인용해도 되는 확정 값**이다. 폐기된 옛 값을 다시 쓰지 말라고 기록을 남겨 둔 것이므로 이전 값 쪽을 인용하지 않는다.

**증보분 갱신 이력.** 4.1 ~ 4.10 은 화면 교정 이전에 작성됐고, 그 뒤 화면들이 교정됐다. 이 판본은 교정 후 17벌을 실측해 다시 맞춘 것이다. 바뀐 곳은 4.1 원장 건수 · 4.3 미해소 → 해소됨 · 4.5 조합 표기 잔존 → 0건 · 4.6 전면 갱신(12건 → 14건) · 4.7 체결 표 열 이름 · 4.8 OKX 잔존 → 0건 및 연동 비율 KPI 폐기 · 4.10 표 헤더 축약 규약과 접근성 실측이다. **어긋나면 화면이 옳고 이 문서가 고칠 쪽이다.**

| 최대 동시 포지션 | `3`                        | 주문 재시도 정책   | `3회 · 지수 백오프`  |
| 현재 포지션      | `1`                        | 계정 모드          | `데모`               |
| 레버리지 상한    | `1배`                      | API 키             | `등록됨 · 읽기+주문` |
| 주문당 최대 명목 | `2,000.00`                 | 펀딩 반영          | `미반영`             |
| 킬 스위치        | `대기`                     | 체결 방식          | `시장가`             |

- 일일 손실 한도의 오늘 소진은 **순손익 기준**이다. 순손익이 플러스면 `0.00` 이고, 개별 손실 `-12.36` 만으로는 한도가 깎이지 않는다.
- 오늘 실현 `+38.55` = `+50.91` + `-12.36`. 최근 체결 표 합산과 일치한다.
- 주문 재시도(`3회 · 지수 백오프`)는 거래소 주문 전송 재시도다. 에러 화면의 HTTP 재시도(`30초 · Retry-After`)와 다른 개념이므로 섞지 않는다.

**세션 시작 이후 체결 5행** (코크핏 기준). 열 이름은 화면 그대로 9개다. `시각` · `심볼` · `방향` · `유형` · `수량` · `체결가` · `수수료` · `실현 손익` · `상태`. `구분` · `가격` · `실현` 로 줄여 쓰지 않는다.

| 시각             | 심볼     | 방향 | 유형 | 수량  | 체결가      | 수수료  | 실현 손익 | 상태 |
| ---------------- | -------- | ---- | ---- | ----- | ----------- | ------- | --------- | ---- |
| 2026-04-14 20:00 | BTC/USDT | 롱   | 진입 | 0.021 | `62,880.00` | `-0.73` | —         | 체결 |
| 2026-04-14 17:00 | SOL/USDT | 숏   | 청산 | 3.2   | `149.30`    | `-0.26` | `-12.36`  | 체결 |
| 2026-04-14 09:00 | BTC/USDT | 롱   | 청산 | 0.020 | `62,410.00` | `-0.69` | `+50.91`  | 체결 |
| 2026-04-13 22:00 | BTC/USDT | 롱   | 진입 | 0.020 | `59,797.00` | `-0.66` | —         | 체결 |
| 2026-04-13 15:00 | SOL/USDT | 숏   | 진입 | 3.2   | `145.60`    | `-0.26` | —         | 체결 |

- `상태` 열은 5행 모두 `체결` 이다. 이 표가 체결된 건만 담기 때문이며, 대기·전송·취소·거부까지 담는 주문 단위 원장은 screen-11 이고 건수가 다르다.
- 실현 손익 무데이터 3셀의 `title` 은 두 종류다. 열려 있는 포지션 = `아직 열려 있는 포지션이라 실현 손익이 없습니다.` / 진입 체결 = `진입 체결에는 실현 손익이 없습니다. 위 (청산 시각) 청산 행에 합산되어 있습니다.`
- `방향` 은 포지션 방향 `롱` / `숏`(`.side.long` / `.side.short`)이다. 주문 원장의 주문 방향 `매수` / `매도` 와 다른 필드다. 두 표의 대응은 4.6 의 1대1 대응표를 따른다.

코크핏은 체결을 **봉 시각**으로 적고(`20:00`), 주문 원장은 **주문 시각**으로 적는다(`20:00:04`). 같은 체결이며 어긋난 것이 아니다.

**킬 스위치 용어.** 상태 이름은 `킬 스위치`, 실행 버튼 라벨은 `긴급 정지` 다(`긴급 정지는 모든 포지션 시장가 청산 후 세션 중지. 되돌릴 수 없습니다.`). 새 화면도 이 배치를 그대로 따른다.

**에러 상태 엔드포인트.** 코크핏 = `GET /trading/sessions/sess_8d14/positions · 503`. 주문 원장 = `GET /orders?limit=200 · 500`.

### 4.8 거래소 지원 현황 (앱 화면과 마케팅 화면의 상한이 다르다)

**앱 화면(screen-01 ~ 13)의 상한.** 언급 가능한 거래소는 **Bybit 하나뿐**이다. OKX · Binance · Bitget 을 앱 화면 어디에도 쓰지 않는다. 거래소 선택 필드는 고정값이고 힌트 문구는 `현재 연결된 거래소는 Bybit 하나입니다.` 계열을 쓴다. Bybit 메인넷은 **주문 0건 빈 상태로만** 등장하며, 라이브 체결이 있었다고 말하지 않는다.

**마케팅 화면(screen-14 · 16 · 17)의 상한.** 아래 5행 표를 그대로 쓴다.

| 거래소  | 환경   | 상태   | 확인한 범위           |
| ------- | ------ | ------ | --------------------- |
| Bybit   | 데모   | 지원   | 주문 · 포지션 · TP/SL |
| Bybit   | 메인넷 | 지원   | 주문 · 포지션 · TP/SL |
| OKX     | —      | 로드맵 | —                     |
| Binance | —      | 로드맵 | —                     |
| Bitget  | —      | 로드맵 | —                     |

- **OKX 는 로드맵이다.** "연결해 본 거래소" 목록에 넣지 않는다. 이전 판본에서 `screen-16-pricing.html` 에 위반이 잔존했으나 교정됐다. 지금 screen-16 은 OKX 를 3곳에서 언급하되 전부 로드맵 쪽이며, 본문에 `연결해 본 거래소는 Bybit (데모 · 메인넷) 하나입니다. OKX 와 Binance 와 Bitget 은 로드맵이며 아직 연결하지 않았습니다.` 를 인쇄한다.
- 로드맵 행은 환경과 확인 범위를 무데이터 `—` 로 비운다. `title` 은 `연결 작업을 시작하지 않아 환경을 정하지 않았습니다.` / `연결 코드가 없어 확인한 범위가 없습니다.` 를 쓴다. 셀 클래스도 고정이다. 환경 `mono-l dim` / 확인 범위 `dim`.
- 표에 `<caption>` 을 둔다. 문구는 `로드맵 행은 연결 코드가 없어 빈 값으로 둡니다.` 다.
- 표와 함께 **두 문장을 모두** 둔다. `표에 없는 거래소는 지원하지 않습니다.` 와 `로드맵은 순서를 정해 두었다는 뜻이고, 착수일이나 완료일을 약속하는 말이 아닙니다.` 실제 인쇄 문구는 뒤에 `날짜를 정하면 이 표에 그대로 적겠습니다.` 까지 붙은 3문장이며 screen-14 `.sup-note` 와 screen-17 `.disclaimer` 가 같은 문자열을 쓴다.
- 표기는 한글로 통일한다. 열 이름 `환경`, 값 `데모` / `메인넷`. `모드` 라는 열 이름과 `Demo` / `Mainnet` 영문 표기를 쓰지 않는다. 본문 산문도 같다. `Bybit 데모 · Bybit 메인넷` 처럼 거래소 고유명사만 영문으로 남긴다.
- **연동 완료 비율 KPI(`2 / 5` = `40%`)는 폐기됐다. 다시 만들지 않는다.** 착수도 하지 않은 로드맵 3행을 분모에 넣은 진행률이라, 같은 카드가 인쇄하는 "로드맵은 착수일이나 완료일을 약속하는 말이 아닙니다" 와 정면으로 어긋났다. screen-14 에서 실제로 제거했고 그 근거를 해당 화면 NUMBERS AUDIT 에 남겼다. 지원 현황을 수로 요약해야 하면 비율 대신 표 5행을 그대로 읽게 둔다.

**성능 주장은 조건과 함께만 쓴다.** 인쇄 가능한 값은 3개뿐이다. `20,064`(BTC/USDT 1h 봉 수, 836일 구간) / `3.24초`(run_2f9c41 백테스트 1회, 로컬 실행 기준) / `6,193`(초당 처리 봉 수, 20,064 / 3.24). 반드시 `로컬 개발 환경에서 한 번 측정한 결과입니다. 다른 환경의 속도는 측정하지 않았고 보장하지도 않습니다.` 를 함께 둔다. 조건 없는 속도 형용사는 금지다.

**공개 상태 문구는 축이 두 개다.** 판매 축 = `공개 판매하지 않습니다` · `사용자 1명 (woosung)` · 가격 `미정`. 공개 축 = `공개 서비스가 아닙니다` · `공개 시점 미정` · `지금은 가입을 받지 않습니다`. 새 화면은 자기 맥락의 축 하나만 쓰고 날짜를 지어내지 않는다.

**Pine 전체 거부 정책** (ADR-003). 문구는 화면마다 다르게 풀어써도 되지만 내용은 하나다. `미지원 함수가 하나라도 있으면 부분 실행 없이 전체를 지원되지 않음으로 처리한다.`

**미해소 1건 (사람 결정 필요).** 프로토타입 캐논은 Bybit 단일이지만 실제 코드는 OKX 데모를 폼 스키마에 갖고 있다. 프로토타입 세트 안에서는 위 표가 SSOT 이고, React 이식 시점에 "OKX 데모로 실제 주문이 오갔는가" 를 실측해 캐논을 갱신할지 결정한다. 프로토타입에서 미리 OKX 를 지원으로 올리지 않는다.

### 4.9 ★인쇄 금지 목록. 데이터 모델에 없어서 만들면 안 되는 값

아래는 서버 응답에 대응 필드가 없다. **화면에 그리는 순간 가짜 데이터다.** 왼쪽을 쓰지 말고 오른쪽 문구를 그대로 쓴다.

| 인쇄 금지                                   | 대신 쓰는 문구                                                                                    |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 대기열 순번 · 큐 위치                       | `시작 시각이 아직 없습니다. 대기열 순번은 서버가 보고하지 않습니다.`                              |
| 최적화 진행률 · 진행 미터                   | `최적화는 서버가 진행률을 보고하지 않아 미터를 그리지 않습니다.`                                  |
| 남은 시간 · ETA · 카운트다운                | `실행 중 작업의 남은 시간은 표시하지 않습니다. 서버가 진행 회차를 아직 보고하지 않기 때문입니다.` |
| 현재 평가 회차 · 중간 최고값                | `실행이 끝나야 결과가 저장됩니다. 서버는 중간 최고값을 보고하지 않습니다.`                        |
| 실행 중 백테스트의 처리 봉 수               | 진행률 퍼센트와 시작 시각만 쓴다. 봉 수를 만들지 않는다.                                          |
| 대기자 수 · 등록 순번 · 예상 공개일         | 집계 자체가 없다. `미정` 으로 둔다.                                                               |
| 미완료 실행의 수익률 · MDD · 샤프 · 거래 수 | 4.3 표의 상태별 무데이터 `title` 문구를 쓴다.                                                     |
| 거래 0건 셀의 샤프 · 순위                   | `거래가 0건이라 샤프 지수를 계산할 표본이 없습니다.`                                              |

**추가 금지 3종.**

- **맥동 점 · 블링크 · 가짜 라이브 인디케이터.** 갱신 로직이 없는 화면에서 살아 있는 척하지 않는다. 무한 반복 애니메이션은 스켈레톤 `shimmer` 하나뿐이다.
- **`aria-live` 로 흘려보내는 가짜 수치.** 미터는 완료된 정적 비율이며 기준을 함께 인쇄한다.
- **원시 enum 노출.** `buy` `filled` `grid_search` `is_degenerate` `reduce_only` `broker_order_id` `skipped_count` 를 텍스트로 인쇄하지 않는다. 예외는 Pine 파라미터 식별자(`fastLength` · `slowLength`) 뿐이며 이것은 코드 심볼이라 유지한다.

**예외 판정 기준.** 실행 중 백테스트의 진행률 퍼센트(`18%`)와 경과 시간(`15분 경과`)은 인쇄한다. 진행률은 백테스트 원장이 실제로 보고하는 값이고, 경과 시간은 시작 시각과 기준 시각 `2026-04-14 21:07 KST` 의 차이일 뿐이며 화면이 그 사실을 함께 밝히기 때문이다. **최적화 실행에는 진행률이 없다.** 두 도메인을 같은 규칙으로 다루지 않는다.

| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| 정렬 버튼이 있는 헤더          | `<th scope="col" class="num" aria-sort="none"><button class="th-sort" aria-label="최대 낙폭 기준 정렬">MDD …</button></th>`    | `screen-03`(원장). `th-sort` 5개 |
| 정렬 없는 정적 헤더            | `<th scope="col" class="num" aria-label="최대 낙폭">MDD</th>` · `<th scope="col" class="num" aria-label="샤프 지수">샤프</th>` | `screen-06`(원장)                |
| 축약하지 않고 전체를 쓰는 헤더 | `<th scope="col" class="num" abbr="MDD">최대 낙폭</th>`                                                                        | `screen-02` 1건                  |

축약 헤더를 쓰는 화면은 **`screen-03` 과 `screen-06` 둘뿐이다.** `screen-09` · `screen-10` 은 표 헤더에 `th-sort` 가 0개이고 축약 헤더도 쓰지 않는다. 두 화면의 정렬·페이지 크기 토글은 표 밖의 `role="group"` 컨트롤이라 이 규약의 대상이 아니다.

- **`abbr` 속성은 축약의 주 수단이 아니다.** 17벌 실측 결과 마크업의 `abbr` 속성은 `screen-02` 의 `abbr="MDD"` **1건뿐**이고(같은 파일 NUMBERS AUDIT 주석이 이 속성을 인용한 1건은 마크업이 아니다), 그 헤더는 가시 텍스트가 이미 `최대 낙폭` 전체라서 축약형을 보조로 단 경우다. **`abbr="샤프"` 는 17벌에 0건이다.** 이전 판본이 지정했던 `<th abbr="샤프">샤프 지수</th>` 형태는 어느 화면도 쓰지 않으므로 폐기한다.
- 정렬 버튼 헤더의 접근 이름에는 `기준 정렬` 을 붙인다. 정적 헤더에는 붙이지 않는다. 존재하지 않는 정렬 어포던스를 암시하지 않기 위해서다.
- 축약해도 되는 이름은 `MDD` 와 `샤프` 두 개뿐이다. `수익률` · `거래 수` 같은 다른 열은 축약하지 않는다.
- **표 헤더 밖의 좁은 라벨도 같은 규약을 쓴다.** `screen-02` 는 전략 성과 카드에서 `<span class="k">샤프</span>` + 값 `1.84` 형태로 축약 라벨을 4번 쓴다(`.perf-figure .k`). 값과 라벨이 세로로 붙는 좁은 칸이라 축약이 허용되는 자리이며, 같은 카드의 짝 라벨은 축약하지 않은 `최근 수익률` 이다. 반면 같은 화면의 표 헤더는 `최대 낙폭` 전체를 쓴다. **좁은 칸이면 축약, 표 헤더·산문이면 전체** 가 판정 기준이다.
- 어느 경우든 **가시 텍스트를 바꿔 열 폭을 흔들지 않는다.** 접근 이름만 더한다.

**동명이의 필드는 이름을 나눈다.** 포지션의 `수익률`(진입가 대비 등락률) · 거래의 `실현 수익률`(비용 차감 후) · 거래 목록의 `변동률`(비용 제외) · 전략의 `최근 수익률`(최근 완료 실행 1건) · 실행의 `총 수익률`. 다섯은 서로 다른 값이므로 한 화면에서 같은 이름으로 부르지 않는다.

**페이지 이름 5축 일치.** nav `aria-label` · `<title>` · breadcrumb · `h1` · 푸터가 같은 단어를 써야 한다. 상세 화면에서 `h1` 만 대상 이름으로 바꾸는 것은 허용하되 나머지 4축은 도메인명을 유지한다.

**접근성.** `role="tablist"` 는 `role="tabpanel"` 이 실제로 있을 때만 쓴다. 페이지 크기 · 기간 · 정렬 · 상태 필터 · 인증 방식처럼 패널을 바꾸지 않는 상호배타 토글은 `role="group"` + `aria-pressed` 를 쓴다.

- 실측 결과 `role="tablist"` 는 17벌에서 `screen-08-strategy-editor.html` **1건뿐**이고, 그 화면은 `role="tabpanel"` 을 3개(`panel-parse` · `panel-param` · `panel-ind`) 실제로 갖고 있어 적법하다. 이전 판본에서 오용이던 `screen-02` 기간 토글, `screen-03` · `screen-09` 페이지당 개수, `screen-10` 정렬 기준, `screen-15` 인증 방식은 전부 `role="group"` + `aria-pressed` 로 교정됐다.
- 토글 상태를 바꾸는 **스크립트도 함께 고친다.** `setAttribute('aria-selected', …)` 를 남겨 두면 마크업에서 지운 속성을 스크립트가 다시 심어 역행한다. `aria-pressed` 토글로 바꾼다.
- `aria-controls` 는 대상이 `tabpanel` 일 때만 쓴다. `screen-15` 의 대상은 `<form id="auth-form">` 이라 tab→tabpanel 관계가 성립하지 않아 함께 제거했다.
- 공용 CSS 는 `.tab.active` 클래스만 쓰고 `[aria-selected]` 같은 속성 선택자를 쓰지 않는다. 따라서 이 교체는 **시각 결과를 바꾸지 않는다.** 활성 표시는 `.active` 클래스가 계속 담당한다.

## 6. 상태 4종 배치 지침

모든 제품 화면은 4종을 **실제로 렌더**한다. 억지로 끼우지 말고 그 화면에서 자연스러운 자리에 둔다.

- **스켈레톤** — 아직 계산 중인 패널 하나(`.sk` + `aria-busy="true"` + `.state-note` 로 예상 시간)
- **에러** — `role="alert"` + `.state-box.failed` + `.state-code` 에 `GET /엔드포인트 · 503` 형식 + `다시 시도` 버튼
- **빈 상태** — `.state-box` + 왜 비었는지 + 다음 행동 버튼
- **무데이터 셀** — 표/KPI 안에서 값이 `—` 하나뿐인 셀 + `title` 속성으로 이유 설명

에러 상태의 엔드포인트는 **그 화면에서 실제로 부를 법한 경로**여야 한다(예: 트레이딩이면 `/trading/sessions/sess_8d14/positions`).
