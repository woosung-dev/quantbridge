## 2. ★측정이 뒤집은 전제 — 반드시 읽어라

이식 계획을 세우기 전에 **실측**했고, 사용자와 내가 인터뷰 시점에 공유하던 전제 하나가 틀렸다.

### 색 대조 — 22종 중 5종 불일치

> ★이 절은 2026-07-20 후속 세션이 **재실측해 정정한 값**이다. 초판은 불투명 hex 14종만 세고 rgba 틴트를 빠뜨려 "1건 불일치 · 2줄이면 끝"이라고 적었다. **틀렸다.**

프로토타입 토큰 **22종**(불투명 17 + rgba 틴트 5)을 앱 `.dark` 블록과 1:1 대조한 결과 **일치 17 / 불일치 5**다.

| 프로토타입      | 앱 토큰            | 프로토타입 값           | 앱 값                   |
| --------------- | ------------------ | ----------------------- | ----------------------- |
| `--ink-3`       | `--text-muted`     | `#8b939c`               | `#7a828c`               |
| `--copper-soft` | `--primary-light`  | `rgba(240,140,46,0.12)` | `rgba(240,140,46,0.1)`  |
| `--copper-line` | `--primary-100`    | `rgba(240,140,46,0.3)`  | `rgba(240,140,46,0.2)`  |
| `--bull-soft`   | `--success-subtle` | `rgba(45,212,167,0.12)` | `rgba(52,211,153,0.12)` |
| `--warn-soft`   | `--warning-subtle` | `rgba(229,169,61,0.1)`  | `rgba(229,169,61,0.12)` |

**`--bull-soft` 는 앱 내부 모순이기도 하다.** `--success-subtle` 이 `rgb(52,211,153)` = `--success #34d399` 에서 파생됐는데, 정작 그 화면이 쓰는 강조색은 `--bullish #2dd4a7` 다. 자기 색이 아닌 이웃 토큰에서 틴트를 뽑았다.

수정 규모는 **2줄이 아니라 6줄**이다(`globals.css` 5 + `brand-palette.ts` 1).

나머지 17종은 hex 레벨에서 완전 일치하고, `@theme inline`(`src/styles/globals.css`) 구조 덕에 **값만 바꾸면 토큰 소비 파일 191개가 코드 수정 없이 자동 반영**된다.

**파일 경로 주의.** `src/styles/globals.css` 다. `src/app/globals.css` 는 **존재하지 않는다.** 이 문서의 모든 좌표는 전자 기준이다.

### 4.2 셸

- 5파일 **416줄**, 이미 잘 분리돼 있어 리라이트 비용이 낮다.
- **활성 nav 6개가 프로토타입 6개와 정확히 일치.** 항목 재정의 불필요.
- 초과분 2개(`/templates`, `/exchanges`)는 둘 다 `disabled: true`. **거취 결정 필요** (프로토타입에 없음).
- `md`(768) / `lg`(1024) 브레이크포인트 픽셀값이 이미 프로토타입과 일치. 햄버거 768px 도 일치.
- **nav-count 배지는 데이터 소스 자체가 없다.** 신설하려면 훅/API 부터 만들어야 한다.

### 4.3 하드코딩 hex = 실질 8건(5파일)

`brand-palette.ts` 38건은 의도된 SSOT 라 정당하다. 진짜 문제는 8건이고, **그중 4건이 P1 `/trading` 안에 있다.**

- `trading-dash-hero.tsx:100-102` — `#EFF6FF` `#D1FAE5` `#FEE2E2` (Tailwind 팔레트 잔재, **다크에서 대비 붕괴**)
- `kill-switch-banner.tsx:46` — `#FEE2E2` (동일)
- `layout.tsx:23,24` · auth 2곳 — theme-color / Clerk appearance 주입용

`components/monaco/pine-language.ts` hex 11건은 `brand-palette.ts` 를 **import 하지 않고 자체 보유**해 desync 위험이 있다.

### 4.4 차트

- **색상이 `lib/chart-tokens.ts` 단일 게이트웨이로 완전 중앙화.** 16개 차트 파일 중 색 하드코딩 0건.
- 라이브러리 2종 병용 — `lightweight-charts` 11파일 + `recharts` 5파일. 스타일 API 가 달라 **두 경로를 각각 검증**해야 한다.
- `chart-tokens.ts:3-4` 에 제약이 명시돼 있다. lightweight-charts 는 `var()` 문자열을 못 읽어서 `getComputedStyle` 로 해석한 hex 를 넘겨야 한다.

### 4.5 테스트 / CI

- 단위 **155개**(41 ts + 114 tsx), E2E **11 spec / 42 케이스**.
- CI 프론트 게이트 5단계 — 훅 규칙 grep / `pnpm lint` / `tsc --noEmit` / `pnpm test` / `pnpm build`.
- **PR CI 는 E2E 3케이스(`smoke.spec.ts`)만 돌린다.** authed 39케이스는 게이트 밖이라 셸·네비 회귀를 CI 가 못 잡는다. 로컬 `pnpm e2e:authed` 수동 실행 필요.
- **프론트엔드 커버리지 임계 없음** — 리디자인 중 테스트를 지워도 CI 가 침묵한다.

## 6. 하드 제약 (프로토타입에서 확립. 이식에도 그대로 적용)

`_KIT.md` §1 이 정본이다. 요약하면

1. 노출 카피 em-dash / en-dash **0건**. HTML 엔티티(`&mdash;` `&ndash;`)까지 검사. **단 값이 오직 `—` 하나인 셀은 "데이터 없음" 관례로 허용**
2. 대비 최소 `#8b939c`(5.83:1). `#565d66`(2.92:1) 텍스트 금지
3. `outline: none` 금지. 쓰면 `:focus-visible` 이 특이도·소스순서 양쪽에서 이기는지 확인. 컨테이너는 `:focus-within`
4. `display:none` 으로 라벨이 사라지는 구간엔 `aria-label` 필수
5. **숫자는 검산이 맞아야 한다.** 공식을 인쇄했으면 그대로 나와야 한다
6. 차트 축은 선형이고 픽셀이 표기값과 일치
7. 엔진은 `pine_v2 · 바 단위 이벤트 루프`. **"벡터화" 금지**(ADR-011)
8. 사용자는 실제 `woosung`. 가공 인물·가짜 알림 배지·가짜 라이브 점 금지
9. 상태 4종을 실제로 그린다 — 스켈레톤 / 에러(`role="alert"` + 실제 엔드포인트 + HTTP 코드 + 재시도) / 빈 상태 / 무데이터 셀
10. `prefers-reduced-motion` 에서 모션 무력화. 주 데이터를 1초 넘게 가리는 애니메이션 금지
11. 반경은 `var(--r)` 하나
12. 무한 반복 애니메이션은 스켈레톤 shimmer 하나뿐. **펄스·블링크 금지**
13. 375px 에서 페이지 가로 스크롤 0

## 7. ★검사 장치 — React 용은 새로 만들어야 한다

> ★정정. 초판은 "React 에 그대로 못 쓴다"고 했으나 **과했다.** 후속 세션 실측 결과 `runtime-check.mjs` 는 이미 Playwright 기반이고 핵심 로직이 `page.evaluate` 안의 **URL 무관 순수 함수**다. HTML 전용인 부분은 파일 탐색 · `pathToFileURL` · 인증 셋뿐이라 **재조준하면 된다.** 새로 만들지 마라 — 이미 캘리브레이션된 임계값을 물려받는 것이 가장 큰 이점이다.

진짜 대체가 필요한 건 **차트 축 검사 하나**다. P1 차트가 둘 다 캔버스라 픽셀 측정이 불가능하므로 축 선형성 대신 `priceScale.mode` 설정 고정으로 바꾼다. BL-407 이 정확히 그 부류 버그였으니 회귀 가치는 실증돼 있다.

`preflight.py` 는 단일 HTML 전용이 맞다. 검사 항목과 임계값은 이식할 가치가 있다.

이번 세션에서 이 두 도구가 잡아낸 것들이 근거다.

- 대비를 **배경 합성 후 실제 렌더값**으로 계산 (단순 hex 비교로는 못 잡음)
- 포커스 링을 **실제 Tab 30회 이동**으로 검증
- 차트 y축 **라벨↔픽셀 공선성**(1.6px 이내)
- 공용 CSS **바이트 무결성** (드리프트 원천 차단)

React 이식 시 대응 방안 후보 — 계획 단계에서 정하라.

- 기존 Playwright E2E 에 대비/포커스 검사를 붙인다 (시각 스냅샷 baseline 이 0개라 자유도가 높다)
- `getComputedStyle` 기반 런타임 검사를 E2E 픽스처로
- 반경/색 토큰 이탈은 **ESLint 규칙 또는 단위 테스트**로 (이미 `no-internal-ids.test.ts` 가 카피 가드 선례)

## 8. 함정 (전부 이번 세션에서 실제로 데인 것)

1. **검사기를 만들면 known-good 산출물에 먼저 돌려라.** 이번에 검사기 자체 버그 4개를 그렇게 잡았다. 안 했으면 빌더 17명의 시간을 태웠다.
2. **grep 만으로 판정하지 마라.** 이번 세션에서 **3번** 오탐했고 전부 **주석 안의 교정 기록**이었다. 주석을 공백 치환한 뒤 노출 마크업만 검사해야 한다.
3. **에이전트 자기보고를 믿지 마라.** "반경 단일"이라며 8종, "순백 0건"이라며 주석에 존재한 사례가 있었다. 판정은 명령 출력에 걸어라.
4. **워크플로 에이전트가 failed 로 떠도 파일은 이미 있을 수 있다.** 이번에 한도 초과로 죽은 2개 에이전트의 산출물이 **완성 상태로 생존**해 재작성을 피했다. 재실행 전 산출 디렉터리부터 확인하라.
5. **파일 단위 검증 통과 ≠ 전체 정합.** 17벌이 개별 통과한 뒤 교차 감사에서 49건(BLOCKER 3)이 나왔다. **정직성 규율은 파일 경계에서 샌다** — 화면 A 가 "이 값은 지어내지 않는다"고 적고 화면 B 가 그 값을 인쇄한 사례가 3건이었다. React 에서는 **컴포넌트 경계**에서 같은 일이 일어난다.
6. **검증 환경이 실사용보다 깨끗하면 stale 을 놓친다.** 뷰어 검증이 매번 새 브라우저 컨텍스트를 띄워 통과했는데 사용자 브라우저에서는 캐시로 구버전이었다.

## 8.5 라이트 테마 — 캐논 검사 대상에 포함하기로 결정 (2026-07-20)

후속 세션이 "라이트는 캐논 검사에서 빼고 아무도 책임지지 않는 상태로 남긴다"고 판단했으나 **뒤집었다.**
기록만 남기고 넘어가면 **아는 결함을 방치**하는 것이고, 이 제품이 파는 것이 신뢰다.

### 도출한 라이트 팔레트 (2차 · 상호 분리도 제약 추가)

> ★1차 도출본은 **폐기했다.** 각 색을 배경 대비만 보고 독립 최적화한 결과 `--bull` 과 `--bear` 의

> 이익/손실이 구분되지 않는다. 색각이상 시뮬레이션에서 다크 대비 deutan 44% · protan 62% 분리도 악화.
> **캐논을 통과하면서도 나쁜 팔레트**였다. 2차는 상호 분리도를 제약에 명시적으로 넣었다.

### ★검사기에 캐논 등급 추가 + 캘리브레이션

`runtime-check.mjs` 가 **WCAG AA 4.5 하나만** 임계로 쓰고 있었다. 그래서 4.5~5.83 구간 미달이 조용히 통과했다.
실제로 라이트 1차본이 그 구간에 **26건**을 숨긴 채 PASS 2/2 를 받았다.

두 가지를 고쳤다.

1. **배경 상수 제거.** `bgOf()` 가 다크 `#0b0d0f` 를 상수로 갖고 있어 라이트 대비가 전부 뒤집혀 계산됐다. `body` 계산값에서 읽는다.
2. **canon 등급 신설.** AA 4.5 와 별도로 캐논 미달을 센다.

**캐논 임계는 5.83 이 아니라 `5.82` 다.** 실제 정의값이 `#8b939c` on `#141619` = **5.827427** 이고,
문서의 "5.83" 은 반올림 표기다. 5.83 을 임계로 쓰면 **캐논을 정의하는 토큰 자신이 걸린다**(실제로 그렇게 됐다).

**canon 은 하드 실패가 아니라 지표다.** 캐논은 "카드 위" 기준이고 `--card-2`(5.44) · `--card-3`(5.15) 같은
중첩 표면에서는 다크 정본도 원래 내려간다. 하드 실패로 쓰면 다크 17벌이 전부 깨져 게이트가 무의미해진다.
**판정 기준은 "라이트가 다크 짝보다 나쁘지 않은가" 라는 상대 비교다.**

실측 결과 라이트가 다크보다 **좋다.**

| 화면   | 다크 canon | 라이트 canon |
| ------ | ---------- | ------------ |
| 리포트 | 33         | **13**       |
| 코크핏 | 41         | **13**       |

회귀 확인. 검사기 수정 후 **다크 17벌 17/17 PASS · preflight FAIL 0** 유지.

> ★★**정정 2026-08-07 (backtest-fidelity).** 위 「17/17」은 `fcc36bf7`(2026-07-26 docs 재편) 이후

### 부수 발견 — 표의 손익 색이 두 테마 모두 죽어 있다

라이트 작업이 드러낸 **선행 결함**이다. 라이트가 만든 것이 아니다.

```css
table.trades tbody td.num {
  color: var(--ink);
} /* 명시도 0,2,3 */
.pos {
  color: var(--bull);
} /* 명시도 0,1,0 — 항상 진다 */
```

`<td class="num pos">+14.22</td>` 가 `.pos` 를 달고 있는데 공용 CSS 명시도에 밀려 색이 죽는다.
브라우저 실측으로 다크·라이트 양쪽에서 `--ink` 로 렌더됨을 확인했다.
프로토타입에서는 고치지 않았다 — 명시도를 손대면 diff 가 토큰 밖으로 번져 "토큰만 바꿨다"는 검증 가치가 사라진다.
**이식 시 `td.num.pos` / `td.num.neg` 규칙을 추가하거나 `td.num` 의 `color` 선언을 걷어내야 한다. 두 테마 동시 반영.**

> ★**해결됨 (실측 2026-08-07).** React 이식본은 이미 반영했다 — `globals.css:1653-1654`(레이어드
> `table.trades tbody td.num.pos`, 명시도 `0,3,3`) + `:2700-2701`(언레이어드 중복)이 `td.num`(`:1645`)을
> 이긴다. **이 절을 미해결 TODO 로 읽지 마라.** 남은 구멍은 다른 것이다 — `.pos`/`.neg` **단독**
> (`.num` 없이)은 여전히 `td` 색에 진다(**[BL-630]**).
> 고친 뒤에도 라이트 팔레트는 안전하다(`--bull` on card 9.99 · hover 표면에서도 캐논 위).

### ★미해결 — 라이트 팔레트 트릴레마 (선택 대기)

라이트에서 아래 넷을 **동시에 만족할 수 없다.** 구조적 제약이고 도출 실력의 문제가 아니다.

|                     | ① 캐논 5.82 | ② bull/bear 상호 1.57 | ③ 단일색(일관성) | ④ 생동감             |
| ------------------- | ----------- | --------------------- | ---------------- | -------------------- |
| **A** (현재 적용됨) | ✅          | ✅                    | ❌ ΔE 25~32      | ✅                   |
| **B1**              | ✅          | ❌ 1.01               | ✅               | ✅                   |
| **B2**              | ✅          | ✅                    | ✅               | ❌ 초록 9.99 로 탁함 |

각 안의 실제 값.

```
A  텍스트 copper #883e07 · bull #074b34 · bear #ad322a
   채움   copper #d06c0f · bull #1f9878 · bear #f4483c   ← 지금 파일에 적용된 상태
B1 단일   copper #934c0b · bull #166b54 · bear #bd160b   (상호 1.01)
B2 단일   copper #883e07 · bull #074b34 · bear #ad322a   (상호 1.58, A 의 텍스트값)
```

**"중간에서 만나기"(C)는 존재하지 않는다.** 캐논 5.82 를 만족하는 색은 채움 기준 3.0 도 자동으로 넘으므로
ΔE 최소화의 최적해가 항상 "같은 색 하나"로 붕괴한다. C 는 B 와 같은 안이다.

**포기의 대가.**

- ② 포기(B1) = 색각이상 사용자가 롱/숏과 이익/손실을 구분하지 못한다. money-path 화면이라 무게가 크다.
- ③ 포기(A) = 같은 의미색이 두 색으로 보인다. `design-taste-frontend` §4.2 COLOR CONSISTENCY LOCK 위반.
- ④ 포기(B2) = 사용자가 직접 보고 "탁하다"고 지적한 상태.

> ★★★**결정됨 (2026-08-07 backtest-fidelity, 사용자 승인).** **앱은 B2 다** —
> `globals.css` `:root` + `brand-palette.ts` 를 같은 커밋에서 교체했다. 아래 「현재 파일은 A 다」와
> 「다음 세션 권고 … 사용자가 고르게 한다」는 **프로토타입 파일 기준의 옛 서술**이다.
> ★그리고 그 선택의 실제 효과는 트릴레마 표가 말하는 것과 달랐다 — 앱을 재 보니 구팔레트 라이트가
> **WCAG AA 미달을 대량으로 싣고 배포 중**이었고 B2 가 그것을 없앴다. **B2 는 심미 트레이드오프가
> 아니라 접근성 수리였다**(전문 = `git show 8abd0d67:docs/dev-log/2026-08-07-backtest-fidelity.md` §3.2
> — 2026-08-13 docs-diet 로 본문은 git 에만 있다).

**현재 파일은 A 다.** 되돌리기 쉬운 쪽을 택했다. 텍스트 토큰은 A 와 B2 가 동일하므로
B2 로 가려면 `--copper-fill` / `--bull-fill` / `--bear-fill` 3줄을 지우고 참조를 텍스트 토큰으로 되돌리면 된다.

**다음 세션 권고.** A · B1 · B2 를 각각 프로토타입으로 만들어 뷰어에서 나란히 놓고 사용자가 고르게 한다.
숫자로는 판정이 끝났고 남은 것은 제품 판단이다.

## 10. 레포 상태 주의

**프로토타입 전체가 아직 untracked 이고 현재 브랜치가 `main` 이다.**

```
?? docs/reference/design/prototypes/shotgun-2026-07/
?? skills-lock.json
```

프로젝트 규칙상 **main 직접 커밋·푸시는 영구 차단**이다. 머지 전략은 `stage/<theme>` 경유 + **사용자가 stage→main 을 수동 처리**하는 것이 이 프로젝트의 기본값이다.

### ★이식 브랜치는 반드시 `stage/` 접두사를 써라

`.github/workflows/ci.yml` 의 트리거가 이렇다.

```yaml
on:
  pull_request:
    branches: [main, "stage/**"]
```

**base 가 `main` 이거나 `stage/**`인 PR 에서만 CI 가 발화한다.** 그 밖의 브랜치로 PR 을 올리면 lint·tsc·test·build 게이트가 **통째로 침묵한다.**
앱 코드를 바꾸는 이식 작업에서 이건 위험하다. 이식 브랜치는`stage/c-language-port` 처럼 잡거나 base 를 main 으로 두어라.

(프로토타입 커밋은 `docs/` + `skills-lock.json` 뿐이라 path 필터 `frontend/**`·`backend/**` 에도 안 걸려 CI 가 필요 없었다. 이식은 다르다.)
