# Step 3: PRD §5 의 속도 지표를 **잴 수 있는 정의**로 재기술한다

## 읽어야 할 파일

- `docs/PRD.md` §5 「성공 지표」 표 (77~90행 부근) — 고칠 대상
- `apps/api/tests/fixtures/pine_corpus_v2/execution_speed_baseline.json` — **step0 산출**. 옮겨 적을 숫자
- `apps/api/tests/fixtures/pine_corpus_v2/execution_stage_breakdown.json` — **step1 산출**
- `apps/api/tests/fixtures/pine_corpus_v2/execution_hotspots.json` — **step2 산출**
- `docs/lessons.md` 434행 `LESSON-128` — 카드 형식의 정본. **다음 번호는 `LESSON-129`** 다

## 배경 — 무엇이 틀렸나

`docs/PRD.md` §5 는 이렇게 적혀 있다:

```
| 단일 심볼 1Y/1H 백테스트 | < 10초 |
```

**세 겹으로 틀렸다:**

1. **근거가 없다** — `git log -S` 추적 결과 이 숫자의 출처는 `89ff1d4e`(초기 프로젝트 설정 커밋)이고
   유도 과정이 어느 문서에도 없다
2. **잴 수단이 없다** — 프로즌 코퍼스는 **6개월(4,368 bar)** 이다. 1Y 데이터가 레포에 없다
3. **정의가 성립하지 않는다** — 전략 간 **18배** 편차가 실측됐다(step0). 「전략 무관 단일 숫자」로는
   같은 제품이 통과와 실패를 동시에 낸다

PRD 자신이 이미 같은 병을 한 줄 위에서 진단해 뒀다 — 「백테스트 정확도」 줄은 **대조군이 사라져
측정 불가**가 됐고 취소선 처리돼 있다. **그 줄의 형식을 그대로 따라라.**

## 작업

### 1. PRD §5 표의 해당 줄을 재기술

기존 줄을 **지우지 말고** 취소선 + 새 사실로 바꾼다(이 레포의 원장 관례):

```
| ~~단일 심볼 1Y/1H 백테스트~~ | ★<날짜> 재기술 — <이유 한 줄> |
| 백테스트 처리량 (6M/1H corpus, `run_backtest_v2`) | <새 정의> |
```

새 정의에 **반드시 담을 것 넷**:

- **`bar/s` 단위** — 데이터 길이에 불변한 지표다
- **실측 범위** — 가장 느린 corpus 와 가장 빠른 corpus 의 값을 **둘 다** 적어라.
  하나만 적으면 18배 편차가 다시 숨는다
- **측정 방법의 경로** — `apps/api/tests/strategy/pine_v2/test_execution_speed.py`.
  숫자만 적고 재는 법을 안 적으면 다음 사람이 또 못 잰다
- **1Y 환산치는 `[가정]` 으로 표기** — 6M 실측의 선형 외삽이고 실측이 아니다

★**「달성/미달」 판정을 여기서 내리지 마라.** 목표선을 새로 정하는 것은 **사용자 결정**이다.
이 step 이 하는 일은 「현재 값은 이것이고, 이렇게 재면 된다」까지다.

### 2. `docs/lessons.md` 에 `LESSON-129` 추가

`LESSON-128`(434행)의 항목 구조를 그대로 따른다 — **상황 / 사슬 / 반증 / 무엇이 갈랐나 / 해결**.
반증의 핵심은 이것이다:

> **PRD §5 는 6줄 중 하나도 잰 적이 없었고, 재려고 하자 지표 자신의 정의가 성립하지 않았다.**
> 목표를 적어 두는 것과 잴 수 있게 만드는 것은 다른 일이다.

`실측 숫자`를 반드시 카드 안에 넣어라 — 숫자 없는 교훈은 다음 사람이 검증할 수 없다.

## Acceptance Criteria

```bash
grep -q 'bar/s' docs/PRD.md
grep -q '~~단일 심볼 1Y/1H 백테스트~~' docs/PRD.md
grep -q 'test_execution_speed.py' docs/PRD.md
grep -q 'LESSON-129' docs/lessons.md
./tools/scripts/ledger-vitals.sh
```

## 자기 점검

1. 위 AC 를 직접 실행해 green 을 확인한다. `status` 를 `completed` 로 바꾸지 마라.
2. PRD 에 적은 숫자가 **step0 의 JSON 값과 일치**하는지 눈으로 대조한다. 기억으로 적지 마라 —
   이 레포는 「적혀 있다 ≠ 그렇게 동작한다」를 반복해 밟았다.
3. `ledger-vitals.sh` 가 rc≠0 이면 **네가 만든 위반인지 먼저 확인**해라. 이 step 은 `status.md` 를
   건드리지 않으므로 원래 통과해야 정상이다.

## 금지사항

- **`docs/status.md` 를 수정하지 마라.** 이유: 그 파일에는 살아 있는 `다음 행동 =` 이 **정확히 1개**
  있고 `ledger-vitals.sh` ① 이 ≤1 을 강제한다. lane 이 한 줄 더 쓰면 **pre-commit 이 회차 전체를
  막는다.** 회차 종료 기록은 CONTROL 이 한다.
- **PRD 의 다른 줄을 건드리지 마라.** 나머지 5개 지표도 미측정이지만 이 회차가 잰 것은 속도 하나다.
  안 잰 것을 고쳐 적으면 그 자체가 이 카드가 경고하는 행위다.
- **목표선(임계)을 새로 정하지 마라.** 사용자 결정 사항이다. 현재 값과 측정 방법까지가 범위다.
- **`~~` 로 지운 옛 줄을 삭제하지 마라.** 이유: 그 줄이 남아 있어야 「왜 바뀌었나」가 문서 안에서
  읽힌다. 이 레포의 원장 관례이고 AC 가 그것을 단언한다.
- 커밋하지 마라(커밋은 러너 소관).
